## 开一轮的固定动作

1. `dotnet build`（0 error）。
2. `game start <res://场景> --port n`，`debug ping` 探活、`debug verbs` 自报词表。要画面加 `--window`。
3. 命题分层（→ 「测试与实测分工」）：逻辑 → `dotnet test`；运行时 → 桥动词；表现 → 出图；玩家操作 → `input_*`。
4. 深号 bug 先 `dotnet run --project src/Tools -- trx <file.trx>` 一发分类。**仅重放类红**才上 `replay --report` / `--bisect`。
5. 判定读产物不读退出码：trx 的期望/实值、快照、`contact.png`、报告 md5。
6. 收尾：`game stop --port n`，`netstat` 复认端口无监听，速度拧回 1x。

## 词表与口径

说时长只写时间单位——报现实耗时用现实世界的秒 / 毫秒 / 分钟，报游戏内时长用该原型数值表定下的游戏时间单位并说清是哪一套。逻辑步是推进计数不是时间单位，不拿它报时长（→ 「时间基准」）。模型体检单那一档叫**采样时刻表**（→ 「时间基准」）。

## 前提条件

真机通道与离线工具线要的都是 Godot **可执行文件本身**。三级找法：`--godot=<路径>` > `GODOT_BIN` > PATH 上的 `godot`（本机现值在 `C:/Users/ZQH12/Desktop/software/Godot_v4.7.2-stable_mono_win64/`）。桥监听 `127.0.0.1`，没配端口就整段不监听；**端口即寻址**，同机多个 worktree 各挑一个端口即可并行。

## 标准验证循环

`dotnet build` → `game start <res://场景> [--port n] [--window]` → `debug snapshot_debug` / `debug eval` / `debug screenshot --path` / `debug input_*` → `debug logs`（看 `dropped_count`）→ `game stop --port n`。

## DebugBridge — 自有调试通道（默认通道）

游戏进程内的 localhost TCP 调试通道（`src/GugaFramework/DebugBridge/`），CLI 一发动词一发短连接，headless 自启。起前探端口、传 `--debug-bridge-port=`，日志落 `.cache/Runtime/run-<端口>.log`。`ping` 回读 `pid` / `port` / `scene` / `started`，其中 `tick` 是已处理的请求数。

**动词表**（`debug <verb> [--args …] [--port 7777]`）：

| 动词 | 语义 |
|---|---|
| `ping` | 探针。连不上就报错，不猜（→ 「三条铁律」） |
| `verbs` / `targets` | 词表 / 对象表自报，冷启动发现口 |
| `snapshot` / `snapshot_debug` | 重放快照全量单行 / DebugSnapshot 明细 |
| `speed --multiplier 20` / `pause` / `resume` / `step` | 操控台四件，立即生效 |
| `advance --tick 600` | 推进到目标步，同测试端 AdvanceTo |
| `inject --cmd PlaceBountyFlag --args "lair1\|25"` | **词表写路径**，写操作走这里进 Journal |
| `mark` / `record_start` / `record_stop --name xxx` | 录制三连，落 json 进 `Tests/Scripts/` |
| `call --target main --method DebugEndgame` | 反射调任意 public 方法/属性 |
| `eval --code "World.Units.Count(u => u.Health > 0)"` | **Roslyn C# 进程内求值**，globals 预置 `Main`/`World` |
| `input_action` / `input_click` / `input_hover` / `input_read` | 合成玩家输入 + 读输入层，参数见下节。前两条**入录** |
| `hover_pick` | 读 3D 拾取结果，只在窗口模式 |
| `save_readout` / `inject --cmd WriteSave --args 1` / `LoadSave --args 1` | 存档读写，**不进 Journal**；`--args` 传纯数字槽号 |
| `logs --count 50` | 读**滚动缓冲**尾部，关键字段 `dropped_count` |
| `replay <script.json> [--report\|--bisect]` | **离线重放取证**。`--report` 首个分歧 + 字段级 diff，`--bisect` log₂ 步定位第一个分叉命令 |

写操作走 `inject`；`call`/`eval` 是读与自带 `RecordWrite` 的 Debug 直达口（→ 「写路径进 Journal」）。接桥样板只有一处：标准七动词与公共接线全在 `DebugConsole.Attach`，数字参数缺了当场抛（→ 「桥只转发」）。

## uitest 通道 — 跑 UI 脚本（默认无头，可开窗口）

界面这一层没有第二个可断言的口：`dotnet test` 断不到控件，「玩家点得动吗」只能在真进程里验。`uitest` 把这件事脚本化：起一局，按 JSON 脚本点控件、发命令、断言读数，逐步打印判定，按失败数给退出码。

```bash
dotnet run --project src/Tools -- uitest <脚本.json> [--port n] [--godot=<exe>] [--scene=res://场景] [--window]
```

- 场景不给就按脚本所在原型推（脚本放在 `src/Prototypes/<原型>/Tests/Scripts/` 底下时，默认是那个原型的 `Scenes/Main.tscn`）；推不出来就显式给 `--scene=`。
- 退出码：全过退 0；有一步没过退 1。**头一个失败就停** —— 后面的步骤多半依赖前面的，继续跑只会报一串假红。
- 跑完必停进程并复认端口无监听（收尾与 `game stop` 同一条路）。
- 默认无头；`--window` 起窗口模式，窗口由 `Game.Launch` 挪到屏外，真渲染器在跑。**无头不出图**（原因见本节末那两条经验）。
- `eval` 只摆前置条件（耐久、名声、负债、账本余量），被验的动词仍走 `click` 或 `inject`。

### 脚本格式

脚本是一个 JSON 数组，每项一个步骤：一步只准一个动作键，可另带一个 `"label"` 写给人看（判红时原样打出来）。

| 键 | 语义 |
|---|---|
| `{"click": "<名字或文字>"}` | 点一个控件。先按 `Name` 精确匹配；匹配不上才回退按**唯一**的可见文字（标题屏那三颗没有名字，只有文字）。零匹配或多匹配都判红。点是真按下（发 pressed 信号），不是移光标 |
| `{"inject": "<动词>\|<参数>"}` | 走调试桥 `inject`（写路径进 Journal）。被拒就算这一步没过，拒绝理由原样打出来 |
| `{"eval": "<C# 代码>"}` | 走调试桥 `eval`，只摆前置条件。改世界不经过 Journal，所以不拿它当被验的动词 |
| `{"wait": <n>}` | 推进 n 个**逻辑步**（不等墙钟） |
| `{"assert": "<表达式>"}` | 对 `snapshot_debug` 与 `readout` 的合读做断言。支持 `&&` 组合；每段两种形态：子串匹配，或 `key<op>数` 的数字比较（`>` `>=` `<` `<=` `==`，key 是快照里的 `key=` 字段；key 不在就判红，不崩） |
| `{"assertUi": "<表达式>"}` | 对 `ui_rects` **首行**做断言（视口与布局那一层的事） |

示例（`src/Prototypes/BeastArena/Tests/Scripts/uitest-start.json`）：

```json
[
  { "label": "根视口是 1920×1080（无头默认那档很小，不设就全错）", "assertUi": "viewport=(1920, 1080)" },
  { "label": "标题屏那颗没有名字，按可见文字唯一匹配点它", "click": "开始游戏" },
  { "label": "推进 5 个逻辑步（不等墙钟）", "wait": 5 },
  { "label": "世界真的推进了", "assert": "tick>0" }
]
```

判红时打的是步号、动作、期望、实际（实测那一发）：

```
第 3 步失败（这一步故意判不过：步号不可能到一百万）：
  动作：assert
  期望：tick>1000000
  实际：tick>1000000：tick=5，不满足 >1000000
```

### 两条实测经验（无头）

1. **无头根视口默认 64×64，`--resolution` 透传无效。** 实测：`game start` 起一局无头，`debug ui_rects` 首行是 `viewport=(64, 64)`。视口必须显式设（uitest 起手就设 `Root.Size` 并回读确认，没生效整轮判红）—— 不设的话所有控件坐标都是错的（同一局的命令栏落在 `rect=(-272,12 320x42)`）。
2. **无头没有渲染器，`screenshot` 回 `shot=empty-frame`。** 出图要另起一次窗口模式（`game start --window` + `debug screenshot`）；uitest 这条通道只做 UI 快速测试，不出图。

## 输入合成 — 真机输入链可被自动化

`src/GugaFramework/DebugBridge/InputInjector.cs`，公共层零游戏知识件，各原型各注册一次。**输入事件本身也进 Journal**：点击本身就是写路径的一部分。**重放端一律跳过 `input_action` 与 `input_click`**（`SyntheticVerbs.Skip`）；漏接会落到 `default` 分支返 `false` ⇒ 重放端 `ok` 翻转（「断言三层」里任何档位都红）。

## 四条动词

`input_action --name <action> --pressed <true|false>` 送 `InputEventAction` 走 InputMap action；`input_click --button <left|right|middle> --x --y --pressed` 送 `InputEventMouseButton` 带视口坐标；`input_hover --x --y` 走 `Input.WarpMouse`，**只在窗口模式**；`input_read` 无参，无头时标 `mouseMeaningful: false`。

## 四条动词各自的最小验证序列（真机跑通，无头）

`input_action --name place_market --pressed true` → 隔一次调用 → `eval` 读私有字段 → `--pressed false` → `input_click --button right --x 640 --y 400 --pressed true` → `input_read`。这一串只验到「事件送达消费方」。

## 五条引擎事实（都是实测，不是记忆）

五条事实已按症状并进末尾的故障排查表：合成滞后一帧、原始事件能到达 `_UnhandledInput`、3D 拾取悬停走不了 `InputEventMouseMotion`、`input_hover` 动的是**真光标**、按下态消费后即清。

## 两条踩过的坑

- **press 与 release 必须成对**：只发按下不发抬起，第二次同 action 的按下不产生跳变。实测隔 800 毫秒不够、隔 2 秒才稳。
- **只看「注入后」读数会误判不成立**：读数必须在同一发里打出注入前的值确认前置状态非空。前置为 null 就中止。

## 取参守卫（四条实测，`BridgeArgs` 那一处口径）

数字参数缺了当场抛，四条实测的返回形状：`动词缺参数 --pressed`、`动词缺参数 --button`、`参数 --button 只接 left / right / middle`、`动词缺参数 --x`，返回都是 `ok:false`。

## 尚未覆盖的边界

**3D 拾取悬停只能在窗口模式验**，读出口是各原型的 `hover_pick` 动词。`input_read` 报的那份名单里 `ui_*` 占绝大多数，项目自定义的聚在前面。

## 端到端断言

一条把「玩家按键 → 逻辑层改状态」整条链接起来断言的真机检查，编排既有 `debug` 动词。判据八条：桥可达、前置读数非空、注入后进入营建态、点击送达、建筑数差 1、金库变小、落成后退出营建态、快照读到新座 id `market2`。无头实测八条全 PASS。

## 3D 拾取读出口 `hover_pick`

把**与悬停标签同一个 `pickedId`** 报出来，实现留在原型侧，不进 `InputInjector.Vocabulary`。窗口模式下 `pause` → `hover_pick`（基线 `pick=none`）→ `input_hover` → `hover_pick`（得 `pick=hero_0`）。

## AI 调试操控台

一根速度旋钮 + 一个画面开关，同一模拟只切不画。**入口只有 DebugBridge**，下表方法本体不变。

| eval 直达口（各原型 Main 侧；Template 带接线样板） | 语义 |
|---|---|
| `SetSpeed(0.25)` / `SetSpeed(1)` / `SetSpeed(20)` | 慢放 / 实时 / 快进（立即生效） |
| `PauseDebug()` / `ResumeDebug()` / `StepDebug()` | 冻结 / 恢复 / 单步（走一步自动停，返回 `tick=N`） |
| `SetRendering(false)` / `SetRendering(true)` | 黑屏纯逻辑全速跑 / 恢复画面（HUD 保留） |
| `DebugSnapshot()` | 全量状态一发读出 |
| `ReplayRecordStart()` / `ReplayMark("t300")` / `ReplayRecordStop("名字")` | **试玩录制三连**：开录 → 检查点 → 落 json 进 `Tests/Scripts/` |

- **交互调试与批量回归的分工**：操控台管交互调试；改代码后的批量验证走重放脚本（`dotnet test` 自动包含 `ReplayScriptTests`）。
- **eval 惯例「探针先行 + 一发串完 + 失败即停」**：正式 eval 前先发 `return str(1+1)` 验通道；eval 一报错就是通道停了，stop 重启再探针（→ 「三条铁律」）。

## 验证通道补充

- **`logs` 的关键字段是 `dropped_count`**：长跑局缓冲滚动丢弃可达数千行，验事件先大窗口回扫（`--count 100~400`）。
- **`snapshot_debug` 是 eval 失效时的状态兜底通道**：可读 C# 侧全量状态，不依赖求值器存活。
- **验证前 30 秒通道预检**：`ping` → `logs` 看事件在滚 → HUD 秒数与快照步号两次求差看时间流速 → 一发 `eval`。

## 故障排查（实测踩坑）

> 红线在 AGENTS.md「进程与运行时安全」一组，事故与通用陷阱在 `docs/debug 指南.md`。看门狗 `src/GugaFramework/Guard/LogRateWatchdog.cs` 超 20KB/s 自动暂停模拟并关 3D 渲染。

| 症状（照这些字搜） | 现法（一条命令或一条指针） |
|---|---|
| 合成输入后同一条命令里读到的还是注入前的状态 | 注入与读数**分两发**；有没有生效以世界自己的读数为准 |
| 游戏在跑，但新增的 UI 节点 / 建筑模型永远不出现 | `GetNode("%X")` 失败后 Godot 照跑 `_Process`，该行之后的装配静默丢失。改用已知子节点反查父容器 |
| `dotnet build` 报一串 `CS0102` / `CS0111` | 工作副本相对仓库 HEAD 陈旧。`git status` 看有没有同一份文件的两个路径 |
| eval 里调 C# 方法报 `Nonexistent function` | 方法名是 PascalCase。`UnprojectPosition` 而非 `unproject_position` |
| headless 跑一局，`ObjectDisposedException` 刷屏、占全日志七成字节 | **C# 字段非 null ≠ 那个 Godot 节点还活着**。`node.TreeExiting += () => _foo = null;`（→ 「离树交还」） |
| 想靠大小写分目录，自家文件写进了 vendored 包 | Windows 大小写不敏感 + `core.ignorecase=true`。取证是一发 `mkdir` + `ls` + `git status` |
| 新写的 `.gd` 加载失败，按场景跑进程仍退 0 | 凭记忆写引擎 API（4.x 叫 `Window.MODE_WINDOWED`）。先发一发 `--check-only --script` |
| 退出码会不会说话 | `--script` 与 `--check-only` 退 **1**；按场景跑根脚本失败退 **0**。走场景那条路只认产物四件 |
| 刷屏 `ERROR: Can't send message. No active debugger` | **噪声不是故障**。只看 `SCRIPT ERROR` 计数（→ 「只看 SCRIPT ERROR」） |
| 要停掉自己起的无头游戏，Git Bash 里没有 `pkill` | `game stop --port n`；手敲 `taskkill //F //IM Godot_v4.7.2-stable_mono_win64_console.exe` |
| 任务管理器里有两个游戏实例，读数像是上一局的 | 一发 `game list` 看全部在跑的实例；起局走 `game start`，起前有人应答就拒绝起 |
| `godot` 不在 PATH | 冒烟测试走完整路径 `<Godot 目录>\Godot_v4.7.2-stable_mono_win64_console.exe --path . --headless --quit-after 5` |
