# 技能系统调研结论摘要 —— 对标 GAS 之后定下来的取舍

> 四轮调研的结账摘要，原件进 git 历史。活的机制文档在 `docs/GugaFramework/技能试验场.md`，逐格读数在 `docs/prototypes/<原型>/技能层验证记录.md`。

## 1 结论速查（这一轮调研真正落定的六件）

| 号 | 结论 |
|---|---|
| 1 | **自研，不 fork。** `yulrun/godot-gas` 只当参考实现读——它的时间由渲染帧推进、真值住在 Node 里、没有状态出口，与本项目口径对不上，而 fork 要买的恰好是本项目逻辑层免费给的 |
| 2 | **技能不是执行器，是每步重算的一笔账。** 四条前提 A1~A4 推出全部机制，每步执行序 S0~S5 顺序即契约 |
| 3 | **显式执行流优先于反应式规则网。** GAS 拿调试透明度换复杂系统表达力，显式流程系统拿通用性换调试透明度，没有银弹 |
| 4 | **功能面覆盖率来自「每档兵种各管一类机制」**，不是来自单条技能的复杂度。16 条技能（D1~D8 + F1~F8）铺满 GAS 功能面，1v1 里跑得完 |
| 5 | **通用性靠可调参数少而正交，不靠场景多。** 三条说法 G1~G3，各配一道机器验的问法 |
| 6 | **公共层零字面量。** 函数名 / tag 名 / 属性名 / 技能内容全由原型侧提供，公共层只认字符串键 |

## 2 选型：为什么自研而不是 fork

自研，不 fork。它还会往使用方工程根写东西，与「源码归 src」对不上——当时只报告未裁定。

### 2.1 `yulrun/godot-gas` 仓库面与代码面

非 editor `.gd` ≈2600 行（单文件 1112 行）；网络相关 15 行；Node 当身份 48 处；硬编码 `res://addons/GodotGAS` 49 次；零测试无 CI；release 资产全为 0。

### 2.2 评估的核心三条（与本项目口径对不上的地方）

时间由渲染帧推进；真值住在 Node 里；全库搜 `serialize` / `to_dict` / `snapshot` 零命中。

### 2.3 fork 要买的三件，本项目逻辑层免费给（这就是作废 fork 的理由）

冷却按整数步 `IntervalTicks` 走 `GameClock`；身份是 `unit.Id`；`DebugSnapshot()` 读得出全量真值；射程零物理查询。宿主身份从 Node 换成逻辑实体 ID 是重写级。

### 2.4 C# 侧对照：换语言没换掉问题

`forge-godot` 的实体也是 Node、作用范围靠引擎物理、同样没测试，那条重放链在同样的位置上不通。

## 3 范式结论：显式执行流 vs 反应式规则网

核心一句：技能是显式可执行流程，不是隐式反应式规则网。GAS 的代价是调试透明度低，快照与重放不是原生保证。

## 4 设计骨架：四条前提 + 六个模块 + S0~S5

### 4.1 四条前提（全部机制由它们推出）

- **A1 一步 = 纯函数。** `State(k+1) = f(State(k), 本步注入的命令)`；参与真值的函数不捕获环境，按名字注册的纯函数合法。
- **A2 状态即数据。** 能进快照的才算：record / 值类型 / 整数步 / 字符串 ID。
- **A3 时间只有一把尺：步。** 一步 = 0.1 秒；前摇、冷却、持续、飞行、无敌帧全落在这一把尺上。
- **A4 真值只有一处，输出只有事件。** 动画不参与判定；步颗粒不适合帧级输入判定（弹反、拼刀、连招窗口）。

### 4.2 六个模块（`src/GugaFramework/Abilities/`）

| 模块 | 它必须不知道谁 |
|---|---|
| `Data` 六个 record + 三张表 | 世界、步、单位、事件——它连「第几步」都不认（**叶子**） |
| `Calc` 按名注册的纯函数集 | 不持有状态、不查世界 |
| `CalcRegistry` `name → function` 查找口，**由原型侧填** | 公共层里不许出现任何一个函数名或 tag 字面量 |
| `Stepper` S0~S5 编排 + modifier 求值 + tag 两段汇总 | Node、场景、动画、物理、`Godot.*` |
| `Host`（接口）单位查询口 / 事件出口 / 随机源 | 不实现任何东西，只有形状 |
| `DebugView` 快照读写 + 注入动词表 | 写只能经注册动词 |

三条硬约束：Data 是叶子；Stepper 只过接口接触外界（所以能离线跑是这条决定的）；公共层零字面量。原型侧那三个是实现不是新层。

### 4.3 每步执行序 S0~S5（顺序即契约）

| 段 | 做什么 | 为什么在这个位置 |
|---|---|---|
| **S0 到期结算** | `ExecuteAtTick == Tick` 的 `Pending` 落地：扣血、加/撤 modifier | 先清旧账，本步新登记的下一步才结，因果不倒。**抵挡在这一步扣血落地前问一次** |
| **S1 计时** | 撤到期的效果；`StepsRemaining--`；冷却只比一个数（`Tick < CooldownEndsAtTick`） | 纯整数，暂停天然全冻。冷却不比递减、比到期步 ⇒ 中途改倍率不会改动已在转的那根 |
| **S2 重算** | **两段**汇总 tag；按 `(AppliedAtTick, Seq)` 排序遍历 modifier，逐条先问条件列，不满足则**跳过不撤销**，最后**套一次** `Min`/`Max` | **一处收口**。判定与显示读同一份值，绝不在调用点现算 |
| **S3 技能推进** | `Pre` 走完 → **过 commit 点**（扣 Cost、写 `CommitTick`、**源属性抄成快照**）→ 生成 `Pending` → `Execute`；同 `StackKey` 按策略加层或刷时长；**事件到达时把命中条目登记成 `Pending`（回调本身不写真值）** | 前摇与结算之间隔着 S0，**飞行时间是一等公民**。commit 在 S3 不在 S4：接受与兑现分属两段，重放才对得齐 |
| **S4 决策与入口** | 问树/政策得意图 → `TryActivate`：查条件列 / 拦截 tag / 射程 / 冷却 / 充能，失败写 `RejectedReason` | 与 S3 分开 = 「兑现旧的」与「接受新的」不混。**拦截 tag 只管入口**，管不了在放中的 |
| **S5 移动与选目标** | 数据算射程与走位、写 `TargetId`、登记飞行物；**位移前再问一次同一条谓词**（定身） | 零物理查询。定身在两个口上必须是同一段代码，否则「入口挡住了、人还是走开了」会静默发生 |

行为树只占 S4 一发同步调用：树管选，技能层管兑现。例外：宿主开 `AbilityLayerConfig.InstantCommitOnPressStep` 时，前摇为零的技能同一步 commit（这一档由各原型各自选，公共层不替内容侧兜默认）。

## 5 验证面：怎么证明这套东西成立

### 5.1 三条通用性说法，各配一道机器验的问法

G1 只读清单那一份文件，逐字搜不到原型的类型名；G2 场子里搜不到技能名、tag 字面量与属性名；G3 加第三个原型时场子与 `src/Tools/` 下不该有文件要改。

### 5.2 场子的形状：两档单位 + 五个可调参数

两档单位：英雄档与木桩档（永不出手、血可定值、打不死；打不死是一列显式数据不是一个 if）。五个可调参数：敌方档位（不还手 / 只平A / 会自动放技能）、敌血（定值 / 打不死）、我方档位（手动释放 / 会自己放一条）、起始距离、随机（关 / 开）。

### 5.3 16 条技能：取材纪律与覆盖矩阵

四档兵种各 3 主动 + 1 被动 = 16 条；进清单要写得出「第几步、读哪一栏、等于多少才算对」。逐格实跑 24 行：**21 行绿 + 3 行按设计不做**，可调试性 8 条全绿（设计期口径是 23 行报「19 行全覆盖」）。

### 5.4 三级重放的分工

级 1 逻辑重放、级 2 引擎重放、级 3 录像；级 1 与级 2 的逐格指纹实测 sha256 相同，挂上行为树再跑一遍仍全等。

## 6 实测推翻过的三条设计写法（存档，改回去会再犯）

免疫形状：由施加的效果声明一列 `ImmunityTags`，目标身上有匹配 tag 时落不上去。前摇对表的判红只挡「动画比逻辑先演完」那一侧。16 条技能前摇在动画里没有对应动作，那一栏今天全念「不适用」。改 clip 的时长要连键帧时间一起改。
