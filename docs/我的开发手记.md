我正在进行游戏项目的最底层基础建设。
我希望使用 R3 作为一个核心操作的总线.
目前游戏原型只需要建立空壳占位即可，还没有到实现的时候。
我现在对于基础建设的具体要求如下，记得将设计思路写入文档和注释：
【技术栈与底层核心】
本项目基于 Godot 4 (C#) 与 R3 (响应式编程) 构建，已全面接入 R3.Godot 插件。核心目标是通过数据流彻底解耦“逻辑生成”与“表现消耗”。全局统一采用“正交 3D 节点处理空间逻辑 + 顶层 2D CanvasLayer 处理所有 UI”的视觉管线。

【三层响应式架构要求】

中台通信层 (AutoLoad)： 建立全局常驻单例，仅需提供基于 Subject<T> / MessageBroker 的强类型事件总线 (Event Bus)。无需手动构建全局节拍器，时间相关逻辑必须使用 R3 官方的 Observable.EveryUpdate(GodotFrameProvider.Process) 或 Observable.EveryUpdate(GodotFrameProvider.PhysicsProcess)，若需 delta 时间需链式调用 .Delta() 扩展方法。

纯数据逻辑层 (Pure C#)： 原型核心业务必须写成纯 C# 类，严禁继承 Node，严禁操作 UI 或 3D 碰撞体。所有关键状态强制封装为 ReactiveProperty<T> 或 ObservableList<T>。具体业务需灵活应用 R3 操作符：用 Queue + Concat 做指令排队，用 CombineLatest 结算复杂多维数值，用事件总线处理海量标签事件。

无状态表现层 (UI/3D)： 场景节点仅作为“提线木偶”，只允许在 _Ready() 中订阅 (.Subscribe()) 逻辑流以更新表现。必须使用 R3.Godot 提供的 .AddTo(this) 扩展方法将订阅绑定到当前节点的生命周期，严禁在表现层脚本中反向直接修改底层逻辑数据。

【工程目录与隔离规范】
目录强制划分为 CoreFramework/（中台事件总线、纯数据基类等）与 Prototypes/（各大原型隔离区）。所有原型必须在独立文件夹内开发并拥有独立 Main Scene，原型之间严禁相互污染，只能通过 R3 全局总线进行对接与通信。




# 游戏制作人

游戏具有 程序、美术、音乐、设计 这四种属性。更高的属性数值将解锁更强的东西。它们被设计为“承载力”或“通行证”。例如，“程序值 50”不是让游戏评分变高，而是代表你的团队“有能力把【3D物理引擎】这个标签模块装配进蓝图里”。如果强行装配超过承载力的模块，就会触发“Bug爆炸”。
玩家在选择页面可以选择这几种属性，和一些特殊能力。选择页面的加点与特殊能力是由培养因素决定的，比如多周目可以有六边形战士的开场或是一开始就获得特定 npc。场外肉鸽的加点界面，可以包装成“主角在决定创业前的一份简历”或者是“童年回忆走马灯”。肉鸽积累的代币可以是上一周目破产后留下的“行业人脉”或“经验笔记”。

玩家将扮演一个怀揣游戏开发梦想的新人，体验这波澜壮阔的游戏开发之旅。
游戏与游戏历史高度重合，因此采用时间轴年轮推进。
游戏将提供不同的开始年份，特殊年份将标注事件，比如 xxx 年 8 位机发布、VR 发布、魔兽争霸发布、红警发布、工作室收购事件。

玩家可以选择任意年份开始。
游戏背景设定为美国，后续可能会加入中国、日本背景。

玩家的初始点可选，默认为车库，也就是车库工作室，只有自己一人。
玩家初始将拥有电脑论坛。
玩家可以选择自行开发独立游戏，或者是找几个人一起开发。
玩家将如同 模拟人生4 一样使用俯视角来跟各种东西交互。
玩家需要前往地图中，去找寻游戏思路和线索，比如街机店、cd 店 或是各种展会。
游戏的开发取决于工作室的整体能力、游戏类型、目标机器硬件条件。
比如，在 8 位机时代，开发游戏完全不需要美术，甚至不需要设计，程序员一个人就能开发出游戏来。那个时代的游戏能运行就行，玩家不在乎游戏的画面和设计。
在主机时代，玩家开始对游戏的画面和设计有了更高的要求，程序员一个人已经无法满足开发需求了。玩家需要美术和设计的加入来提升游戏的质量。

玩家需要权衡收益和风险，选择合适的开发方式和团队成员。玩家还需要管理工作室的资源和时间，确保游戏能够按时完成并达到预期的质量。
游戏尊重历史，所以很多事件和游戏的配方是固定的。
有些著名游戏的“配方是固定的”（比如：管道 + 跳跃 + 蘑菇 = 超级马里奥）。配方固定，但“加工过程”是动态的。
比如玩家第一周目就知道配方，打算逃课直接合成“旷野之息”，强行让低级员工去融合高级功能，会引发你设计中的“灾难事件”（Bug爆炸、员工崩溃离职）。这就逼迫玩家必须遵循团队养成的客观规律。如果是在不合适的年代妄图实现过于超前的设计，就会引发灾难事件。玩家需要通过不断尝试和调整，找到适合当前时代的游戏设计和开发方式。市面上的经典游戏是固定组合，但玩家自己“瞎组合”也可以产出奇葩游戏。如果玩家把【恋爱养成】加上【克苏鲁恐怖】进行融合，虽然现实中没有对应的国民级爆款，但游戏内可以判定为诞生了某种“Cult神作”，如果满足历史条件“离经叛道和披头士”，那会引发特定的小众狂欢。

玩家在小有成就后，将会面临工作室收购和 ip 收购。玩家可以选择出售自己的工作室或者 ip，获得资金和资源来支持下一步的发展。玩家也可以选择继续独立发展，保持对自己作品的完全控制权。
玩家可以招募各种有性格的员工来加入工作室。有些特殊员工将会有特殊招募条件。
玩家可以通过 mda 模式来获得现在市面上已有游戏的底层配方。

玩家可以通过参加各种展会来获取灵感和资源。展会将根据时代的不同而变化，比如在 8 位机时代，展会可能是街机店的比赛，在主机时代，展会可能是 E3 游戏展。
玩家初始可以通过电脑网络论坛和杂志获取自己游戏的评价。后续随着时代解锁，玩家将过渡到 YouTube 等平台获取评价和反馈。

某些著名制作人的经历很有趣，比如 kenshi 作者兼职了很久的夜场保安，星露谷物语制作人被女友养着，因此玩家可以选择去做各种兼职，甚至去寻找富婆。

玩家可以选择接取各种外包项目，不过不只是金钱，外包项目将允许玩家接触其他工作室的人，可以学习和挖人。

玩家在富裕后可以将工作室环境升级，从车库到公共空间到别墅等环境。
游戏的类型将随着时代的变化而逐步解锁，但是玩家可以提前“预知般”解锁，但过早解锁会引发灾难事件。比如在 8 位机时代过早解锁“开放世界”类型，就会引发灾难事件，因为当时的技术条件无法支持开放世界游戏的开发。


玩家的角色会具有一整套技能树，，以提供更多的发展可能性。
游戏的设计最高将局限于一个小型工作室，因为更大就会变成公司管理了，不再是游戏开发了。


玩家不会有真正意义上的失败，但是可能会出现资金负数的情况，这时会触发“破产事件”，玩家如果已经有了一些佳作，那么可以进行众筹，粉丝也会捐款来支持玩家度过难关。如果没有佳作，那么玩家只能选择打工还钱或者重开了。

游戏中还有一些随机事件，这些事件的出现都有征兆，对应历史上真实发生过的事件。比如在 8 位机时代，可能会出现“芯片荒”，导致玩家无法获得足够的芯片来开发游戏；在主机时代，可能会出现“盗版猖獗”，导致玩家的游戏被盗版商大量复制和销售，影响玩家的收入。比如可能出现水淹服务器事件，这是《无人星空》制作组真实发生的事，但是在最开始没有人相信。这些事件的出现都有明显的预兆。
