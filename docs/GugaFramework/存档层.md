# 存档层（`src/GugaFramework/Persistence`）

落点 `src/GugaFramework/Persistence/`：`ISaveable` / `SaveWriter` / `SaveReader` / `SaveCursor`（手写 JSON 游标，两侧共用）/ `SaveText` / `SaveFile` / `SaveMigration` / `SaveStore`。测试：`PersistenceTests.cs` 22 条、`RestorePortTests.cs` 11 条。纯 C#，不引引擎：`SaveStore` 收一个目录字符串，不收 `Godot.FileAccess`，整件在离线测试里能跑。公共层与前端层、寻路层平级。

## 是什么，不是什么

写档只读权威状态，读档只灌权威状态，派生数据一律不进档。

不管的三件事各有归属：冻不冻结时间归原型的世界（只抛 `PauseRequested`）；档里装什么归每个原型那一半；存档 UI 画在哪归前端层。管的一件事：落盘形状——文件头、原子替换、体积上限、迁移分派。

## 接口形状

```csharp
public interface ISaveable
{
    int SchemaVersion { get; }
    void WriteState(SaveWriter w);   // 只写权威状态
    void ReadState(SaveReader r);
}
```

写侧与读侧按「键 → 值」一一对应，是同一个形状。没有 `TryRead` 那一路，缺键当场抛 `SaveFormatException`。浮点走 `"R"` 加 `CultureInfo.InvariantCulture`。手写游标与 `ReplayScriptJson.Parser` 同形状，不引第三方 JSON 库。

### 出口守卫

反射扫 `Persistence` 命名空间（手法抄 `VfxLedgerTests.cs:334-356`），**出口只有 `WriteState` / `ReadState` 两个。**

## 文件形状

```json
{"v":1,"world":"<原型名>","tick":4000,"state":{…}}
```

末尾补一个 `\n`（与 `ReplayScriptJson.Write` 同一口径）。**只有这四个键。** `v` 是迁移链的钥匙，不等于当前版本时按 `v` 找迁移函数；`world` 读档先比对，不对当场抛 `SaveWorldMismatchException`。写盘走原子：先写 `.tmp` 再改名。半份档比没有档更难查——读的那一侧看不出自己读到的是残件。

### 落点

`%AppData%/Roaming/Godot/app_userdata/DemoFactory/saves/slot1.json`。引擎侧的 `user://` 由原型用 `ProjectSettings.GlobalizePath` 解成真实路径递进来。

## 存档装什么（三分判据）

每个写进存档的字段，标它属于哪一档。

| 档 | 含义 | 存不存 |
|---|---|---|
| 权威状态 | 玩家做过什么、金币、职业、上限、**单位当前位置** | 存 |
| 派生数据 | 公式能算出来的（净空场、寻路路径缓存、血条百分比） | 不存，读档时重算 |
| 引擎句柄 | 模型、贴图、音频、Node 引用 | 绝不存，只存指向 |

**位置属权威档，要存。** 只存命令、读档时重算位置走不通：重算要的是上一份解的输入（`_stepIndex`、游标、路径缓存），那些都不在命令里。派生那一档是危险所在：存了它，代码里同时还有算它的公式，两边不一致就成了两个真值。这套判据只管存档，调试快照本来该冗余（→ `docs/adr/0012`）。

## 体积上限

`SaveFile.MaxBytes = 10MB`。**它是开发期报警线，不是容量预算。** 正常存档应不到 1MB。超限当场拒绝写入并抛 `SaveTooLargeException`，报错要带**哪一段最大**（`Sections` 按写入次序给出每段字节数）。

## 迁移链

`SaveMigration.Table` 第一版是**空表**，分派先在：`v != CurrentVersion` 就查表，查到就调，查不到抛 `SaveMigrationMissingException`；档比当前版本新抛 `SaveVersionTooNewException`。改字段时只加一个函数。`SaveMigration.Readout()` 把「表现在有几条、从哪几版到哪几版」并进存档读数。

## 槽位清单

`SaveStore.Enumerate(count)` → `IReadOnlyList<SaveSlotInfo>`，每条给槽号、有没有档、所属原型名、写档那一刻的步数、存盘时刻、文件字节数。清单是取值的函数，不是一份快照：写完档那一发要立刻念出新的一份。档坏了不抛：念清单那一格返回 `<读出>`，设置屏要的是读数，不是崩溃。存档模块不认识 UI 控件，存盘时刻那一格的文案（「空」）在 `SaveSlotInfo.WhenText` 里。存档区那五个键走 `i18n/frontend.csv`，玩家看得到的四行反馈走原型侧那一份 `i18n/<原型>.csv`。

## 时间可控那一格：恢复口

存档与调试快照不共用字段清单（→ `docs/adr/0012`），但**时钟与寻路层各开了恢复口**，两处的口都是窄的：只读一个数、写一个数。

| 层 | 口 | 为什么要 |
|---|---|---|
| `GameClock` | `Schedule(id, delay, action)` · `Pending()` · `RestoreTick(long)` | 待触发事件是权威状态，不存就读档后经济周期与 BOSS 降临不再触发。`RestoreTick` 只许前进 |
| `NavStepper` | `RestoreStepIndex(long)` · `CommandOf(id)` · `Roster()` | 单位位置与**当前命令**都是权威状态。存命令是因为重发一次 `Chase` 会换掉路径 |

原型的恢复接线那一层有一处真坑（某趟迁移踩到的，逐条读数记在 `docs/prototypes/<原型>/`）：`AbilityStepper.Restore` 的 `shell` 参数被忽略，返回的 stepper 挂在 `restored.World` 上，包装器不把 `_sets` 修回去，新生成的单位会在 `KeyNotFoundException` 上炸。

## 调试桥接缝

| 动词 | 走哪 | 进不进 Journal |
|---|---|---|
| `inject cmd=WriteSave args=1` | `ReplaySetup` 词表 | 否 |
| `inject cmd=LoadSave args=1` | `ReplaySetup` 词表 | 否 |
| `save_readout` | 原型侧读数动词 | —— 只读 |

**桥动词名是 `snake_case`，Journal 命令名是 `PascalCase`。** 写档不改逻辑状态，读档是换世界，两条都不是「一次写」，所以用 `InjectNames` 分档表把它们挡在 Journal 之外（`ReplayAssembly.cs:223` 只判 `IsVerb`），与 `NavVerbs`、`ConstructionVerbs` 同一形状。存档那两条的实现由**表现层递进来**（`ReplaySetup.SaveHooks`）：换世界要重建整个表现层，逻辑层碰不到它。重放端没有表现层，那一格判否，返回「没有接线」。

## 实测数字

**五条测试线全绿**：`src/GugaFramework/Tests` 602 通过 / 0 失败 / 1 跳过（共 603）；`dotnet build DemoFactory.csproj` 0 错 0 警告。新加的三处：`PersistenceTests` 22 条、`RestorePortTests` 11 条、`SaveRoundTripTests` 16 条（后者把某个原型那条线从 204 抬到 220，重放基线未动；逐条读数记在 `docs/prototypes/<原型>/`）。i18n 那条抓过 4 个键：四行反馈漏登记进原型的 `i18n/<原型>.csv`，插值键也在扫描范围内。

### 真机撞出的四处（都不是离线测试能抓到的）

全绿之后再真机跑一遍，报了 4 处：`--args` 传纯数字被序列化成 JSON 数字（`BridgeArgs.Str` 只收字符串）；`LoadSlotNow` 里 dispose 的是刚灌好的新世界；eval globals 建一次就存一份引用，念到旧世界；终局横幅换世界没清。前两处在「表现层 ↔ 引擎 ↔ 工具链」这一圈，逻辑层那份纯 C# 世界看不见。第三处两个读数都自洽。第四处只有出图看得见。

### 真机读数（seed 42）

seed 42 真机跑一趟：开局槽位空；推进两千步后写档；推进到第 4000 步判终局；读档之后局面回到运行中，寻路段的步号与 agent 数、建筑数都接得上。**一局存档离 10MB 那条线有两个数量级余量。**逐条读数记在 `docs/prototypes/<原型>/`。

## 待确认项

- **冷缓存那一格**：`NavStepper` 的派生路径缓存不存，读档后第一步要重新解一遍路径，于是读档那一局与不读档那一局从此不再逐步相同（差厘米级）。`WriteState → ReadState → WriteState` 逐字相等那条通过；「读档后与不中断的对照局逐步相同」本版没做，也不打算做。
- **读数那几行的语言**：`Readout()` 与「已保存 / 读取」那两行反馈目前只有中文。调试读数走 `RollingLog` 不走 `Loc`，那一半是有意的。
- **多槽还没做**：`SaveSlotCount = 1`，接口已按枚举做。多槽要改的是布局。
