# 对象池（`src/GugaFramework/ObjectPool/`）

答「同一件东西反复借还」的公共件。约束句在根 `AGENTS.md`「契约索引」，本页只记机制与实测数字。

## 1 池子是什么、不是什么

池子只有三件事：借出一个、归还一个、池空时现造一个。借出去的东西长什么样、该重置成什么样、满池时怎么销毁，三样全是构造时递进来的委托，池子一个都不读。它不是性能优化开关，是复用机制：不接池子，游戏照样跑。也不是 IOC 容器，不自带池化策略：没有生命周期、没有自动装配、没有依赖解析。

## 2 形状借的是 Unity

构造五个委托 + 两个容量数：

```csharp
new ObjectPool<T>(
    createFunc,        // 池空时造一个；返回 null = 这一发「借不出」
    actionOnGet,       // 借出那一刻：放进树、开可见、复位
    actionOnRelease,   // 归还那一刻：停处理、藏起来、清状态
    actionOnDestroy,   // 满池时销毁那一个
    collectionCheck,   // 重复归还当场抛（开发期建议开着）
    defaultSize,       // 构造时先造这么几个备用
    maxSize)           // 池里最多留几个
```

形状同 Unity 内置 `UnityEngine.Pool.ObjectPool<T>` 与 `Microsoft.Extensions.ObjectPool`。泛型 `where T : class`，不碰 Godot 类型，因此能链进 `src/GugaFramework/Tests/` 被 `dotnet test` 直接测。做成 Node 专用要在五处 csproj 点名排除，于是永远离线测不到。

## 3 三条语义

| 情形 | 这一件怎么做 | 为什么 |
|---|---|---|
| 池里还有 | 弹一个，调 `actionOnGet` | 复用的正路 |
| 池空 | 调 `createFunc` 造一个 | 「新建」那一格是唯一能证伪池子有没有用的数字 |
| 归还时池满 | 不进池，调 `actionOnDestroy` 销毁 | 让池涨过 `maxSize` 之后，「在池 N」与「上限 M」从此对不上，那是静默失配 |

`createFunc` 返回 `null` 就是借不出：记 `CreateFailedCount`，不排队。Vfx 那一档「峰值宁可丢演出也不要节点数失控」就是这么开的。`collectionCheck` 开着时同一个东西还两次当场抛：它在池里已有一份，再推一份就成了同一对象的两个副本，画面上完全看不出区别。

## 4 读数

```csharp
pool.Readout()
// 池 在池 1｜借出 1｜新建 2｜销毁 0｜借不出 0｜上限 4
```

「新建」那一格最要紧：借还各走一圈之后它不涨，复用才真的发生；它照涨，池子在空转。其余五格（`InPool` / `Borrowed` / `CreatedCount` / `DestroyedCount` / `CreateFailedCount`）是纯计数器。在池几个、借出几个都在真值下游，不进检查点快照、不进逐字基线（「特效不进真值」）。

## 5 `ModelAnimator.Recycle()`：复用动画节点的那一发

表现层借还模型时，归还那一路要接 `ModelAnimator.Recycle()`，它清三档私有状态：`_dead` / `_oneShot` / `_base`。

`_dead` 没有任何一条路把它写回 `false`：`Die()` 置 true，death 分支不清它。复用过一个「死过」的模型，它借出来一帧都不动，画面上看不出区别。三条都属静默失灵，只有读数或真机看得见。停播交给 `actionOnRelease`，本件只清自己那三档。

## 6 实测

### 离线测试

`src/GugaFramework/Tests/ObjectPoolTests.cs`，14 条：计数从零、池空现造、满池销毁、借还不新建、重复归还抛、没借出就还抛、collectionCheck 开关、借不出返回 null、容量上限、重置回调、`Clear` 只清空闲的、读数格式。

`dotnet test src/GugaFramework/Tests`：同项目合计 648 通过 0 失败（1 条跳过是既有的 S37）。

### 真机实测（技能试验场，Godot 4.7.2-stable mono）

`game start` 起 `res://src/GugaFramework/Abilities/Stage/SkillStage.tscn`（`--window`，端口 7803），桥上 `vfx_play` 连演同一条轨（`hit`，一次性档，单位 `trainee`）四次，逐次读 `vfx_read`：

| 次 | 演 | 在池 | **节点新建** |
|---|---|---|---|
| 1 | 0 → 1 | 2/2 → 1/2 | 0 → **1** |
| 2 | 1 → 2 | 2/2 → 1/2 | 1 → **1** |
| 3 | 2 → 3 | 2/2 → 1/2 | 1 → **1** |
| 4 | 3 → 4 | 2/2 → 1/2 | 1 → **1** |

演了 4 次，节点只造了 1 个。「在池」每轮回到 `2/2`（演完自动归还），`借不出 0`（峰值丢弃语义未被破坏）。持续档（`guard`）也验了：挂上 `trainee` 后读数 `挂着 1 条`，HUD 同步显示 `vfx attached=1`。

出图（`.cache/Shots/Pool/`）：场景、五个单位、HUD 正常。粒子在本场机位下（距离 28.5 米、俯角 78°）分辨不出色块，这一格以读数为准（「测试与实测分工」）。
### 迁进度

| 原型 | 池化那一层 | 状态 |
|---|---|---|
| `VfxPlayer`（Vfx 公共层） | 按轨空闲栈 → `ObjectPool<GpuParticles3D>` | 已接，已验 |

`VfxLedger` 那一本账保留：它判「峰值丢弃」（池空就丢、不排队），那是业务决定；池子管节点造与复用。两个数看的是同一局的两个面（见 `VfxPlayer.Readout()`），缺一个都会漏故障。
