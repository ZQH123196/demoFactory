# 世界装配（`src/GugaFramework/Composition/`）

答「一个逻辑世界装哪几件、按什么次序装、每步按什么次序推」的公共件。约束句在根 `AGENTS.md`「契约索引」，本页只记机制、实测数字与待确认项。

## 1 这一件存在的理由

被收编的是三段构造与一件每步次序：

```
new NavSolver(new NavSpace(空间, 网格), 预算, 重算档, 三份容量)
new NavStepper(求解器, 步进档, 时钟, 激活检查, 避让档, 事件出口)
new ConstructionCore(放置规则, 蓝图表, () => 时钟.步号)
```

以及每步推进的那三件事：先落地形、再推时钟、再推建造。这三段收编前在多个宿主里各抄一份，抄错一处没有任何断言会红——症状是世界演化结果不对，要等结果不对才反查得到装配。收进一处之后，「装配错在哪一步」从读三处构造段变成读一处 builder 加一次单测。

本件是纯 C#，零引擎依赖，因此能链进 `src/GugaFramework/Tests/` 被 `dotnet test` 直接测。

## 2 五步

| 步 | 方法 | 做哪几件事 |
|---|---|---|
| ① | `WorldAssembly(GameClock)` | 只认时钟并存下来，不造任何层 |
| ② | `BuildNavPipeline(NavPipelineSpec)` | 造求解器与步进器，并把那张网格存进 builder |
| ③ | `BuildConstruction(IPlacementRule, IEnumerable<Blueprint>)` | 造建造模块，步号读数是接在装配那个时钟上的闭包 |
| ④ | `AttachTerrain(mapCell, navCellsOf)` | 造地形接线并接在建造模块的事件出口上 |
| ⑤ | `Advance(steps, afterEachStep)` / `AdvanceTo(target, chunk)` | 每步那三件事 |

②的档 `NavPipelineSpec` 照 `NavGridSpec` 与 `NavSolver` 的口径：三份容量与两份档全部 `required`，公共层一个缺省都不给。`Gate` / `Separation` / `Events` 可空——「有没有站位冲突」是玩法决定不是数值档。

## 3 每步的次序

```
Pump() → Clock.Advance(1) → Construction.Advance(1) → afterEachStep?.Invoke()
```

次序不是风格问题：

- 地形排在最前。反过来的话「这一发砌的墙」要到下一步才生效，绕障的读数与建造那一步对不上。
- 建造进度排在时钟之后。这一步里到头的工期带的是这一步的步号；时钟在暂停中回 false 且不动，模块跟着不动，时间冻结对两边是同一件事——**暂停那一格只判一次**（`Advance` 开头那一次），不在第三件事上再判一次。
- `afterEachStep` 是宿主自己的收尾（排事件那类），不在五步之内。

`steps < 1` 与暂停中两种情形都回 `false` 且什么都不做，连地形都不读。

**局结束冻结那一道闸开在本件**（`FrozenProbe`）。真值在 `GameLogicBase.TimeFrozen`，
本件只读那个谓词（`GameLogicBase` 构造时把 `() => TimeFrozen` 递进来）。
判的位置排在步数与暂停之后、循环之前：

```csharp
if (_clock.IsPaused) return false;
if (FrozenProbe?.Invoke() == true) return false;
```

**闸开在这里而不是开在基类的 `Advance`**，因为有的世界重写了 `Advance` 并直接调本件，
闸若开在基类那一处，那条路绕过去（实测：冻结之后 `Advance(10)` 仍回 `true`、步号照爬）。
`AdvanceTo` 走的是 `Advance`，所以三条推进的路（基类 `Advance`、重写后直调本件、`AdvanceTo`）
都从这一道闸过。冻结与暂停并排判、对推进效果一样，真值分开放：
暂停可解冻，冻结是这一局的结局（→ `docs/adr/0016`，口径 → `docs/GugaFramework/前端.md`）。

## 4 网格为什么由 builder 存一份

`NavStepper` 不公开网格属性（只有 `NavSolver.Space.Grid`），而 `AttachTerrain` 不收网格参数。所以那张网格只能从档里存下来给第 ④ 步用——这是本件最容易踩空的一处。

## 5 七条守卫

层数对不齐的时候当场抛，并逐条说出缺哪一层。静默建半套的症状是世界演化结果不对，要等结果不对才反查得到。

| 情形 | 抛什么 | 消息里有什么 |
|---|---|---|
| `AttachTerrain` 在 `BuildConstruction` 之前 | `InvalidOperationException` | 「地形接线接在建造模块的事件出口上」 |
| `AttachTerrain` 在 `Advance` 之后 | `InvalidOperationException` | 「晚了阻挡永不落」+ 当前步号 |
| `AttachTerrain` 第二次 | `InvalidOperationException` | 「已经接过一次」 |
| `AttachTerrain` 在 `BuildNavPipeline` 之前 | `InvalidOperationException` | 「地形接线要落在走位流水线建的那张网格上」 |
| `BuildNavPipeline` 第二次 | `InvalidOperationException` | 「一个世界只有一条走位流水线」 |
| `BuildConstruction` 第二次 | `InvalidOperationException` | 「两个模块就是两本册」 |
| `AdvanceTo` 的 `chunkTicks < 1` | `ArgumentOutOfRangeException` | 「分块步数必须 >= 1」 |

缺层那条的消息逐条列出缺哪几层，顿号分隔，名字是「走位流水线」「建造模块」「地形接线」：

```
推进前五步没走齐，缺：建造模块、地形接线。
推进前五步没走齐，缺：走位流水线、建造模块、地形接线。
```

**缺层守卫排在暂停判定之前**：先判守卫再判暂停，缺层才会当场抛得出来。反过来的话，暂停中调 `Advance` 会把「装配少一层」这条真 bug 盖成一句「暂停中，推不动」。

「在 `Advance` 之后」的定义是**成功推过至少一步**：`steps < 1` 回 false、暂停中回 false、缺层抛异常，这三种都不算。

## 6 退订

`Detach()` 交还本件挂上去的那两处订阅，返回交还了几处（最多 2，重复调返回 0）。

读数口径是「交还了几处订阅」，**不是**「摘了几条时钟脉搏」：步进器那一处订的是时钟脉搏，地形接线那一处订的是建造模块的事件出口，两者订的不是同一样东西。

## 7 基类那几个观测口

`GameLogicBase` 造一个 `GameClock` 与一个 `WorldAssembly`，于是时间可控那个观测口在基类上就有了实体。

| 成员 | 形状 |
|---|---|
| `Clock` | 那个逻辑时钟 |
| `Assembly` | 五步收在它身上（`protected`） |
| `Tick` / `IsPaused` / `Pause()` / `Resume()` | 转发 |
| `SetPaused(bool)` / `Advance(int)` | `virtual` |
| `AdvanceTo(long, int)` | 分块循环住在基类，以虚 `Advance` 为一步 |
| `SubscribePulse(handler)` / `TrackDetach(detacher)` | 订阅 + 登记退订，一步做完（`protected`） |
| `SubscriptionCount` | 只数基类订阅表，不含装配挂的那两处 |
| `IsDisposed` | 有没有放过 |

`SetPaused` 与 `Advance` 是 `virtual` 的理由：有的世界在某个阶段不接受暂停，子类要重写它加那道守卫；非虚的话子类那个只是遮蔽（编译器报 CS0108 / CS0114）。

**`AdvanceTo` 的循环住在基类、以虚 `Advance` 为一步**：不接 ②③④ 三层的世界因此也能用这一份，不在原型侧再手写一条 `while (Tick < targetTick)`。原型侧那条手写循环是判据测试扫源码禁掉的形状（守卫在 `InputLayerTests`，判据「推进到目标步只剩基类那一份」）。接了三层的世界行为与从前逐字相同——基类那份 `Advance` 就是转发到本件的 `Advance`。

**退订次序**：先跑订阅表（后进先出），再交还装配挂的那两处，最后 `OnDispose()`。`Dispose` 幂等，重复调直接返回，不重复交还。

**时基字段**：派生类的字段初始化器跑在基类构造之前，所以子类不能在字段声明处把私有字段指到 `Clock`（那时 `Clock` 还是空），必须在构造体第一行赋。

## 8 操作步骤

1. 造 `GameLogicBase` 的子类。
2. 构造体第一行把私有时钟字段指到 `Clock`。
3. 按五步调 `Assembly`：②③④ 依次。
4. 推进用基类的 `Advance` / `AdvanceTo`；宿主自己的每步收尾走 `Assembly.Advance(steps, afterEachStep)`。
5. 自己那几处订阅走 `SubscribePulse`（订脉搏）或 `TrackDetach`（订别的出口），退订不用再写一遍。
6. 需要重写暂停或推进时 `override` 基类那两个 `virtual`。

## 9 实测

- `dotnet test src/GugaFramework/Tests --filter "WorldAssemblyTests"` → 17 条全过，耗时 55 毫秒。
- 装配守卫全部离线判红，不起引擎、不出图。
- 测试场地：8×8 格、格长 1.0 米、阻挡表空表、一张半径 0.5 米的圆形占地蓝图。半径非零是为了「地形落地了没有」这一条断言不退化成 `0 == 0`——半径 0 米的圆在格长 1.0 米的格上落不出印子。
- 网格、求解器、步进器、建造模块、地形接线五个类型全部纯 C#，测试项目零引擎依赖（`Camera/` 那一类由 csproj 点名排除）。

## 10 待确认项

- 本件只覆盖走位流水线、建造模块、地形接线三件。表现层那几个模块（相机、特效、模型动作）由各自那层自己接，不进这个五步。
- 本件不替宿主排次序。各宿主有自己特有的次序依赖（决策段先订、地形接线必须早于种子建筑放置、某些层必须先于走位那一档），那些留在宿主侧。
