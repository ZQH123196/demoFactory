# 输入层（`src/GugaFramework/Input/`）

答「一个输入动作叫什么、按哪种读法读、漏掉的那一发怎么补」的公共件。约束句在根 `AGENTS.md`「契约索引」，本页只记机制、实测数字与待确认项。

## 1 这一件存在的理由

收编前，每处读输入的地方自己挑「这里该用按下还是按住」，挑错的后果是「按住不放重复触发」，而那种错在画面上要按住键才看得见，源码里看不出来。收进一处之后，读法是概念自己带的，漏给读法编译不过。

三件：

| 件 | 职责 | 引擎依赖 |
|---|---|---|
| `InputConcept.cs` | 概念名 + 读法（`ReadMode`），以及那十六条公共概念 | 无 |
| `InputRead.cs` | 读法分派：按概念自己带的读法去问源 | 只认构造时递进来的三个委托 |
| `InputBuffer.cs` | 时间窗（按步数），补漏掉的那一发 | 无 |

三件全是纯 C#，因此能链进 `src/GugaFramework/Tests/` 被 `dotnet test` 直接测。

## 2 概念名公共、绑定原型

公共层只说「这些概念存在、统一叫什么」，不碰「绑哪个键」。暂停共用 `input_toggle_pause` 这一个概念名，各原型把键绑在自己那一侧。

读法是**必填**的：`InputConcept(string Name, ReadMode Read)` 的 `Read` 没有缺省值。开了缺省就等于可以不给，而「不给」就是挑不出读法。

`ReadMode` 三档：

| 档 | 形状 | 典型 |
|---|---|---|
| `JustPressed` | 一次物理按下只成立一次 | 暂停、单步、变速、镜头跟随与复位 |
| `Held` | 还按着就每帧成立 | 平移、绕转、俯仰、缩放 |
| `Axis` | 取动作强度 | 连续量按强度读的那一档 |

`InputRead` 按读法分派，读法用错当场抛：拿真假读模拟量、拿强度读刚按下、拿「刚按下」去问一个按住的——三种都抛，因为它们各自会把一种量塌成另一种（塌成假红的判据比塌成绿的值更贵）。

## 3 读法分派为什么是构造参数而不是引擎调用

`InputRead` 的构造函数收三个委托（刚按下 / 按住 / 强度）。这么切的理由：**「这一发输入为什么触发了两次」从此可以在不起引擎的进程里判红**。用例递一个假的源进去，照引擎真实形状喂（刚按下只亮一帧、按住一直亮），跑几十帧数触发次数。

引擎那一侧传进来的必须是 lambda 而不是方法组：引擎读法收的是 `StringName`，而 `string → StringName` 是用户定义的隐式转换，方法组转换不吃它（实测报 CS1503）。

## 4 输入缓冲

判据钉在这一条，否则它与契约「同种子重跑逐字全等」矛盾：

> 缓冲**只补这一发本来会作废的输入，不改变任何已生效命令的时机**。

| 读法 | 缓冲补不补 | 对逐字等的影响 |
|---|---|---|
| 刚按下 | 补 | 无。窗口内消费时命令与参数与「没丢」完全相同 |
| 按住 / 模拟量 | 不补 | 不适用。本来每帧读，不存在「作废」 |

补的是**触发时刻**不同，不是**命令内容**不同。这条钉在 `InputBuffer.Bufferable` 一处，不是钉在每个调用点：拿按住的或模拟量的概念去 `Record` 当场抛。

**窗长 2 步（0.2 秒）**是判断，不是实测。理由：`GameClock` 的步长是 0.1 秒，窗口的意义是「补一帧没接住的那一发」，两帧已经足够覆盖失焦与暂停态的路径，再长会让「玩家早就想按、现在才生效」变成常态。改一个构造参数即可。

出窗的那一发**当场作废**，不留在缓冲里等人来收 —— 留着就正是「早就想按、现在才生效」。

同一概念还挂着的时候再记一次 = 玩家又按了一次：新的一发顶掉旧的，所以「狂点两下」不会在窗口里堆出两条同概念的记录。

### 参数依赖步号的命令不许走缓冲

那条命令的内容要读当前步的世界真值（例如「现在悬赏定价是多少」）。延到窗口里再执行，读到的就是另一个步号的数 —— 那不是「补触发时刻」，是「改命令内容」。这类命令走 `InputRead.ReadSameFrameOnly`：当帧消费，不记也不查缓冲，窗口对它无效。用例里配了一条对照，证明同一发交给缓冲那条路**是会被补的**（所以这条约束是必要的，不是保守）。

## 5 时间旋钮的记录待遇

暂停 / 单步 / 变速三个动作**既不进 Journal 也不进快照**。它们是表现层与调试旋钮，不是写路径。

判据落在两处，都由用例守：

- 快照与动作账逐字不变（暂停、变速各按一次之后比对）。
- 三个旋钮名不在任何一条公共层动词表里 —— 补进词表就是把它变成写路径。

单步是唯一的例外形状：它本来就要把世界推进一步，那一步改的是步号不是账。所以断言是「步号 +1 且动作账不变」。

## 6 推进到目标步收编成一份

三个世界的「推进到目标步」收编成一份，各原型那一处只剩一句转发。暂停语义统一为**守暂停**：暂停时空转、步号不动、循环自然退出。

那条循环现在住在 `GameLogicBase.AdvanceTo` 里，**以虚 `Advance` 为一步**，不再转发到装配。接了走位/建造/地形三层的走基类那份 `Advance`（逐字与收编前相同）；不接那三层的世界因此也走同一份，不必在原型侧再手写一条 `while (Tick < targetTick)`。原型侧出现那种循环会红——守卫扫 `src/Prototypes` 源码，判据名「推进到目标步只剩基类那一份」，它自带一份样本并断言守得住。

收编前有三处不同，都不是「玩家那条」：

| 原型 | 收编前 | 差别 |
|---|---|---|
| 某处 | 手写分块循环 + 守暂停 | 与世界装配那份逐字同形 |
| 某处 | 调试直达口写的循环，暂停中也照走 | ① 那是重放钩子那一侧的语义（活局冻着时靠调试直达口跳），玩家按暂停对它没有意义；② 调试直达口只推逻辑时钟，世界装配那份每步还落地形、推建造；③ 调试直达口在战斗分出胜负之后返回 0，旧循环那句护栏于是让世界停在结算那一格 |

第 ② ③ 两条是收编顺带抹平的历史分叉，不是输入层这一格要验的事实。第 ③ 条有一处可见后果：那两份入库的重放基线改了检查点的**头部步号**（实体与建造读数逐字未变）。这是「推进到目标步」终于名副其实的结果，要「分胜负就停」走那一侧自己那个终局口。「暂停里也要跳步」的那个口没有消失，只是不再由重放钩子默认走它。

## 7 命名空间与目录不同名（踩过的坑）

目录是 `src/GugaFramework/Input/`，命名空间是 `DemoFactory.GugaFramework.InputLayer`。**这不是笔误。**

命名空间若叫 `Input`：C# 解析裸 `Input` 时，在 `DemoFactory.GugaFramework` 下先找到**命名空间成员** `Input` 就不再问 using 里的 `Godot.Input`。于是所有位于 `DemoFactory.GugaFramework.*` 下的文件里 `Input.IsActionPressed` 与 `Input.MouseModeEnum` 一起变成 CS0234。实测命中的是前端层那一份（不在输入层的归属范围内，所以改的是这边）。

## 8 实测数字

引擎那一侧三组（无头 Godot 4.7.2-stable，一次探针跑出来的）：

| 探针 | 结果 |
|---|---|
| 一个 `echo=false` 的按下事件 `is_action_pressed` | true |
| 一个 `echo=true` 的按下事件 `is_action_pressed` | false（自动重复被引擎滤掉） |
| 一个松开事件 `is_action_pressed` | false |
| 引擎级按住（按下一次不松，60 帧） | 节点收到 0 个事件；刚按下读数命中 0 次 |
| 同一帧合成 60 个按下事件 | 节点收到 60 个，逐事件读命中 60 次；**逐帧读「刚按下」命中 1 次** |
| 松开后再走 5 帧 | 刚按下读数不再亮（边沿确实被闩住了） |

最后两行是这一层存在的理由：同一份输入，逐事件读与逐帧读的触发次数差 60 倍。

## 9 待确认项

- 窗长 2 步缺实测依据。等有第二个消费者（触屏 / 手柄）时补一次「玩家实际漏输入的步数分布」，再定这个数。
- 失焦丢输入的路径在离线用例里是用假的源模拟的（形状对、真实事件流没跑过）。要真判一次得在窗口模式下手工制造失焦，那属于真机实测那一格。
