# 行为树与跨语言共存 — GugaFramework 说明

> 讲 GDScript 行为树（vendored Beehave）与 C# 任务同树共存的机制。约束句在 AGENTS.md「行为树与跨语言共存」一组。
> 通道用法见《验证操作手册》；原型结论见 `docs/prototypes/<原型>/design.md`。

## 单位 AI 上行为树（Beehave 运行时 + C# 任务）

Beehave 2.9.3 vendored 在 `src/GugaFramework/beehave/`。现况：只用运行时节点，不启用编辑器插件。任务基类 `BeehaveTask.cs` 就住在这个包里。

分工：树的结构（选择、顺序、冷却、黑板）在 `src/GugaFramework/beehave/nodes/`，vendored 不改写；决策与规则落纯 C# 类（原型侧 `AI/<Brain>Policy.cs`），链进原型 Tests；任务节点是 C#，继承包内 `BeehaveTask`，只搬参数（原型侧 `AI/Brain*Task.cs`）；树与逻辑层之间是原型侧的桥，标量进标量出。

### 为什么这条路走得通（两条实测支柱）

1. **容器不看类型、只按名字喊**。`composites/selector_reactive.gd` 的 `get_children()` 无类型，随后调 `child.before_run(...)`。所以 C# 任务不必继承 `BeehaveNode`，代价是放宽 13 行类型校验。
2. **GDScript 按方法名能调到 C#**，注册名逐字等于 C# 声明名。引擎不做 PascalCase→snake_case 转换，实测喊 `tick_pascal` 找不到 `TickPascal`。这就是「小写转发入口」那条例外的原因。Godot 4.7.2 的 C# 没有 `[Callable]` 特性（`Callable` 是结构体，写成特性报 CS0616），public 方法本身对脚本可见。

### 三个观测口在行为树上的落点

- **时间可控**：`process_thread = MANUAL` 加 `tick_rate = 1`，由 `LogicWorld.Stepped` 一步喊一次 `tick()`；受 `tick_rate` 节流的那几次返回 -1。
- **状态可查**：`HeroBrainBridge` 的 `Sense*` 口加 `DebugSnapshot()`；行为流走 `HeroBrain.log_decision` 单一出口。Beehave 自带的 `get_running_action()` 与 `get_last_condition()` 对 C# 任务恒 null。
- **行为可注入**：意图口 `Command*` 加宿主实验剧本（`injure_after_step`、`injure_to_ratio`），剧本挂在树上，换实现语言不用重写。

### C# 任务与宿主的六条写法

1. **决策落纯 C# 类，节点只搬参数**。`HeroBrainPolicy.cs` 零 Godot 依赖，链进 Tests，15 条决策断言连行为流的中文文本一起钉住。另有 4 条在 `BrainIntentExecutionTests` 钉意图到了逻辑层怎么执行。
2. **算术走 double**。C# 侧用 float 会在末位分叉（`10.31f - 3.0f` 已进测试）。
3. **日志文本走 `CultureInfo.InvariantCulture`**。跟着系统区域设置走，同一局在别的机器上会录出别的样子。
4. **大小写方向不对称**。GDScript 调 C# 用小写 `bridge.call("SenseHealth")`（写成 `Call` 报 Nonexistent function 'Call'）；C# 调 GDScript 用大写 `node.Call("get_value", ...)`。
5. **节点引用靠注入，标量参数可以走场景**。`[Export]` 的节点引用在手写 `.tscn` 里取回来是 null（根因未查），现法是表现层 `brain.Set("bridge", x)` 注入、C# 任务从 `actor.Get("bridge")` 取。
   `[Export]` 的标量往返成立：手写 `.tscn` 里给 `Flee` 写 `RatioBelow = 0.42`、`SafeDistance = 17.5`，节点上读回的就是这两个数（代码默认 0.3 与 14.0），删掉那两行退回默认值。同一颗种子下逃跑占掉的时间从 0.2 秒涨到 0.6 秒。场景继承覆盖标量同样生效（`Scenes/Brains/*.tscn`）。留痕：宿主 `_report_params()` 每个节点打一行 `参数 | Flee | ...`。
6. **宿主的离场校验**。单位被移除后树还在被驱动，叶子读到的观测全是默认值，行为流会写出「血量 0/0，眼前没有敌人」这种把离场者写成活人的行（实测连刷 150 步 = 15 秒）。做法：桥上加 `SenseAlive()`，宿主每步先问一次，不在了就停手，并向行为流里留一行 `离场`。

### 扩到多名英雄前：接管表的写作用域，以及「快照比对」为什么不能用

断言在 `BrainTakeoverIsolationTests`（5 条）。结论分两半。

- **成立的那半：写路径按 heroId 收口**。`DelegateHeroToBrain`、`ReportBrainIntent`、`ReleaseHeroFromBrain` 三口都以 heroId 为唯一作用域。实测让位那一下除该英雄自己的 `intent=` 之外全表逐字不变；对未登记的英雄、怪物、不存在的 Id 写意图是 no-op（`BrainIntentOf` 恒 -1）。
- **不成立的那半：两棵同种子世界逐 0.1 秒比全量快照做不到**，且与脏写无关。全世界共用一条 `Random _rng`（`LogicWorld` 字段），一名英雄的行为一变，后面所有人的抽签都跟着变。实测让位之后 0.1 秒别人的落点就分叉；抹掉 `pos=` 再比，到 10.3 秒别人的血量也分叉。⇒ 全量快照 diff 当不了归因工具。要一个真能逐字比对的窗口，得让随机数按单位分流水（未立账）。

同种子两跑比的是**行为流**：`grep -E "剧本|step .* hero|参数 \|"`，两跑 0 差异。整份日志长度随这一局跑多久而变（36.8 秒的局 8 条村民税，300 秒的局 114 条），拿它 diff 会带出上千行假分叉。关键词计数含重叠，基线报**状态行数**（现值 369 条）。

### vendored 改本（升上游时要重新落地的全部改动）

放宽类型校验，12 个文件 13 行：`nodes/composites/composite.gd:7` 与 `nodes/decorators/decorator.gd:7` 的 `var running_child: BeehaveNode` 改成 `: Node`；9 个装饰器 `get_child(0)` 的局部类型改成 `Node`（`cooldown:17`、`delayer:17`、`failer:8`、`inverter:9`、`limiter:18`、`repeater:18`、`succeeder:8`、`time_limiter:18`、`until_fail:11`）；`nodes/beehave_tree.gd:233,238` 两处返回类型改成 `Node`。不改则给 C# 节点赋值当场失败。

两条已批前置（不在 13 行内）：`blackboard.gd:74,75` 两处显式类型（否则 `:=` 从 Variant 推断，整个文件编译失败）；`project.godot` 的 autoload `BeehaveGlobalDebugger`。

清单里标着不可删的两个文件（「外部插件禁改」）：`debug/debugger_messages.gd`（24 个运行时文件调 `process_tick`）、`debug/global_debugger.gd`（autoload）。`plugin.gd` 与 `debug/` 那 10 个编辑器 UI 文件运行时永不加载，里面 9 处硬编码路径一行未修。

### 一棵树多份参数档、同步问，以及 headless 那条噪声

**一棵树多份参数档**：同一棵树（`SelectorReactive` 通到若干条 C# 叶子）配多份单位参数档，每份各自 instance 那棵树、只覆盖射程与标签两列，每个单位一棵。**参数档与数据表必须钉在一起**：射程住在两处——数据卡（进 `dotnet test`）与参数档（运行时叶子真读的）。两道校验：离线逐字解析各份档，不等于数据卡就红；运行时宿主 `_report_params()` 比对，漂了 `push_error`。逐档读数与那几处文件路径记在 `docs/prototypes/<原型>/`。

**同步问，不等下一步**：宿主可以收步事件要决策（树写意图 → 世界下一步执行），也可以在同一逻辑步里回头问树（世界委托口子 → 桥喊一次 → 叶子认账 → 当场拿回决策执行）。后者没有「哪一步的意图被哪一步执行」这本二次账，适合判绿建立在「离线跑与运行时逐字同一局」上的那条线。

**headless 跑带树的原型，日志里有一条噪声不是故障**：`ERROR: Can't send message. No active debugger`。来源是 vendored `beehave_tree.gd:139` 无条件调 `BeehaveDebuggerMessages.register_tree(...)`，而 `can_send_message()` 的条件是 `not Engine.is_editor_hint() and OS.has_feature("editor")`——用编辑器二进制 `--headless` 直跑游戏时这条为真、调试器会话却不在，于是每棵树发送失败（`_ready` 一次、`interrupt` 一次）。导出构建不响。

### 选型账（写给下一位读者）

在 C# 里写 AI 任务只有两条真路：改自家搬进来的 Beehave（本方案），或换 module 专版引擎的 LimboAI（已彻底移除）。后者代价是引擎二进制绑到专版构建。取前者由用户确认。原始账见 `docs/research/README.md`。
