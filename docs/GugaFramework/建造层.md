# 建造层 — GugaFramework 说明

> 讲 `src/GugaFramework/Construction/`：答「能不能放、实际落在哪、造到哪一步了」。
> 约束句在 `AGENTS.md`「契约索引」。本文只记事实、机制、操作步骤、实测数字与设计结论。
> spec `.scratch/construction/spec.md`，决策 `docs/adr/0005`、`0006`、`0007`。

## 0 一句话形状

**一个建造模块 + 一个放置规则 seam + 两条规则（网格 / 自由）**，不是两套建造系统。册、占用、建造过程、损毁、事件出口、动词表、快照段全是一份。整族纯 C#，原型**组合持有** `ConstructionCore` 而不继承它。

### 0.1 落了哪几件

十三份源码：`ConstructionCore.cs`、`PlacementRule.cs`、`GridPlacementRule.cs`、`FreePlacementRule.cs`、`ConstructionVerbs.cs`、`ConstructionEvents.cs`、`Blueprint.cs`、`IConstructionHost.cs`、`HoverVerdicts.cs`、`BuildLifecycle.cs`、`BatchGestures.cs`、`LayoutBlueprint.cs`；用例在 `src/GugaFramework/Tests/` 下八个文件。

### 0.2 「不判自己」不等于「不占地方」

`RegisterFixture` 跳过落位校验，但**照样占位**，好让后来的玩家建筑被 `Check` 判成 `TooClose`。

## 1 骨架与两条放置规则

### 1.1 完备性判据

**生命周期内完备，seam 外零泄漏。** 模块不认识经济、建筑功能、升级、科技、建造者、地形数据。

### 1.2 裁决是三路共用的唯一真值

`Check`（纯查询）是**悬停、落建、直达口三路共用**的唯一判定实现；**经济类原因不进模块**，**每次拒绝都是原型「不扣款」的信号**。

### 1.3 两类失败的分界

**作者错误当场抛**（名单外动词、必填缺参、方向越界、伤害 ≤ 0、显式重名、形状与规则不匹配）；**世界状态拒绝回 `Ok=false` + Reason + 录 `ok=false`**（越界、压占、过近、不可建、状态不对）。参数一律竖线切、位置固定、**没有转义档**（「桥只转发」）。

### 1.4 网格规则

格坐标 = `floor(世界坐标 / 格长)`，**用 floor 不截断**，测试盖 `0.9` / `-0.1` / `-1.0` / `-0.001`。占地 = 锚点格 + 非负偏移，锚点 = 最小行最小列，**只登记锚点格**；边界 = 有限矩形，格长非正或边界反了当场抛。方向是**八值整数编码**：`0~3` = 旋转 `k × 90°`，`4~7` = **先镜像再**旋转，变换在**本地包围盒内**做；编码里**没有「纯镜像」那一档**。

### 1.5 自由规则

间距**边缘到边缘**，半径是蓝图数据；位置量化缺省 `0.01`，角度量化缺省 `15°`，裁决给整数度；**自由放置没有边界矩形**，自由侧走宿主，快照段印 `bounds=unbounded`。

### 1.6 内部 seam：核心只持册与生命周期

规则接口是 **public**（插件槽要求原型构造时递进实现类型），Core 不向外返回它。

### 1.7 方向整数由规则解释

八值语义住在 `GridPlacementRule` 的 `GridOrientation`、角度步长住在 `FreePlacementRule`，**Core 只透传 `int`**。

### 1.8 实测数字

`dotnet build` 0 警告 0 错误。`src/GugaFramework/Construction` 无「造」字面量。

### 1.9 悬停：推手势，不是每帧轮询

表现层推**手势描述**，模块去重两层，裁决不变就零事件；悬停态不进 Journal、不进检查点快照。

### 1.10 预览一致性契约

表现层显示「能不能放 / 落在哪 / 占哪些格 / 什么角度」只准读裁决流，**禁止第二次计算**。

## 2 建造过程与生命周期

### 2.1 两态状态机，摧毁不是状态

`BuildState` 只有 `Building` / `Completed`，**摧毁是一个去向不是一个状态**，归零走 `Detach(b, RemovalCause.Destroyed)`；`Commit` 与 `Advance` 调同一个私有 `Countdown`，**全模块没有第二处完工判定**。

### 2.1b 归零之后留不留册，由调用方答

归零去向是**玩法决定不是模块内务**：同一件事在不同原型里可以一个要拆、一个要留。模块因此把它当插件槽，与既有那几处同一口径（`FrozenProbe`、`NavPipelineSpec.Gate`、`IConstructionHost`、`tick` 源、`EntityCore.payloadOf`）。

- 构造末尾收 `Func<Building, RemovalCause, bool>? removePolicy = null`；**没递 = 答出册**，与接缝之前逐字相同。
- 问询收敛在私有 `DetachOnZero`，`Damage` 与 `SetHealth` **两个零出口都走它**——只改一处等于半个口子，负数两条路都仍当场抛。
- 政策拿到 `Building` 与 `RemovalCause`：答留就停在册上、血量是真 0、仍 `Find` 得到；答出册走同一条 `Detach` 链（空转、撤占用、发 `BuildingRemoved`、重算）。
- `SetHealth` 带政策时 `hp == 0` 是合法写入（与扣血扣到 0 同一件事，两个出口若一个抛一个不抛，同一原因会在两条路上给两个答案）；不带政策时非正数仍当场抛，与接缝之前相同。
- 这一条只在这道缝上被问，去向恒为 `RemovalCause.Destroyed`。`RemovalCause` 仍是三值闭合枚举、**没有敌意/意外之分**，`BuildingRemoved` **仍不带载荷**，所以政策覆盖移除时没有级联钩子——那两处是独立的设计问题，本轮只报告未实现。

宿主经 `WorldAssembly.BuildConstruction(…, removePolicy:)` 递进来，那是生产代码里唯一构造 `ConstructionCore` 的位置。纯委托不吃 Godot 类型，`src/Tools` 那份按源码链接的构建不需要加排除行。

### 2.2 在建五格

**占用**放置即占、在建期间不腾；**血量**放置即满值，施工中打空 = `Completed` 永不发 + 立腾占用（出不出册由 2.1b 那道政策答）；**功能**由原型挂 `Completed` 事件起；**进度**是整数倒数，模块 `Advance(steps)` 由原型在自己的 Advance 固定点调，**没有定时器对象**。

### 2.3 暂停只停住倒数

`PauseBuild` / `ResumeBuild` 只把倒数停住，**模块不问为什么**；重复调都回 `InvalidState`。

### 2.4 修复钳上限，而上限可以被合法抬高

`Repair(id, amount)` 与 `Damage` 对称、钳到上限。**`SetHealth(建筑id, hp)` 把上限一并抬到 `max(现上限, hp)`**：上限只抬不降，要更小的上限走 `Remove` + 重新放置。

### 2.5 载荷是不透明数据

`Commit(..., object? payload)` 挂上，`Find(id).Payload` **原样还回同一个对象引用**，模块不解析、不进快照、不进事件行；蓝图不可变，换血量上限或占地 = `Remove` + `Commit`。

### 2.6 快照段的形状

一行摘要 + 每建筑一行。**格式化只有 `RenderSegment` 一处生成**，两处出口共用：

```
construction kind=Radius buildings=8 occupied=8 bounds=unbounded
B palace Palace Hero lv=1 pos=-8,0 hp=8000/8000 state=completed left=0 paused=0 dir=0
```

每行 = **模块的 D32 九列**（`id 蓝图 锚点/坐标 hp=当前/上限 state left paused dir`）**＋ 载荷的 Owner / lv 两列**，原型列由原型自己印。网格侧印 `anchor=0,0`，自由侧印 `pos=x,y`。

### 2.7 实测数字

`src/GugaFramework/Tests` 全库 **441** 通过 / 1 跳过，建造族 192 通过。各原型那几条的读数记在 `docs/prototypes/<原型>/`。

### 2.8 偏离 spec 与 spec 未钉之处

`PlaceBuilding` 多了第 7 段「载荷原文」；**载荷原文不许出现竖线，也不许字面写 `-`**（`DashToNull` 把 `-` 与空都当「没有这一段」）。

## 3 编辑器动词

### 3.1 Move / Rotate 走同一条链

差别**只有「候选点从哪来」与「发哪条事件」**；**原子**，失败一寸不动；**占用检查排除自身**；id / 载荷 / HP / 建造进度全保留。

### 3.2 方向是绝对值，不是「转几步」

`RotateBuilding` 的**方向必填**，缺了当场抛 `FormatException`——兜一个缺省会让「转」在 Journal 里可能整条不存在；`MoveBuilding` 的方向是**单独一格可省档**（null = 保持当前）。

### 3.3 本模块写路径里唯一一处不对称

**`Commit` 拒绝发 `PlacementRejected`，`Move` / `Rotate` 拒绝不发事件**，一次没成的拖拽不是「放下一座被拒」。

### 3.4 `BuildingAt` 是 call 类

命中回 id，未命中回空串；重复调用三次后快照段逐字不变；不在 `InjectNames` 里。

### 3.5 实测数字

`ConstructionEditorTests.cs` 19 条 + `ConstructionVerbsTests` 5 条。

### 3.6 留给后面的口

「转一步」的换算没有入口；拖拽预览缺「排除自身的**只读** Check」。

## 4 批量与区域蓝图

### 4.1 两套批量语义刻意并存

`PlaceLine` 与 `PlaceRect` **部分成功**，边判边落，回成功计数 + 逐格裁决；`PlaceLayout` **全有或全无**，任一成员判不过则一个都不落；`RemoveRect` 部分成功、**不加汇总事件**；**顺序单一真值 = 确定性**。

### 4.2 布局是数据不是状态

区域蓝图 = 名字 + 成员列表，`Layout` / `LayoutMember` 只读不可变；**放置的 args 自包含**，一条 Journal 记录即可逐字重放。

### 4.3 批量预览与提交同一条流水线

`CheckLine` / `CheckRect` / `CheckLayout` 是三个**公开纯查询**，与提交同一条流水线。

### 4.4 事件粒度

成功成员**逐个**发 `BuildingPlaced`，外加汇总 `BatchPlaced` / `LayoutPlaced`；布局整体拒绝发**一条** `LayoutRejected`。

### 4.5 `BatchResult` 的两列是两把尺子

`Placed` 量发出去号的几个，`Failures` 量判不过的几个，`PlaceLayout` 的判据是 `FailedCount > 0`。踩坑：按裁决一刀两断时整体被拒会报成「落下 1 个」而世界里一条也没落，`PlacedCount` 是算钱与动词 `ok` 的依据，报 1 会付错钱。

### 4.6 实测数字

`ConstructionBatchTests.cs` 25 条，`ConstructionLayoutTests.cs` 22 条。

### 4.7 留给后面的口

**载荷格**：`PlaceLine` / `PlaceRect` / `PlaceLayout` **三条没有载荷格**；另有整布局 `Move`、布局名注册表、盒形占地 OBB + 分离轴、六角格规则。

## 5 场地建筑登记（`RegisterFixture`）

### 5.1 这条口是被一个真 bug 顶出来的

成因是**种子建筑不在册内**：模块的裁决流看不见它们，原型在落建入口里补了自己的距离判定，于是**同一个点上两处裁决不一致**。

### 5.2 两条修法的代价实测

禁区是 `MinPlaceDistance = 12` 这条**玩法规则自带**的；**结论：改地图那一条修不了这个 bug**，要彻底消掉得把 `MinPlaceDistance` 归零，那是改玩法。

### 5.3 `RegisterFixture` 的口径

`RegisterFixture(蓝图id, 位置, 建筑id, 方向?, 载荷?)`：**进册 + 占位 + 跳过落位校验**，**但它照样占位**；它是**独立一个成员**，不是 `PlacementRequest` 上的「跳过校验」开关；进度直接落在完工只发一条 `Registered`；作者错误当场抛，这一格**没有「打不成」的读数档**；占用几何由放置规则产（`OccupyFixture`），**核心不重算任何一列**。
**不进 Journal**（`InjectNames` 里没有它）：它调在世界初始化期，两端都跑同一个 `SeedWorld`，录一遍反而会在重放端重复登记、当场撞重名那道抛——**这是写路径上唯一的例外**。

### 5.4 修完的读数证据

同一条探针改前改后逐字对照，`coreReason` 从 `None` 变 `TooClose` 正是修好了的证据；**这在迁移前是「只能出图看」的表现层事项，现在是一发 `dotnet test`**。

## 6 迁后形状与接缝

自由规则已经有真实消费者落地。顺序照「先接后删」：**先接新 → 验证绿 → 再删旧**。逐原型那一趟的迁后形状、逐条实测与踩坑记在 `docs/prototypes/<原型>/`。

### 6.1 迁后形状

蓝图半径由玩法那条距离规则折半（`MinPlaceDistance / 2`），位置量化 0.01，方向段恒 0，工期 0；载荷文本 = `阵营/等级/产出周期`（**斜杠分隔**，竖线是 args 分隔符，见 2.8），入录 args 从 3 段变 7 段；**建筑 id 与工期不记**，id 照世界的编号规则在重放端逐字复现；**旧脚本照旧可重放**。

### 6.2 「一份表、两处问」与订阅那一半

`ConstructionVerbs` 标准动词表是公共层一份，原型注入 = 薄适配器（`SupportedVerbs` 声明 + 每个动词一次调用），名单外当场抛；**模块事件流没有推送订阅**，只有只追加环形表 + 只读出口。

### 6.3 直达口与玩家那条走同一个写入口

原型侧的落建直达口 → `Write("PlaceBuilding", Args(种类, 坐标))` → 录制器 `Inject` → `ReplaySetup.PlaceBuilding` → `ConstructionVerbs.Dispatch(…, Place, …)` → 世界的落建核心。桥那一层的 `inject` 与玩家点鼠标那条走同一个写入口（「桥只转发」）。

### 6.4 一处静默毁世界的缺陷

游标记的是「留下来的第几条」，环形表满之后**留下来的条数恒等于容量**，游标卡住不动；现在改成「全局流里读到第几条」对齐 `Events.Total`。

### 6.5 重放基线处置

快照形状变，按「断言三层」走良性改动条款：落盘基线重录在新格式、仍 L3 逐字，已有那份停在 L2 的脚本**内容一字未改、档位仍 L2**。

### 6.6 这条线上的真机操作口径

真机跑法与故障查表见《验证操作手册》。

### 6.7 待确认项

- 其余待办见 3.6 与 4.7。

## 8 消费者与收编账

两条规则都已实现并各有真实消费者：自由规则、网格规则（契约测试验收，D35）。逐消费者的接入状态与收编读数记在 `docs/prototypes/<原型>/`。

**这一层对 prototype 侧的永久边界**，它不是缺失功能：经济与计价、建筑功能、原地升级、建造者政策、地形数据、死后结算、退款政策。三条**文档化耦合**是接口的一部分：**时序契约**（原型在自己的 `Advance` 固定点调模块 `Advance`）、**经济排序契约**（先查钱 → `Commit` → 成功才扣，拒绝 = 不扣款信号）、**蓝图构造时注册**。

**单位↔建筑的伤害路径改走技能层**：`EngageBuilding` 与怪物袭城那两处不再自己调 `DamageBuilding`，改由技能层判激活检查、算这一笔、再写回模块，且写回只走 `ConstructionCore.Damage` 不走 `SetHealth`；机制与 `TargetGone` 那一档拒绝理由见 `docs/GugaFramework/技能试验场.md`「建筑进技能目标域」一节。

### 8.1 场地建筑收编那一档

场地建筑各走一条写路径、血量全部归模块；**场地建筑都不落阻挡**（地标那一类若掉墙，「进圈」的判定永远打不着）。逐类读数记在 `docs/prototypes/<原型>/`。

### 8.2 赛前路障那一档

赛前路障是**网格规则**的第一个真实消费者：蓝图单格占地、格长 1.0 米（「档与表钉死」）、方向恒 0、工期 0 步、模型引用空串（**不渲染**），**只在布阵期摆得下与撤得动**，开打之后两发都回 `ok=false + InvalidState`。绕行基线那几格读数记在 `docs/prototypes/<原型>/`。
