# 实体层（`src/GugaFramework/Entities/`）

答「场上有谁」的公共层。约束句在根 `AGENTS.md`「契约索引」。词条见根 `GLOSSARY.md`「15 实体层」。定稿档 `.scratch/entity-layer/spec.md`。

## 1 册子里有什么

`EntityRecord` 一条只有四格（D3）：

| 格 | 谁答 | 说明 |
|---|---|---|
| `Id` | 原型 | 身份字符串，`p01` / `hero_3` / `m1` 各是各的格式 |
| `Seq` | 册子 | 序号，单调递增、永不复发（D8） |
| `Kind` | 原型 | 短字符串：这一条是哪一类 |
| `Payload` | 原型 | 不透明载荷：册子存它、还它、不读它（D7） |

血量、阵营、位置、属性一格都不在。血量真值有四处不同源（`Unit.Health` / `BattleUnit.Health` / 技能层 hp 属性 / `Building.Health`），硬抽一处要动两个已交付模块（D2）。

## 2 四个不变量

| 不变量 | 实现形状 |
|---|---|
| **id 唯一且永不复发**（含读档恢复） | 每个 id 占一个**永久槽**，摘册只把槽标成不在册 |
| **序号单调、永不复发** | 册子发 `++_seq`，原型拼 id 字符串 |
| **稳定遍历次序 = 登记次序**（D10） | 遍历走 `_live`（在册槽的升序表），不是历史表 |
| **摘册不挪次序**（D14） | 复登回它首次登记的那一格 |
用永久槽而不是活表：有一个原型在居民环路重建时复用同一个 id 对象，是刻意的，复用不新增登记、次序不动。活表表达不出「复登回原位」，而那正是 D14。

## 3 两个上册的口

| 口 | 发不发序号 | 事件 | 用在哪 |
|---|---|---|---|
| `Spawn(id, kind, payload)` | 发一个新的 | `EntitySpawned` | 第一次上册 |
| `Register(id, kind, payload)` | **不发**，沿用首次登记那一格 | `EntityReRegistered` | 复用一个发过的 id（居民一类的环路单位） |

走错那一条的后果不是报错，是次序悄悄挪了一格、同种子重跑不再逐字相同。两个口都当场抛作者错误：Spawn 撞号、Register 对没发过或在册的 id。

## 4 移除次序（D11）

`Remove(id)` 内部四步，一步不缺：

```
① 摘册（槽留着，载荷丢掉）
② 寻路层定身与退注册   → IEntityRemoval.DetainInNav
③ 放旗、腾引用         → IEntityRemoval.Release
④ 发事件（放最后）
```

**②要有**：位置真值住在寻路层那条流水线里，不换命令它会照着原命令继续走，而一个已不在册的单位还在挪，读数上查不出来。三个原型各踩过一次。

**②③ 拿的是那一条本身**（`EntityRecord`），不是 id：②③ 跑在①之后，那时册子里已经查不到它，宿主回头按 id 查会拿到 null 而静默不做事。**退注册**走两个既有 API（寻路层没有注销口）：`Issue(id, NavCommand.Hold(当前位置))` 定身 + `SetCountedInSeparation(id, false)`。
## 5 活的查询口（D6）

`IEntityHost` **整个接口就一个成员**：`bool Alive(string id)`。形状照 `IConstructionHost`：不递 = 全活。不在册也答 false ——「不在册」与「在册但不活了」是两句不同的话。

## 6 事件出口（D12）

三个：`EntitySpawned` / `EntityRemoved` / `EntityReRegistered`。没有「序号推进」与「册子重置」两类：前者是 `Spawn` 的副产品，后者是 `ReadState` 的一次调用。**`ReadState` 全程不发事件**。

## 7 快照段（D15）

**段首是 `entity`**，与各世界自己的段首无关：

```
entity count=20 issued=20
p01 seq=1 kind=unit
p02 seq=2 kind=unit
```

- 调试段与重放段同一份格式化（两个入口两个名字，格式只有一处）。
- 载荷不进快照（D7）：印进去等于让册子替原型保管它会不会变。
- **各世界的段首一个字不动**：各世界自己定一个，改它要重录基线。

## 8 存档

- `WriteState` 写**全部槽**（含已摘册的那些），每行 `{id, seq, kind, live}`。只写在册的，读回来就有一段「发过的 id」不见了，于是又能发第二次。
- `ReadState(r, payloadOf)`：键序与写侧逐字一致（读侧按键顺序读，不按键查找）；同一个 id 出现两次、序号倒退，当场抛。载荷不进档（D7），读档时按 id 从原型那份对回去。
- 序号从档里最大那个接上，**不从 1 重来**。往返两串逐字相等。

## 9 读数

```
实体层 在册 20 条｜发过 20 个 id｜下一个序号 21｜事件漏登 0 条｜宿主 接上｜移除接线 接上
```

## 10 迁进度

迁出记录见 `docs/prototypes/<原型>/`。三步的顺序：先是零生成零删除那一档，接着搬大世界那份，最后搬血在技能层、居民同 id 复用那一档。

**零生成零删除那一档的实话**：战斗中零生成零删除、只置血零不出表，所以 `Remove` 与 `Register` 都没有调用点，D11 那四步的次序由公共层测试线判红。每步那句「把不活的那个发一条驻守命令」是**在册活物**的停步令，不是册子上的移除。**上册那一侧**：册子不管寻路层注册，那一处由原型侧的寻路移动件登记。

## 11 留待迁第三步验的事

居民那条「同 id 对象复用」走 `Register`：重建前后那一段的快照逐字相同。

## 12 迁完那几趟的重放基线账

册子那段进了快照，所以落盘的 L3 基线会被测试跑重录。**漂移是纯增量的**：把册子那三段（`entity count=N issued=N` 与每条 `{id} seq=N kind=unit`）摘掉之后，各原型那几份文件与 `HEAD` **逐字相同**，段首一个字没动（D15）。
