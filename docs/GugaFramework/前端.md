# 前端层（`src/GugaFramework/FrontEnd`）

**术语**：这一层叫「前端」（front-end），词义与出处见根 `GLOSSARY.md`「12 前端层」。判据在 `AGENTS.md`「输入模式单源」与「UI 试验场随前端层」。

**落点**：

```
src/GugaFramework/FrontEnd/
  FrontEndSettings.cs   纯 C#：语言 / 主音量 / 窗口模式 / 分辨率
  MenuStack.cs          纯 C#：菜单栈（LIFO）
  FrontEndLayer.cs      Godot：菜单栈的搭法、输入模式的归属、四项设置的落引擎
  FrontEndVerbs.cs      调试桥共享词表：ui_open / ui_close / ui_read / ui_result
  Stage/                UI 试验场（场景壳 + 入口 tscn）
  i18n/frontend.csv     框架共用文案表
```

## 是什么，不是什么

浮在游戏之外的那一层：开始菜单、暂停菜单、设置菜单、结算菜单。不认识任何原型，不读任何逻辑世界的数据。冻不冻结时间归原型的世界（前端只抛 `PauseRequested`，→ 「表现层只读」）；「开始」跳哪归原型。它管的一件事：输入模式——`Input.MouseMode` 与控件焦点只在这里设。

能离线判的判在离线（与 `SkillStage` / `SkillStageScene` 同一笔账）。

| 文件 | 引 Godot | 离线可测 |

| `MenuStack.cs` | 否 | 是（11 条用例里 5 条） |

## 菜单栈

后进先出。开设置叠在暂停屏上面，退一层回暂停屏而不是全关——上面那层停用不销毁，所以滑条拧到哪一格、焦点停在哪一个按钮都还在。与 Unreal CommonUI 的 `ActivatableWidgetStack` 同一形状。两条规则各有判据钉着（`FrontEndTests.cs`）：重复开同一屏不叠层；退空归 `None` 而不是报错。`KeepTopOnly`（换根）与 `Clear`（全关）写混的结果是退出游戏。

**结算屏是唯一的例外，它走 `PushExclusive`（栈里只剩它）**。`Result` 与暂停屏不是「叠在上面的一层」那层关系，是替身：按 `Push` 叠上去的栈形是「暂停屏 + 结算屏」，而结算屏之上没有一层能退——退一格回到暂停屏，玩家看到的是一局已经打完的世界，那屏上写着「继续」，点下去什么也不会发生。开 `Result` 时原先栈里有暂停屏就顺手抛一次 `PauseRequested(false)`（那一屏已经不在了，留着暂停标记等于把世界冻在一个玩家看不见的暂停上）。

## 局开始与局结束

两个事件抛在**这一层**，不抛在逻辑世界（「表现层只读」+「原型隔离」）：逻辑世界不认识菜单，菜单也不该认识任何一个世界。

| 入口 | 时机 | 副作用 |
|---|---|---|
| `NotifyRunStarted()` | 宿主在自己那一局装配好之后 | 抛 `RunStarted` |
| `NotifyRunEnded(RunOutcome)` | 判定落地那一刻 | 抛 `RunEnded`，再 `SetResult` + `Open(Result)` |

`RunOutcome` 是中性形状：`Title` / `Details` / `Tick` / `Won` / `Actions`。「赢/输/平」在三个原型里是三套不同的枚举，步号的读法也各不相同，所以内容一律由原型递，框架只保证形状统一。**次序是「先抛事件，再开屏」**：订阅方在事件里冻时间轴，开屏那一下可能顺带发一次解除暂停，冻在后面才不会被那一发解掉。

## 结算屏

`SetResult(title, details, actions)`：接标题、几行明细、几个按钮，**本层只摆版式**。末尾自动补一颗「退出游戏」——结算屏是模态的、栈里只剩它，原型若把按钮都做成「不能退出」，玩家就再也没有路离开这一局。进这一屏之前，三个原型各画了一套结算 UI（一个居中 Label、一块自绘面板、一行 HUD 字），现在统一由这一屏画；原型侧 HUD 只留玩法读数（阵面、存活数、地标血量）。

## 冻结口径

局结束冻结时间轴，三个原型统一（用户裁决）。**真值在基类一个字段**：`GameLogicBase.TimeFrozen` + `FreezeTime()`，没有反向口。**闸不在基类的推进口，在推进公共件那一条路上**（`WorldAssembly.FrozenProbe`，`GameLogicBase` 构造时把 `() => TimeFrozen` 递进去）。要翻回「局结束不冻结」改那一个字段加订阅方那一行，不必逐个原型改回去。

闸开在公共件那一处而不是基类的 `Advance`：有的世界重写了 `Advance` 并直接调装配那一份，闸开在基类就绕过去了。`AdvanceTo` 也走 `Advance`，所以三条推进的路都从这一道闸过。

冻结与暂停分成两个字段是有意的：暂停可解冻（玩家按继续），冻结是这一局的结局（结算屏上的「再来一局」走的是换世界，不是解冻）。合成一个字段的话读数会把「打完了一局」念成「玩家按了暂停」。

冻结从**下一次** `Advance` 生效，当前那一步推到底——判定照旧照跑，闩锁与事件都在冻结之前就落地了。

**2026-10-12 补记**：这一段初版写的闸在基类那一处推进口，缺口记在下面那条待确认项里。缺口已收口（闸改开到公共件那一处，三个原型一致），收口后的机制 → `docs/adr/0016` 与 `docs/GugaFramework/世界装配.md`。

## 四项设置

| 项 | 落引擎那一发 | 越界怎么办 |
|---|---|---|
| 语言 | `TranslationServer.SetLocale` | 空标签当场抛 |
| 主音量 | `AudioServer.SetBusVolumeDb("Master")` | 越 0~1 当场抛 |
| 窗口模式 | `DisplayServer.WindowSetMode` | 未定义枚举当场抛 |
| 分辨率 | `DisplayServer.WindowSetSize` | 边长非正当场抛 |

越界一律抛，不静默钳（照 `SpeedControl.SetMultiplier` 那一档的理由：挡笔误）。只落变了的那些。`Resolutions` 那张表是下拉里给的档位，不是白名单。

## 接法（原型侧）

```csharp
var front = new FrontEndLayer();
AddChild(front);
front.PauseRequested += paused => _world.SetPaused(paused);   // 冻不冻由你答
front.QuitRequested  += () => GetTree().Quit();
front.SetTitleEntries(("开始新局", () => StartRun()));        // 条目由原型递
front.SetPauseEntries(("操作说明", ToggleHelp), ("回标题", ShowTitle)); // 暂停屏多出来的条目也由原型递
front.RunStarted += () => Log("局开始");
front.RunEnded   += o => _world.FreezeTime();                  // 局结束 = 冻住时间轴
foreach (var (v, h) in FrontEndVerbs.Vocabulary(front)) _bridge?.Register(v, h);

// 宿主在装配好一局之后、判定落地那一刻各报一次：
front.NotifyRunStarted();
front.NotifyRunEnded(new RunOutcome(title, details, tick, won, actions));
```

`FontSetup.Install()` 要先调一次（缺省字体没有汉字字形，菜单上屏会是一片空白）。

`SetPauseEntries` 收的条目落在「继续」之后、「设置」之前；框架自己的「继续 / 设置 / 退出游戏」始终在，不递条目的原型仍是那三颗。条目只收「文字 + 动作」，框架不认识「操作说明 / 重开 / 回标题」这些语义。

## 存档区

设置屏那一栏，接在四项设置后面：一条分隔线 + 「存档」标签 + **一条**槽位条目（槽号 / 存盘时刻 / 文件字节数 / 保存·读取两个按钮）。清单与两个动作都由原型经 `BindSaveSlots` 递进来；清单是取值的函数，不是一份快照，所以 `RefreshSaveSlots()` 在开设置屏、写完档、读完档三个时机各调一次。

**「读档之后 UI 不会自动同步」**：那些控件构造时一次建好、永不重建，原型读档填回 `FrontEndSettings` 之后要自己调 `RefillFromSettings()` 往控件上写，并**一并重置那四个 `_applied*` 字段**，否则 `ApplySettingsToEngine` 认为「没变」而跳过落地。存档机制本体 → `docs/GugaFramework/存档层.md`。

## 调试桥四发

与 `InputInjector` / `LocaleVerbs` 同一档：公共层的**共享词表**，由原型侧展开注册，不占标准七动词的名字（「标准七动词」）。

| 动词 | 参数 | 干什么 |
|---|---|---|
| `ui_open` | `screen=title\|pause\|settings\|result` | 开一屏，回读栈深 |
| `ui_close` | 无 | 关最上面一屏，回退完之后栈顶是谁 |
| `ui_read` | 无 | 念出栈、设置、输入模式三项 |
| `ui_result` | `title=<键>`、`line=<键>`（可省，可给多条） | 填结算屏并开它，回读行数 |

`ui_result` 单独一发是因为 `ui_open screen=result` 开出来是「（这一屏的内容由原型递进来）」那行占位字，出图复核看不到结算屏长什么样。

读数格式：`stack=Pause > Settings depth=2 top=Settings | locale=zh master=0.75 mode=Windowed resolution=1920×1080 | mouse=Visible`。三件事放一行，菜单卡住时最容易分不清是「栈没弹对」还是「鼠标模式没收回去」。接了存档区之后末尾多一段槽位清单原文（槽位 / 原型名 / 步号 / 字节数 / 存盘时刻），那是**调试桥的读数**，界面上给玩家看的那几行少了原型名与步号。

## UI 试验场

`src/GugaFramework/FrontEnd/Stage/FrontEndStageScene.tscn`，要在引擎里跑。它自带一块底与一台固定机位：菜单要浮在**真的东西**上面才验得出来遮挡。

### 七格验收

| 格 | 怎么验 |
|---|---|
| 开一屏 | `ui_open screen=pause` + 出图，看面板与遮罩 |
| 栈叠对不对 | 暂停屏进设置，`ui_read` 应念 `stack=Pause > Settings`；退格回暂停屏而不是全关 |
| 鼠标收没收回来 | `ui_read` 末尾那一格 `mouse=`；关屏后应等于开屏前那一档 |
| 设置落没落上 | 改音量/窗口模式/分辨率，`ui_read` 念四值，出图看得见窗口尺寸变了 |
| 取字走没走 Loc | `set_locale en` 之后出图，那一行字应该不是中文了 |
| ESC 收不收得住 | 连按两下 Esc 不该叠两层暂停屏 |
| 结算屏是不是替身 | 标题屏第二颗按钮抛局结束事件，`ui_read` 应念 `depth=1 top=Result`；再 `ui_result --title "…" --line "…"` 出图复核版式 |

### 操作步骤

1. 起场子：`godot --path . src/GugaFramework/FrontEnd/Stage/FrontEndStage.tscn`
2. 配端口 `DEBUG_BRIDGE_PORT`，起桥。
3. 先探活再操作（「三条铁律」第①条）：`ping` → `verbs` → `call ui_open screen=pause` → `call ui_read` → `call screenshot path=<路径>`（「落地配出图」）。
