# 确定性与重放 — GugaFramework 说明

> 讲确定性测试怎么搭、重放三级各答什么、断言怎么写才不空。约束句在 AGENTS.md「测试与确定性」一组。

## 确定性测试基建

**分工**：纯 C# 逻辑行为走 `dotnet test`，表现层绑定走真机实测（→「测试与实测分工」）。入口 `dotnet test src/Prototypes/<原型>/Tests`，读失败输出走 trx（→「失败读 trx」）。

- 原理：测试项目**源码链接** `Scripts/Logic/*.cs` 与 `src/GugaFramework/**/*.cs`，不引用 Godot 主 csproj；链进 `Scripts/Main.cs` 当场编译失败。
- **确定性哨兵**（`DeterminismSentinelTests`）：同种子两遍 / 逐步 vs 大块快进 / 暂停冻结不变性。隐藏随机源与浮点精度丢失在这里先红。
- **重放脚本**（`ReplayScriptTests`）：`JournalingWorld` 装饰 LogicWorld 在逻辑写路径录 `{tick, 命令, 参数, ok}`；重放端同种子建世界 → 按步注入 → 快照逐字断言。排布口是 `LogicWorld(randomSeed: 42)` + `Advance(n)`。
  - **写路径全录**（→「写路径全录」）：连排布口 `DebugSetTreasury` 也要进 Journal，漏录则重放端金库对不上。
  - **同一步的先后**（→「先快照后命令」）：录制端先抓快照后发命令，顺序反了金库立刻差一笔。
- **守恒不变量**（`EconomyConservationTests`）：逐步断言「金库+钱包+在途旗 = 150 + Σ注水 − Σ焚烧」。

### 断言三层（`assertLevel`）

脚本头部 `assertLevel` 选档：1=L1 不变量（不进脚本，由守恒测试承担）/ 2=L2 语义 / 3=L3 逐字（缺省）。写端恒写键，读端缺键默认 L3，存量脚本零迁移。

**L2 的机器红绿线（零游戏知识）**：红的是结构——头部步号漂移（`tick` 键）、实体段数漂移、段首身份（类型+Id）漂移；键集漂移与同键值漂移容忍。命令 ok 翻转不走快照路径，任何档位都红。降档即改 json 头部 `"assertLevel":3` → `2`。本体重放与取证器（`--report`/`--bisect`）同用一份 `CheckpointPasses`。

## 重放分三级 — 一份日志、多个消费端

同一份 Journal 加同一粒种子，能在三个地方跑。

| 级 | 回答什么问题 | 一致性到什么程度 | 走哪条通道 | 现状 |
|---|---|---|---|---|
| **级 1 逻辑重放** | 第 1800 步（180 秒）为什么没放出来 | 快照可比对，强度按 `assertLevel` 选档 | `dotnet test`、`replay <原型> <json> [--report\|--bisect]` | 已就位 |
| **级 2 引擎重放** | 这一局看起来、手感对不对 | 逻辑对齐；画面近似 | 起活局 + 按步喂进 `inject` 词表 | 已就位 |
| **级 3 录像** | 留一份当时的画面证据 | 不是一致性问题，是证据 | `--write-movie`、真机截图（→「落地配出图」） | 已就位 |

**级 2 的前提是时序归逻辑**：每一步该发生什么由 `Advance(steps)` 决定。计时交给引擎回调（`create_timer`、动画通知、`_process(delta)`）就唤不醒，落哪一帧也不确定。口住 `Replay/LiveReplaySession.cs`，不住 `DebugBridge/`（后者被测试项目按表现层排除）。

**三条口径**：① **时间轴归剧本**——级 2 开局即 `SetPaused(true)`，只由 `LiveReplaySession` 经钩子的推进口喂（该钩子现为基类的 `AdvanceTo`，实体循环在 `WorldAssembly.AdvanceTo`，护暂停；反证：不暂停当场报分歧 6）；② **比对前先归一行尾**——桥 CLI 是 CRLF，脚本写文件是 LF；③ **换局即作废**——中途 `duel`/`restart` 后抛「会话作废」。回传用指纹，红了再 `replay_detail <seq>` 取全文。级 2 不追求逐帧相同；挂上行为树那格另看 `brain` 的 `treeDecisions` 等于「兵数 × 步数」。

### 子快照并进重放段格式：整行的分号都要换空格（现法在码、断言是 A53）

只换第一个分号，「类型」就占一个 token、其余列全挤进第二个 token。L2 语义档比的正是「段首两个 token = 实体身份」，于是给层的行尾加一列，降到 L2 照样全红。现法是 `BattleWorld.ReplaySnapshot` 与 `SkillTestWorld.LayerRowAsSegment` 各一句 `Replace(';', ' ')`。

### 同一份数据有两条落地路径时，断言要在两条路上各跑一次

- **两条结算路径**：`CancelMatchingTags` 写在 `ApplyEffect` 里，带 `DelayTicks` 的走 `Settle` 根本不经过那儿，「延迟 + 打断」于是静默失效：不报错、不红、什么都不发生。修法是两处收进 `AbilityStepper.QueueCancels`。
- **一份抄了两遍的表**：H2 与 H3 各一份，同一发 `CastAbility` 第 4 段目的地因此一侧接得住、另一侧被静默丢掉。现法是一份 `AbilityVerbs.cs`。

**两份实现必然漂移，断言要在两条路上各跑一次。不接的词当场抛 `NotSupportedException`**，返回 false 会被录进账。

### 给状态加一列之前，先定这两条

1. **写得出不等于读得回**。新列要有「交给 `Load` 再念一遍」那一腿（`p;` 行的 `move=从>到` 靠断言 A66 钉住）。读不懂的形状当场抛，不兜 0。
2. **真用到时念得出，就不逼重录基线**——加 `move=` 列那一轮逐字基线 `git diff` 为空。

### 一份断言 + N 个注册壳：同一张清单要在多个宿主上跑

技能层那 16 条（D1~D8 + F1~F8）第一次在三个宿主上跑全（H1 假数据 / H2 单挑场 / H3 真 1v1）。**通用的是形状，不是那 16 条。** 断言本体在宿主无关的 `Tests/AbilityChecklistTests.cs`，每个注册壳一文件，只登记自己那一侧的名字、数字与支持位。契约是 `IChecklistHost`，外加 `Shapes` 那 **34 个槽位**；本体自证「不认得原型」（A54），壳侧由 A70 自证没有第二份断言。

## 重放装配收成一处

公共那半原先在三个原型里各抄一份。收口进 `src/GugaFramework/Replay/`：`ReplayAssembly`（词表派发 / 写路径守卫 / Journal 追加 / 检查点守卫）+ `ReplayArgs`（分隔与规范化）+ `IReplayWorld`（世界契约）。约束句在「重放装配单源」。

**各原型递哪三样**：① 自己的动词名单；② 每个动词那一次调用；③ 推进到目标步的循环。别拿「删了多少行」当收益——三份原型文件是变长的（191→212、157→191、175→210），长出来的是注释。

### 跑契约测试

```bash
dotnet test src/GugaFramework/Tests      # 含 ReplayAssemblyContractTests（14 条）与 ReplayArgsTests（6 条）
```

这个项目不在 `DemoFactory.sln` 里，根目录 `dotnet test` 碰不到它。

### 各宿主的规范化口径不一样，这是事实不是缺陷

**有别名集的宿主**把 token 折成枚举名那一种；**没有别名集的宿主**复用技能层那份 `AbilityVerbs`，token 原样取，所以原样就是规范形状。为消掉「空串 vs 省略」造回渲染器，是为修不成问题而造机器。修的是结构不是文本。逐宿主那几行读数记在 `docs/prototypes/<原型>/`。

### 收口时踩到的两个坑（都写进了契约测试）

- **`Dispose` 不清 Journal / Checkpoints**。调用方常把这两个 `List` 的引用直接递进 `ReplayScript`，清空等于在对方手里抹账；而空脚本读回自己照样自洽，假绿比红更贵。
- **`ReplayArgs.Number` 的 float 与 double 是两个重载**。float 升 double 再走 `"R"`，`0.1f` 打成 `0.10000000149011612`，逐字基线当场分叉，且不报任何错。

### 顺带统一的一格：起点快照

原先有一个宿主第 0 步记 `null`，另两个抓实快照。收口统一成开录即抓。

## 重放脚本落盘补末尾换行

`ReplayScriptJson.Write` 是公共层唯一那份写口径，末尾补一个 `\n`。不补的话，回读用例会就地重录脚本，每跑一次全量就弄脏一次工作区。

## `replay-mcp-smoke.json` 重录结果与仍红的那一处

重录经编辑器通道完成（CLI 给不了）：产物 **119675 字节**、`assertLevel=3`、**3 条 entries**、**检查点 2 段**。仍红在起点快照——活局录制 **37047 字符 / 33 段**，离线重放 **36570 字符 / 31 段**，第 28 步 `hero_0` 的位置差约 **1.12 米**。含义是两个世界的构造路径不同，不是脚本坏了。

**根因（已钉死）**：**行为树只在活局存在**。活局侧世界从接管那步起跳过整条决策链（实测 `BrainIntentOf("hero_0") = 0`），离线侧排除 `beehave/**/*.cs`、`DelegateHeroToBrain` 零调用方（实测 `= -1`）。根子是树的意图没进 Journal。修法是 `ReplaySetup` 动词表加 `ReportBrainIntent`，意图口改走同一 sink，`ReplayAssembly` 加「挪正式起点不清账」与「补一笔起点前的写」两个口。那条用例由红转绿。

## 存档动词为什么单独分一档

存档模块落地（机制在 `docs/GugaFramework/存档层.md`），给 `ReplaySetup` 补了一张 `InjectNames` 分档表。原先 `VerbNames` 是一张平表，`ReplayAssembly.cs:223` 只判 `IsVerb`，加一条就自动进 Journal；另两处早有分档表。

**分掉的两条是 `WriteSave` / `LoadSave`**：写档不改逻辑状态，读档是换世界，都不是「一次写」，录进去离线重放端会去找一个不存在的表现层钩子。那两条由表现层递进来（`ReplaySetup.SaveHooks`），重放端 `SaveVerb` 返回「没有接线」判否，不抛。

## 存档往返与调试快照的分工

`WriteState → ReadState → WriteState` 逐字相等是存档层的验收口径，`SaveRoundTripTests.cs` 16 条全绿（一条顺手断言体积在 10MB 之内）。**红只有两种病**：有派生数据被存进去了，或漏了字段。

它比「读回来再写出去」，重放比「同种子两跑」，两把尺子不同。「读档后与不读档的那一局逐步相同」本版没做。权威状态被写两遍这一版接受，取舍记在 ADR 0012。
