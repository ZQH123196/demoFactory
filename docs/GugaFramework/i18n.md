# i18n 层

> 约束句的唯一出处是 `AGENTS.md`「契约索引」，本页只记事实、机制、操作步骤、实测数字、设计结论与待确认项。

**落点**：`src/GugaFramework/I18n/Loc.cs`（取字与格式化入口）；翻译表 `src/Prototypes/<原型>/i18n/<原型>.csv`（每原型一份，彼此独立）；判据测试 `src/GugaFramework/Tests/I18nRuleTests.cs`（纯 C#，离线）。

## 为什么是「中文当键」

键就是中文原文，经 `Loc` 透明查表替换：查不到就把中文本身当译文显示，所以「没有译文」和「没接 i18」长得一样。
## 取字入口

```csharp
using DemoFactory.GugaFramework.I18n;

Loc.T("中文");                        // 取字；查不到返回键本身
Loc.Fmt("中文模板{0:F1}", value);      // 取字 + string.Format(InvariantCulture, ...)
```

包 `TranslationServer`，复用 Godot 自带的 CSV 导入、复数形式、运行中切语言与 `Control.auto_translate_mode` 的自动替换。`Fmt` 的格式说明符写在模板里（`{0:F1}`、`{0:0.####}`），译文要保留同样的占位符。

## 翻译表

每原型一份 CSV，彼此独立：

```
keys,en,ja,fr,de,es,ru,ko
"战斗中 · 第 {0:F1} 秒 · 我方存活 {1}/{2} ",,,,,,,
"盾卫",,,,,,,
```

首列即中文原文，其余七列留空，交给译者填。UTF-8 无 BOM、LF。键用双引号包住（内部有逗号，如 `定价 ${13}(, / .)`）。

翻译表在原型侧，每个原型一份 CSV，表头与格式同上。新起的那份可以只留表头（0 键，占位）。键数与表路径逐原型的读数记在 `docs/prototypes/<原型>/`。

## 转换范围

**进了表**：结构化 HUD、世界 `Label3D`、`Logic` 数据经变量上屏的名字。
**没进表**：`Say(...)` 调试反馈与 `*Debug()` 返回值。它们参与重放逐字比对（「断言三层」），翻译它会让读数随语言变。
**`Scripts/Logic/` 未改**：数据里的中文值原样保留，在文本节点那一处翻译。

## 判据测试

`src/GugaFramework/Tests/I18nRuleTests.cs`，纯 C#（不引 Godot 命名空间）。**七条判据，分两组。**

### 原型那组（四条）

`DiscoverProtos()` 扫 `src/Prototypes/*/i18n/`，一张表一套判据：

1. 每张表头是 `keys,en,ja,fr,de,es,ru,ko`。
2. 表里没有孤儿键——每个键都能在原型的 `.cs`（表现层 + 逻辑层）与 `.tscn` 里找到出处。
3. `Loc.T` / `Loc.Fmt` 传的中文键都在表里。
4. 上屏路径（`Scripts` 顶层 + `UI`）里直接赋给 `.Text` 的中文，都经过 `Loc` 或已在表里。

### 框架那组（三条）

扫 `src/GugaFramework/FrontEnd/` 与 `i18n/frontend.csv`：表头、孤儿键、漏键。表归框架自己，不隶属任何原型（「原型隔离」），`DiscoverProtos` 扫不到那张表。与原型那组同判据有两处差异：**孤儿键那侧要把 `+` 拼接的 Loc 键还原**（`FrontendPresentKeys` 并入 `LocKeys`）；**表存在**（框架这组判红）。

### 为什么不做「上屏裸中文一律判红」那种全扫描

`.Text = "中文"`（上屏）与 `GD.Print("中文")`（只进日志）在源码上长得一样，全扫必然把日志判成上屏。

### 判据抓不到的一类

**方法实参里的中文**。`MakeRowLabel("兵源（拖到格子上…）", 20)` 这种文本经函数参数进去，不在 `.Text =` 右值位，静态扫不到。已有原型在这条上漏掉过，逐条读数记在 `docs/prototypes/<原型>/`。

### 扫描器踩过的坑

- **`+` 拼接的长模板**：`ReconstructConcatenatedKey` 还原成单个键，否则判成孤儿。
- **无汉字的键**：`☹{0}`、`BOSS {0}` 这类也要进表，判「是否中文」时不能把 `Loc` 键过滤掉。
- **CSV 内嵌逗号**：读取器按带引号字段读。
- **注释**：仓库中文注释 15080 行，扫描前整段跳过。

## 字体：让上屏中文真的有字形

Godot 缺省字体不含汉字字形，中文上屏实测是**整行空白**。装上 fallback 链之后这一格才算补上。

- `src/Shared/ui/ProjectTheme.tres`：`SystemFont`，`font_names` 排 10 档（Microsoft YaHei → 微软雅黑 → Noto Sans SC → Noto Sans CJK SC → SimHei → SimSun → WenQuanYi Zen Hei → PingFang SC → Heiti SC → sans-serif），`allow_system_fallback = true`。
- `src/GugaFramework/I18n/FontSetup.cs`：`Install()` 装主题、`FontChainReadout()` 读字体链。四个原型 `_Ready()` 开头各加一行 `FontSetup.Install()`。

### 踩到的坑：改了设置不重载，不报任何错

`ThemeDB.Singleton.FallbackFont = ResourceLoader.Load<Theme>(ThemeResourcePath)?.DefaultFont;` 这句不能省。省掉的实测表现是：设置写进去了、上屏仍是缺省字体，而它**不报错**。

## 调试动词：切语言与查表变可验动作

`src/GugaFramework/I18n/LocaleVerbs.cs`，两发：`set_locale --locale <tag|system>`、`locale_probe [--key <键>]`。`locale_probe` 读回当前语言、`default_font` 名字链、已注册译文语言、给定键的取字结果。

### Godot 4.7.2 C# API 实测

- `TranslationServer.GetLoadedLocales()` 返回 `string[]`（**没有** `GetLoadedTranslations()`，那是文档里的旧名）。
- `OS.GetLocaleLanguage()` 不存在，要用 `OS.Singleton.GetLocaleLanguage()`；C# 类名是 `ThemeDB`（不是 `ThemeDb`）。

## `.translation` 注册

`src/Tools/RegisterTranslations.cs`，工具动词 `register-translations [--force]`。接法顺序：`godot --headless --path . --import` 打头 → 再 `dotnet run --project src/Tools -- register-translations`。只登记**至少有一格非空**的目标语言。编辑器里那份 CSV 会自动导入并自动登记，但**无头环境没有编辑器**，「表存在」与「引擎读得到」在命令行下会脱节。

### 踩到的坑：手写 `.translation` 二进制，引擎不认

曾自己写过一个编码器（「GDST」魔数 + 长度前缀），产物引擎直接拒：`ERROR: Unrecognized binary resource file: 'res://.../<原型>.en.translation'`。真格式是 ResourceLoader 的二进制资源（`RSRC` 头 + `OptimizedTranslation` + 哈希桶 + 字符串池）。编码器已删，`.translation` 全由引擎的 CSV 导入器产出。

### 踩到的坑：改写 `project.godot` 时留下重复键，整份文件被引擎跳过

症状是引擎侧 `ERROR: Couldn't load file 'project.godot', error code 43.`。难查在于**登记表看着改成功了**；崩的是引擎读文件那一步。三个独立成因症状一模一样：旧块没被吃掉；扫描起点差一行（真凶——`section` 指向段名行 `[internationalization]`，它本身以 `[` 开头，第一轮就 `break`，`keyIndex` 永远等于 -1，改成从 `section + 1` 起扫）；幂等判据方向反了（正确方向是「`entries` 里每一条都见于块内」）。

## 长度压力测试：长文撑破布局

往一张原型翻译表的 en 列填约 3 倍长的英文（占位符原样保留），重导入，切 `set_locale --locale en`，出图看布局撑不撑。**结论：撑破了。** 那一块面板的声明高在 `Arrange()` 里写死，长文下 `GetCombinedMinimumSize` 量到的高**明显超出声明高**；中文下同样这两行标签量到的和落在声明高之内——**中文布局本身是好的，破的是「按中文长度写死的面板高度」**。读数坑：`Control.Size` 与 `GetCombinedMinimumSize()` 在 `set_locale` 之后不立刻更新，要等一次布局。布局结论以**出图**为准。那一趟的声明高与实测高记在 `docs/prototypes/<原型>/`。
