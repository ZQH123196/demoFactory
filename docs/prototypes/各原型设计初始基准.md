## 表一：九大原型深度批评与风险表

| 游戏名称 | 核心循环设定 | 最尖锐的批评与开发毒点（致命风险） | 原型验证的唯一生死线 |
| :--- | :--- | :--- | :--- |
| **大胃袋** | 大地图探索 + 背包乱斗构筑 + 场馆不同胜利条件 | 数值维度爆炸，容易变成纯堆数值的垃圾时间。 | 能否仅用两套核心逻辑完全不同的卡组跑通两种比赛？ |
| **360度转一圈** | 随机审核案件 + 弹幕连麦 + 线索击溃防御 | 随机生成容易变得机械和弱智，丧失推理快感。 | 用代码随机生成出5个案件，测试能否产生破案惊喜感。 |
| **学习戒灵** | 角色扮演陪伴 + 心理学技能 + 高考Boss | “教玩家做事”与苦难数值化，体验悬浮甚至冒犯。 | 用一个“重度拖延症”AI测试，能否产生有反馈的系统。 |
| **游戏制作人** | 俯视角RPG探索 + 时代变迁彻底改变机制 | 跑图垃圾时间与“填表模拟器”的极致无聊。 | 跨入“网络时代”时，研发策略能否被彻底颠覆。 |
| **排兵布阵** | 布阵期网格摆位 + 战斗期**非网格**实时自动战斗（云顶之弈 / 9 Kings 式）+ 随时暂停 + 指挥官战术手牌 | 战术手牌设计平庸化，变成无聊的消磨战。 | 战术手牌能否与自走棋本身的站位逻辑产生化学反应。 |
| **无限领主** | 间接控制（发悬赏） + 主神空间肉鸽 | AI行为完全随机导致玩家绝对挫败感。 | 仅靠发悬赏给行为模式可预期的AI，能否策略通关。 |
| **巨兽竞技场** | 航行／狂欢双轨制：在活体巨兽背上经营小镇 → 停靠城镇开活体竞技场办赛 → 玩家用"上帝之手"物理干预角斗士对战 → 拔锚起航换城 | 严重的系统割裂，巨兽养成和战斗毫无关联。 | 巨兽升级器官，能否在竞技场内产生对应的Buff。 |
| **迷雾之都** | 密教模拟器式的资源黑盒 + 叙事 | UI交互灾难，没有底层引导的学习成本过高。 | 凭直觉（俺寻思）能否在无指引下合出新卡。 |
| **人生模拟器** | 纯文字版基于标签碰撞系统的无缝大世界 | 状态机逻辑黑洞与穷举法的死胡同。 | 建立NPC与互动行为，测试能否自然涌现故事。 |

## 表二：四大核心体验聚合表

| 核心体验类别 | 包含的原型 | 玩家在追求什么快感？ | 设计必须守住的底线 | 致命的设计误区 |
| :--- | :--- | :--- | :--- | :--- |
| **A. 构筑与验证** | 大胃袋、排兵布阵、无限领主 | “我真聪明”的解题感。 | 清晰的反馈链条，AI行为可预期。 | 流派同质化、战术卡牌沦为纯数值对撞。 |
| **B. 养成与羁绊** | 学习戒灵、游戏制作人、巨兽竞技场 | 投入心血后的回报与塑造成就。 | 成长的可视化与阶段性里程碑。 | 粗暴降维成“点加号”，缺乏叙事高潮。 |
| **C. 抽丝剥茧** | 360度转一圈、迷雾之都 | “原来如此”的顿悟感。 | 极度严谨的逻辑与符号暗示。 | 用“不讲道理的突变”代替“逻辑推理”。 |
| **D. 自由与涌现** | 人生模拟器 | “看看会发生什么”的恶作剧与沧桑感。 | 万物皆可交互，基于标签法则。 | 做成了死胡同极多的树状图。 |

## 表三：改进建议与批评采纳汇总表

| 游戏名称 | 核心痛点 / 原始思路的局限 | 采纳的改进方案与设计转型 |
| :--- | :--- | :--- |
| **大胃袋** | 缺乏长线动力，数值对撞。 | 大地图探索与“双规制（吃回本/大胃王）”并行。 |
| **360度转一圈** | 人工编剧产能跟不上。 | 构建随机文书与弹幕逻辑的生成器。 |
| **学习戒灵** | 说教味重，思路僵化。 | 根据AI人格特质进行针对性的心理学机制对抗。 |
| **游戏制作人** | 填表模拟器，时代感弱。 | 俯视角跑图探索，时代更迭彻底颠覆研发逻辑。 |
| **排兵布阵** | 抢夺注意力，拼手速。 | 引入“随时暂停”，手牌转为“规则改变/地形改变”。 |
| **无限领主** | 不可控AI导致全盘崩溃。 | 固化AI性格缺陷（如贪财），让玩家利用性格通关。（旧方案，用户已否决——现方向为复刻 Majesty 2） |
| **巨兽竞技场** | 巨兽与内部机制割裂。 | 航行／狂欢双轨制让经营与办赛共用同一批人与同一座场馆（同一段时间里没有空窗）；竞技场做成可插拔模块，模块组合直接改变比赛规则。 |
| **迷雾之都** | 黑盒交互体验极差。 | 利用视觉语法与概念隐喻，实现“渐进式披露”。 |
| **人生模拟器** | 文本无底洞，无涌现感。 | 摒弃文本穷举，建立标签碰撞的底层规则法则。 |

## 表四：九大原型系统架构与核心选型决策表

| 核心中台系统 | 强依赖的原型 | 核心职责 | 绝对不能踩的坑 | 架构选型与决策基准 |
| :--- | :--- | :--- | :--- | :--- |
| **全局时间/时钟** | 排兵布阵、游戏制作人、人生模拟器 | 接管所有时间推移，支持逻辑暂停。 | 依赖引擎原生帧率。 | 独立步进循环 (Standalone Tick)。 |
| **标签/事件总线** | 人生模拟器、迷雾之都、学习戒灵 | 让万物通过标签产生化学反应。 | 事件连环触发导致死锁。 | 纯代码强类型总线 (Typed Event Bus)。 |
| **指令排队/调度器** | 无限领主、排兵布阵、学习戒灵、**巨兽竞技场** | 所有改动塞进队列排队处理（不改底层数据这条 → AGENTS.md 「表现层只读」）。 | 越权直接执行。 | 命令模式 (Command Queue)。 |
| **剥离状态的AI** | 无限领主、排兵布阵、学习戒灵、**巨兽竞技场** | 只产生“意图”，绝对不直接修改世界。 |  | ~~大模型生成的纯代码决策树。~~ **落地形状（2026-09-26 实测改写）**：树的结构走 vendored Beehave（GDScript，不改写），决策落纯 C# 类并链进原型 Tests——技术账见 `docs/GugaFramework/行为树与跨语言共存.md`，约束在「行为树与跨语言共存」一组。 |
| **抽象容器/物资** | 迷雾之都、大胃袋、排兵布阵 | 将卡槽/背包统一为带规则黑盒。 | 玩家操作过快导致数据不同步。 | ~~被动响应式 UI (Passive View)。~~ **落地形状（2026-10-02 实测改写）**：R3 已从仓库整体移除，包引用、`addons/R3.Godot` 插件与两条 autoload 全清；现在事件与状态出口一律纯 C#（`EventBus` / `EventChannel` / 各模块有界账本），表现层只读（「表现层只读」、「C# 优先与总线」），不引响应式库。 |
| **数值计算/规则层** | 游戏制作人、巨兽竞技场、大胃袋 | 所有计算的最后一道海关。 | 结算优先级混乱（先乘后加）。 | 观察者模式劫持。 |
| **数据/随机生成** | 360度转一圈、大胃袋、无限领主 | 根据权重配置自动生成内容。 | 生成死局或ID配错。 | 极致配置化(JSONC)+快速失败(Fail Fast)。 |
| **网格/寻路中心** | 排兵布阵（**仅布阵期**）、游戏制作人、大胃袋、**巨兽竞技场** | 压扁为带通过成本的网格。 | 地形变动导致角色鬼畜卡墙。 | 统一寻路请求接口。 |
| **战斗裁决插件** | 所有原型 | 将战斗作为可拆卸的零件。 | 战斗逻辑污染核心躯干。 | 策略模式与黑盒化。 |
