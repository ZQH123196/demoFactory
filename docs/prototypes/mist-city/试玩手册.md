# 生死线试玩 —— 材料与判读表

> 这张 ticket 是 `ready-for-human`：agent 只能准备材料，判绿判红要三个真人跑出来。
> 本文只记事实、操作步骤与判读口径，不写契约（约束句在 AGENTS.md「契约索引」）。

## 生死线两条

判绿口径：三人中至少两人**同时**满足两条。

1. **发现**。每人结束前至少合出三张事先不知道存在的牌。
2. **决策**。进食缺口出现之后，有两人主动改变过绑定关系。

自动化 seam 盖不住第二条。测试能证明绑定关系变了，证明不了是人主动决定变的。

## 试玩之前：agent 已经验过什么

| 项 | 证据 |
|---|---|
| 逻辑层 147 条断言全绿 | `dotnet test src/Prototypes/MistCity/Tests`（2026-10-13） |
| 注入与真机逐字一致 | 同一条七步序列（叠出合成 / 叠出生产链 / 叠出住户 / 拿下来 / 丢牌）跑两遍：一遍 `debug drag_to` 注入，一遍真鼠标拖动；8 份快照逐字相同，两边都停在 tick=0（2026-10-13 实测） |
| 牌集够三个人各发现三种 | `CardSetTests.从开局那一手牌能试出至少三种新牌`（BFS 从开局牌序算，够 4 种） |
| 出图复核 | `.cache/stacklands-benchmark/t10-01…t10-07*.png`：拿起态、拖到另一张牌上、叠上去的层级、摞成塔、房屋住满与生人进度条、拖到弃牌堆、暂停顶栏 |

**没验过**：人会不会自己发现、会不会主动改绑定或调住房。这两件事只能靠试玩。

## 开试之前先看这一格：开局牌序只喂得饱两个人

三个人每步吃 3 份。开局牌序（4 柴 2 石 1 泉眼）穷举 35 个可达牌集，稳态产出的上限是 **2.361 份/步**（1 柴 + 1 石 + 2 夜露瓶）。两个人每步吃 2 份，所以两个人活下来之后城站得住；三个人吃不饱，第一轮结算（第 60 步 = 6 秒）至少死一个人。

实测数字（`Tests/BalanceTests.cs`，四条断言钉着）：

| 打法 | 这一轮吃进 | 缺口 | 死者 |
|---|---|---|---|
| 什么都不派 | 5 份 | 175 | h1, h2, h3 |
| 七张连成环全派 | 95 份 | 85 | h1, h2, h3 |
| 合成到穷举上限（1 柴 + 1 石 + 2 夜露瓶连成环） | 146 份 | 34 | h3 |

最后一行是能走到的最好结果：缺口全压在最后那个人头上（先到先得），另外两个吃饱。所以**试玩时死几个，直接量的是玩家在 6 秒里把产出凑到多高**——这一格本身就是要观察的东西，不要在开场替他们把路铺好。

数字口径是玩法决定（要不要调成三个人都活得下来），等用户拍板。四条断言会在改数值时变红，那时连同 `design.md` 待确认区那一条一起改。

## 操作步骤

### 1. 起一局（窗口模式，试玩必须开窗口）

```bash
# 项目根执行。窗口模式用 --window；--godot 只认等号那一支。
dotnet run --project src/Tools -- game start res://src/Prototypes/MistCity/Scenes/Main.tscn --window --port 7777
```

### 2. 录屏

三种都行，任选一种：

| 办法 | 命令 | 适合 |
|---|---|---|
| 系统录屏 | OBS / 录屏工具，录整个窗口 | 最省事，录像带鼠标轨迹 |
| 引擎出帧 | 直调引擎可执行文件，`--write-movie <绝对路径>.avi --fixed-fps 60` 排在 `--` **之前**，`--` 之后只留 `--debug-bridge-port` | agent 能直接读帧；帧数 = 游戏秒 × fps |
| 桥侧出图 | `dotnet run --project src/Tools -- debug screenshot --path <绝对路径> --port 7777` | 只要几张关键帧 |

**引擎选项不能写在 `game start` 的 `--` 后面**（2026-10-13 实测）：那条命令自己会先吐一个 `--`，
写在它后面的 `--write-movie` 会被当成用户参数，引擎根本没收到 —— 录屏一个字都没记，
而报出来的是「一切正常」。要录屏就走上面第二行那条直调引擎的路。

录像落 `.cache/` 下，不进版本库。收尾要用**引擎自己退出**（`GetTree().Quit()`）；
`game stop` 是杀进程，Movie Maker 的收尾那一步不跑，AVI 一个字节都落不下来。

### 3. 规则怎么说（只说规则，不说配方）

照下面这段念，**不要**补充「什么东西能合」「合出来有什么用」：

> 桌上这些是牌。按住一张，拖到另一张上，放手 —— 两张之间会发生一件事：
> 能拼出一张新牌就拼出来，拼不出来就变成一条产线（被压的那张开始按自己的间隔出食物）。
> 压到房屋牌上是住进去，那间房住满两个人之后，每 60 步多一个人。
> 拖到空白处是把它从产线上拿下来，不损失材料；拖到画面左下角的弃牌堆是丢掉，拿不回来。
> 每 60 步结算一次进食，在世的人每人每步要吃一份。桌上没有食物的那些份会记成欠账，
> 结算那一刻还欠着的人会死。牌面上写着每步多少步出一次、出过多少。
> 每轮能保留几张牌顶栏写着，超出的那几张在结算那一刻会被丢掉。
> 玩到在世的人都没了就结束。

第一版那句「没了的人不会回来」**已作废**：房屋住满 2 人之后每隔 60 步生一个人，
死了的人不会回来，但人口能自己长回来。这两句不要混着说 —— 说「没了的人不会回来」
会让试玩者放弃合成房屋牌，而那条路正是本轮要看的。

### 4. 同一份开局

三个试玩者用**同一个种子**（默认 `20260930`），牌序固定。差异来自人不来自内容。

要换种子重开：`debug eval --code "Main.StartNewRun(12345)" --port 7777`。
中途重开要记得跟下一位说「这是重开」。

### 5. 不要做的事

- 不提示配方、不说「试试这两张」。
- 不在玩家卡住时解释规则（口述阶段再问「你怎么发现的」）。
- 不在他主动问「这样对不对」时回答，先记下他问了什么。

## 结束后：逐人口述

对每个人问同样三个问题（**先记他说的话，再问下一个**）：

1. 你是怎么发现那条配方的？
2. 你第一次觉得「食物不够了」是在什么时候？
3. 你后来改过产线或住房吗？为什么？

口述里出现「试出来」「试了几次」「瞎试」而不是「看懂」「看名字就知道」，**发现那条算成立**。

## 判读表（一人一行，填完再判）

| 编号 | 合出几张事先不知道存在的牌 | 口述里有没有「试出来」 | 缺口出现后有没有改绑定 | 缺口出现后有没有主动调整住房 | 第一次改绑定在第几步 | 结论 |
|---|---|---|---|---|---|---|
| P1 | | | | | | |
| P2 | | | | | | |
| P3 | | | | | | |

「第一次改绑定在第几步」看录像数，不看自述 —— 这一格是用来分辨「一开始就规划」与「被逼的」。

「有没有主动调整住房」这一列是加的观测：把一张牌从满员的房屋上拿下来、
或把人往空位上补，都算这一列。生死线那两条一个字没动，加一列不改变判绿口径。

## 判绿 / 判红

- **判绿**：至少两人同时满足两条。
- **判红**：写清是哪一条不成立 —— 发现不成立还是决策不成立。
  这两条指向完全不同的下一步，不许合成一句「循环不成立」。
- **牌集不够导致的判红**，要跟「循环不成立」分开写。
  判据：三个人里有人**试了很多次但牌集里根本没有那条路**，那一条是牌集的问题。

## 收尾

试玩完按**端口属主 PID** 停掉那一局，不留进程：

```bash
dotnet run --project src/Tools -- game stop --port 7777
dotnet run --project src/Tools -- game list     # 复认无残留
```

结论写进 `docs/prototypes/mist-city/design.md` 的「生死线」栏：把「待验」改成「判绿」或「判红」，
并附上三人分别的情况。
