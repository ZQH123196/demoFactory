# 巨兽竞技场（BeastArena）

一句话定位（长期愿景）：**在会游历的活体巨兽背上经营小镇，用那座需要喂养的活体竞技场办赛收割**。

> **口径**：上面那句是长期愿景，不是现役 MVP 的验证载体。切片 1 验的是**「背上小镇的经营产出，能不能真的改变大地图防守战的胜负」** → 见 `design.md`「灰盒验证结论」。

- **代码**：`src/Prototypes/BeastArena/`。`Scripts/Logic` 26 份、`Models` 88 件、`Tools/`（含 `Rigs/`）与其余子目录齐备。
- **参照物**：巨兽方向《漂泊牧歌》《同舟共济》《DuneCrawl》；战斗与法术方向《地下城守护者》《王权2：幻想王国》。

- 上一轮开出的三条待裁项（暴食态累计喂食、荒漠态阈值、洞穴清剿的「清完」口径）已在 `design.md`「10.2 垂直切片」结案（用户确认）；当前无设计待裁项。最终构建的键鼠主线偶发失败记在 `acceptance.md` 第 9、11 节。

长期愿景里仍保留的两条（**第 2 条本期不做，第 1 条的载体已换**，见 `design.md`「灰盒验证结论」）：

1. **一条可归因的经营→战斗链**：喂食投入 → 竞技场饥饿度 → 本场停掉哪几个模块 → 胜负翻转。"饿"直接改规则，不改收益。
2. **可插拔竞技场模块**：模块组合本身就是非传递性的来源，对上"存在一档通吃"的老问题。

双轨制解决的是"没有空窗"，与"经营能不能改变胜负"是两个问题。
