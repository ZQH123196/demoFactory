# 排兵布阵（BattleArray）— 技能层验证记录

> 本文只留事实、机制与实测数字，约束句一律引契约名（「约束唯一出处」）。这里装技能层（`src/GugaFramework/Abilities/`）的实测结论；工位用法在 `技能层操作与验证.md`，已结案的确认记录在 `待确认区.md`，调研与最终口径在 `docs/research/技能系统/调研结论摘要.md`。逐格覆盖的最终口径是 24 拆行 21 绿 / 3 按设计不做，16 条技能那本账由 `skill-review.md` 逐格投影。

## 基建 — 技能层 H1

公共层 `src/GugaFramework/Abilities/` 纯 C# 零 `Godot.*`，随游戏运行；H1 与清单两套断言在原型 `Tests/` 里，靠 `BattleArray.Tests.csproj` 现成的源码链接 —— **本原型的玩法代码一行没动**。16 条技能的覆盖面＝GAS 功能面 ＋ 可调试性 D1~D8 ＋ 单挑场 16 条检查清单。

**接技能层没逼任何既有账重录**：全关档（`BattleWorld.Abilities = null`）下世界的演化与快照一个字节都不变。最初记着的那笔「`DebugSnapshot()` 每兵要续栏、逐字基线要重录、摆位对照 60 场要重跑」没有发生 —— 续栏做成了「接了技能才念 `[技能层]` 那一栏」；这是设计选择（全关档就是回归校验档），不是漏掉了。

### 基建第二轮 —— 级 2 引擎重放通了，H3 接进这一局一条突斩

随游戏运行的四件：公共层 `LiveReplaySession.cs`（级 1 与级 2 共用的那一份驱动器）、`BattleAbilities.cs`、`DuelRiftSetup.cs`（那一局的装配 ＋ 剧本词表 ＋ 重放快照段格式，三方共用一份）、`MainReplayBridge.cs`。H1 那轮欠的运行时三件在这一轮闭合，**D1~D8 可调试性全绿**。

H3 那一局挂一条突斩后的账：第 40 步按下、第 43 步落 20 血 ⇒ 蛮牛只需 12 刀平A，剑士第 **152 步**打死、剩 **66** 血；全关档是第 162 步、剩 53 血 ⇒ **早 10 步结束**，与 M4 那本手算账逐字吻合。

### 基建第三轮 —— 级 2 挂上行为树再跑一遍，六笔形状收口

两件装配口径都是踩出来的：

- **级 2 那个口落在 `GugaFramework/Replay/`，不在 `DebugBridge/`**：DebugBridge 被测试项目按表现层排除，放那儿级 1 就编不到，而两边必须共用同一份驱动器，否则「逐字相等」测的是两套实现像不像。
- **全场每兵一个空技能栏**（新账 N-18）：只给施法者装 `AbilitySet` 不够 —— 射程激活检查要读**目标**的坐标，「打一个没装技能栏的兵」当场抛。

**级 1（决策走纯 C# 直答）与级 2（决策走 GDScript 组合树 ＋ C# 叶子）逐格 sha256 6 格全等**，整份 dump 归一后同一个 `1eaa3489…`。「注入的路径与玩家的路径等价」（「桥只转发」）从推定变成实测；跨语言那条算术口径（场景档射程 ＋ 双方半径 vs `TroopCard.ReachAgainst`）在那 152 步里**没有一次末位分叉把判定翻边**。树确实在管事：`brain` 读数 `brains=2/2`、`treeDecisions` ＝ 兵数 × 步数，退回纯 C# 那条告警 0 次，`SCRIPT ERROR` 0。**反证各一次**：① 把树交出的意图一律改成站着 ⇒ 级 2 一发报**分歧 5**，第一条指到第 40 步、快照第 123 个字符；② 把词表里那道「不接目的地就当场抛」的校验摘掉 ⇒ 只红 A69 一条。两次定位成本都是 0 发额外调用。

**六笔「要动形状」的定稿**（一条尺子：能不动 A1 就不动、能不加列就不加、覆盖面一格都不许掉）：

| 账 | 定稿 |
|---|---|
| N-13 距离 | 归 S5 那段数据算 ＋ 宿主按边界重应用效果（公共层**不加**距离列） |
| N-14 角度 | 归 S5（顺带结掉单挑场那页的待确认项） |
| N-15 回充 | **不加列** —— `PeriodTicks` 就是它的表达 |
| N-16 排队释放 | **建**（`Ability.QueuedInput` 一列）—— 矩阵那一行只有一个载体，不建就掉格 |
| issue 08 同步抵挡 | 留在功能面 —— 落法是 S0 扣血前的第三处激活检查问 |

功能面仍是 16 条。**其中两笔推翻了上一轮报的倾向**：「先做 8 条」被否（四行矩阵各只有一个载体，砍一半就掉覆盖）；「宿主打 tag 表达距离」也被否（会破「tag 计数只有 S2 能写」那条归属）。

### 基建第四轮 —— 单挑场 H2 开机，第一批 8 条上台摆出台账

单挑场建起来了，16 条里的前 8 条在它上面各跑出一份**可手算的数值台账**，设计文档那四笔形状全部落成代码、每笔各指着一条断言编号。词表后来收成公共层那一份（`AbilityVerbs.cs`），两侧退成薄适配器。第二批（H2 六条 ＋ H3 两格）上来时**一列都没加**，只动了一处 record（新账 N-23）⇒ **级 1 与级 2 的逐字基线一个字都没重录**（N-19 那笔修法的红利第一次被验证：加一列不再逼重录）。

**N-22 是同形缺陷**：带延迟的落地（`rider.joust` 第二段）不过 `CancelMatchingTags` 的登记口，**同一条数据在两条执行路径上给出两种结果**。修法是两处收进同一个 `QueueCancels`；反证 ＝ 把 `Settle` 那处调用关掉，只红 A63 一条。**G2 那条通用性要求第一次有机器检查（A50）**：拿断言去搜场子源码，`warrior.` / `tank.` / `archer.` / `rider.` / `fx.` / `status.` / `"hp"` / `"rage"` 一处都搜不到 —— 加一条技能不改场子，不再靠人眼审；清单本体另由 A54 逐字扫。

**P4 那一轮买的东西大半不在功能上**：GAS 表里最后一格「没做」（GameplayCue）改口成绿，代价几乎全花在「只有出图与实跑才看得见」的那六件事上；三份分工＝机制进公共层 `AbilityCues.cs`、内容进本原型 `SkillCueSpec.cs`、上屏进 `SkillCues.cs`（A73 扫它有没有碰注入动词 —— 「表现层只读」第一次在表现层有机器边界）。

**纯逻辑测试一条都没抓到的六件**：

1. HUD 底部三行字互相压住（技能栏在满阵下换七行）⇒ 改用 `VBoxContainer` 并整栏挪到右边。
2. `挂着 0 轨` 是假读数（那数其实是「还没播出去的槽」）⇒ 改名 `待播 n 轨`。
3. 换局漏挂 cue 件（cue 还指着上一局已释放的世界 ⇒ 画面上一个 cue 都没有、测试与日志全绿）⇒ 三件观测件收成一个入口 `RebuildOverlays`；收口时又踩到第二层：`Rebuild` 依赖上次存下的相机架，第一局调它会抛 ⇒ `_Ready` 抛异常、`_Process` 照跑、整局停在布阵期。
4. 合并计数恒 0 让「演 815」成虚数（「上次发过什么」存在了待播槽、一清就忘）⇒ 加一份活过 `Drain` 的记忆。
5. **自增益的靶子口径漂了**（新账 N-25）：`CastAbility|p01|tank.guard|e01` 把盾墙挂到了敌人身上 —— 自动战斗与剧本注入各判各的。宿主入口一处收敛，**带了目标就当场抛**、不静默改靶（A74 腿 ④）。
6. **`.godot` 脚本缓存过期**会让 vendored `.gd` 全部 Parse error（新 `.cs` 落地没重导入 ⇒ 240 帧喷 6946 条，而世界静默走纯 C# 退路、`SCRIPT ERROR` 是 0）⇒ `--headless --import` 一发即清。

**每兵种一条**（`AbilityOfTroopKind` 那张表，不是 if）。开关 `BATTLE_ARRAY_ABILITIES=1` 或 `--abilities`，**缺省关**：关着时世界一个字节都不碰技能层，于是全关档那本旧账与摆位／配比对照都不必重跑。工位形状与前摇对表的读数见 `skill-review.md` 与 `技能层操作与验证.md`。

## 第十一轮 —— N-28 落地：四条起手动作烘进模型

**起手动作允许演得比前摇久**，于是「前摇只有 0.2~0.3 秒、正好等长的动作肉眼读不出是什么招」有了不碰数值的解。四条 clip 时长 0.6~0.7 秒，键帧按绝对秒写、顶点那一帧正落在 commit 上；挂号表只有一份（`Scripts/Logic/SkillWindups.cs`），表现层与开发期体检单都读它。八件模型重导，无限领主那 17 件一件没动（它的登记表没引用新 clip）。

读数：栏 2 那四格从「不适用」变成 `+0.4 / +0.4 / +0.4 / +0.5`，另外 12 格照旧念「不适用」，0 红、退出码 0；`review` 8 模型 0 FAIL、模型体检单与挂号前那次跑 0 行差。**反证走的是真通路**：把 `windup_slam` 整条压到 0.1 秒 ⇒ 那一格红、退出码 1、A76 腿 ⑤ 跟着红；回退后 md5 复原。

**同日补：N-30 当场闭合** —— 台账件 `OneShotLedger.cs` ＋ 桥只读口 `windups` ＋ 断言 A78。读数一上线就抓到一条真缺陷：起手动作原先按渲染帧采样 `CastingOf`，桥一次喂 300 步时那 2~3 步的前摇落在两帧之间 ⇒「windup_slash 演 0 次」；改成订 `activate` 事件后注入一发突斩就读到「演 1(第 0 步)」，反证（演但不记账）读数归零。顺带第一次把平A 的「被吞」数出来（那一局 22 次请求吞了 20 次），但 headless 一次喂多步会让这个数虚高，N-27 的观感判决仍归真人 1x 局。

## 基建 — 技能层出口换成带字段的事件形状

取舍与被否方案记在 `docs/adr/0001-ability-event-outlet-is-typed-shapes.md`，这里只留实测数字。

- `AbilityEvents.cs` 一份名单 46 个形状，类型名即事件名（没有 `Kind` 枚举，也没有第二份要人工对齐的表）；层的 40 处 `Emit("...")` 全换掉，该目录下 `Emit("` 现在零命中。
- **留着的结构检查**：每个形状都要念得出名字与非空明细；构造参数里不许有默认值或可空位（`NullabilityInfoContext` 机器检查）；同一（名字, 明细形状）不许撞名；容量边界腿——2001 条进 2000 格 ⇒ `Dropped=1`、头行 `dropped=1 total=2001 kept=2000`。一次性逐字对照（46 条全绿，含七族分隔符差异）已随提交进历史、文件本身删掉：长期基线不锁文案，理由同「断言三层」那条「良性改动别全红」。
- **删掉的第二份实现**：原型侧五个解析函数全删，三个清单宿主的 `EventCount(kind, contains)` 删掉，数字格式化从四处收成一处。
- **因果链现在直读字段**：旧代码从 `damage` 那行抠字符串喂 `KilledById` 再进 `DebugSnapshot` 的 `why=`。抠的那 7 行没了，`why=` 由字段生成 —— **解析不出来不会红，只会把 `why=` 悄悄变空**，这条是本轮最值钱的修法。
- **宿主不再判相位**：那处比字符串的判断换成匹配 `AbilityCommitted`；扇形命中通过层的补记口发 `ShapeHitLanded` / `ShapeHitMissed`。「打空要读得出为什么空」原样保住（空集仍念 `hits=-`）。读数口只一份：`AbilityEventLog` 的 `Tail` / `Where<T>` / `Count<T>`，流改有界环形；桥动词 `ability_log` 改成与标准 `logs` 同形的三键 `dropped_count` / `total` / `lines`。

**真机出图复核的读数**：起 H3 演示档 → 自己打 16 秒 → `cue_readout_debug` 回「cue 演 47｜合并 360｜dropped=0｜待播 0 轨」，`windup_readout_debug` 回「一次性动作 演 23 次 · 被吞 50 · 模型没这条 0」。截图那一帧里两个兵都活着、头顶血条与一条前摇读条都在，底部那行「为什么」念的是「最近的活人是 e01「蛮牛」，隔 2.51 米（够得着的距离 2.98 米）｜为什么：在射程内、冷却剩 8 步」——「冷却剩 8 步」正是换了形状之后从字段直读出来的。图落在 `.cache/Runtime/`。

一处如实记下的观察（**不是本轮改出来的，也没下判语**）：`attack_melee 演 0 被吞 50` —— 平A 那格起手动作一次没演、全被吞，而 `模型没这条 0` 说明动作在模型里，所以吞它的是优先级那一档。

两条实操坑：MCP 的 `game_eval` 跑 GDScript 子集，而这些口是 C# 方法 ⇒ 修法走「小写转发入口」那个例外形态（五个只一行、只做转发的小写入口）；eval 里带缩进的 `for` 会把活局打进 `break`，**eval 只写平铺语句，别带缩进**。

## 基建 — 技能层公共层那三列

架构走读那一轮读公共层读出来的三处「接口上写着、实现里没做」，本轮一次收掉。断言 A79~A82。

- **归并键（N-6）第一次真兑现**：两个分支原先都按 `EffectId` 比，而设计页三处写的都是「同 `StackKey`」；实现收成一处 `MergesInto`，给了键的按键归、没给的按 Id 归。**实测零行为变化** —— 全仓现有内容没有任何两条定义共用同一把键，所以级 1 与级 2 的逐字基线一个字都没重录。
- **既有 200 多条断言为什么没抓住它**：那几格都只反复施加**同一条**效果，按 Id 归与按键归逐字相同；「两条不同定义共用一键」这一格全仓没有用例。A79 补的就是这一格（本轮唯一一条先红后绿的断言，其余三条钉的是已成立的口径）。
- **跨条归并带来的读数问题按 A80 钉住**：共用一键时身上那条实例记的是**第一次挂上那条**的 Id，所以快照那格 `charges=` 只跟着当家定义的 `IsChargeCarrier` 念一次；A60 那条分界不被归并改写。
- **两处无主冗余删掉，前后行为逐字相同**：条件列 `MagnitudeFor` 里看 `RequirementTags` 的那个 `if` 两臂同 `return`（真生效的是 S2 的 `TagsSatisfied`，口径写成 A82）；触发链 `ConsumeTriggers` 外层那道比字符串引用、几乎恒真，等于没筛（真生效的是内层那句「被触发的正好是造成事件那条 → 跳过」，A81 钉它）。
- **`StackKey` 的两重身份写进契约旁边**：契约写明「归并的实现只有一处 ＝ `MergesInto`」＋「这一列同时被 `IsChargeCarrier` 借作『层数可归并』的存在性标记」。16 条台账的钉子跟着扩（叠层 `A59 A60` → `A59 A60 A79 A80`，触发链 `A40` → `A40 A81`，条件列 `A46` → `A46 A82`）。本轮全是纯 C# 命题，按「测试与实测分工」没跑真机。

## 基建 — 「不在本原型手搓技能系统」那条界今天落在公共层

原先那条界立在排兵布阵这侧的 ticket 里（状态 `ready-for-human`）：这一期不含技能，不许在 C# 里手搓一套 cooldown / 施法 / buff，防的是将来拆的成本比当初不做还高。激活条件是「任何一个原型开始需要第二个技能」—— **已触发**：16 条技能、三个宿主、技能试验场都在了。

今天的样子：那套系统没长在原型的战斗逻辑里，落在公共层 `src/GugaFramework/Abilities/`；本原型的战斗逻辑只挂一个可关的 H3 技能层，全关档下世界的演化与快照一个字节都不变。界按原意兑现，账随之销掉。顺手改掉三处过期文本（`BattleWorld.cs` 的 M4 世界注释、`design.md` 2 节第 2 条、`docs/prototypes/各原型设计初始基准.md` 的技能那一行）—— 三处都改成指向公共层。技能系统的选型收口记在 `docs/research/技能系统/调研结论摘要.md`。
