# 排兵布阵（BattleArray）— 表现层记录

> 本文只留事实、机制与实测数字。约束句一律引契约名（「约束唯一出处」）。
> 这里装表现层（相机 / 画面 / HUD）各轮的实测记录；等确认的口径在 `待确认区.md`。

## 表现层 — 整场视角换成 9 Kings 那一档

**这一轮要解决的问题**（用户提出）：拿《9 Kings》的两张实机图当参照，排兵布阵的视角不如它好观察，
技能测试场景也一样要换。改的是相机，一个逻辑真值都没动。

**俯角不是挑的，是量出来的**。量法：地面方格（世界里各向同性的正方形）投影到屏幕上，
其像素二阶矩的 `std_y / std_x` 恰等于 `sin(俯角)`，与偏航无关（正交近似下地面→屏幕的线性映射
`M·Mᵗ = diag(1, sin²θ)`）。两幅参考图各分割出十余块地面方格反解，中位值 **28.4° 与 29.0°**
⇒ 取整 **30°**，正好落在像素等距的 2:1 菱形那一档。那发 numpy 脚本是临时件、跑完已删。

**四个杠杆，缺一不可**（旧 → 新，全在 `Scripts/Main.cs` 那组常量里）：

| 参数 | 旧 | 新 | 为什么这一档 |
|---|---|---|---|
| 俯角 `InitialPitch` | 52° | **30°** | 上面量出来的 |
| 偏航 `InitialYaw` | 0° | **45°** | 场地两条边对称斜开 ⇒ 我方/敌方分列左下与右上；0° 那一档实测出图里单挑场两个兵**叠成一个人** |
| 视场角 `CameraFov` | 75°（Godot 默认，从没设过） | **32°** | 低俯角下「平不平」由这一档决定：75° 时近处的兵是远处的三倍大，菱形场地被拉成鱼眼 |
| 距离 `InitialDistance` | 17 米 | **36 米** | 24×24 转 45° 之后屏幕上是 34 米宽的对角菱形，32° 视场角下 36 米刚好装下还留一圈余量 |

**连带的屏幕口径**（「相机单源」那条「相机一变，屏幕像素口径的东西要跟着换算」的现场版）：
屏幕尺寸 ∝ 世界尺寸 ÷ (距离 × tan(视场角/2))，所以名牌与血条的参考机位 `PlateReferenceDistance`
从 15 米换成 **34 米**（出图比了 40 与 28 两档之后取 34）。点选容差跟着同一档走，实算 1.42 米
（旧 1.32 米，格边 2 米 ⇒ 邻格不会互相抢点击）。距离上下限 8~70 → **9~80**。

**技能测试场景那一档**：`DuelCameraPitch` 42° → **30°**（与整场同一档，两档视角不一致会让人觉得换了个游戏），
按间距倒推的距离档 8~18 米 → **11~22 米**（32° 下等价换算）。45° 偏航把「一前一后」摊到屏幕斜对角上，
旧档那种「后面的兵被前面的挡住」在画面上直接消失了。

**新开一个机位覆盖口** `BATTLE_ARRAY_CAM`（`Scripts/MainCameraOverride.cs`，键值对
`fov=;pitch=;yaw=;dist=;focusz=;ref=;min=;max=;duelpitch=;dueldist=`）：这一轮扫档全走 `--write-movie`，
那条道上没有 eval 通道，没有这个口就是「改一次常量、重编一次」。运行时那一侧不重复造口，
仍走已有的 `CameraSetPose`。它只碰表现层，且旧口径可以用它原样复现。

**跑过的验证**：`dotnet test src/Prototypes/BattleArray/Tests` 通过 207 / 失败 0 / 跳过 2
（跳的还是 H3 宿主的 D6/D7，与本轮无关）；`dotnet format --verify-no-changes` 无改动；
出图三张（布阵期 / 战斗第 14.9 秒 / 单挑场第 7.4 秒）新旧并排落在 `.cache/Movie/compare_9kings.png`。

**没验的**：真人在窗口里拖中键改俯仰、滚轮缩放到 9 米与 80 米两端的手感，以及鼠标点格子的实际命中率 ——
这三条要 MCP 运行时通道（《AI 能力手册》「已验证能力」），本轮只做了离线出图那一半。
