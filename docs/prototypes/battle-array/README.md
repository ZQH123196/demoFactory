# 排兵布阵（BattleArray）

一句话定位：**布阵期在网格上摆兵，点一下自动打完一整场**——验证「摆位 + 兵种组合」这件事本身有没有决策价值。
英文代号取「布阵」的军事语本义 array（一名一动：既是「阵」也是「列阵」）。

- 代码：`src/Prototypes/BattleArray/`（自 `_Template/` 复制起步）
- 参照物：云顶之弈 / 《9 Kings》式自动战斗，**不是回合战棋**（详见 `docs/prototypes/各原型设计初始基准.md` 文末澄清）

## 当前状态

**M0~M8 全部完成 ＝ 灰盒阶段收口**：8 个模型全过体检单 ＋ **摆位对照测试判绿**（换摆位真的换结果：阵亡差 3.10 兵、20 局配对 16 局同向）＋ **八件上屏、兵种差异落到数据、一棵行为树配八份参数档**（30/30 个兵由树接管，挂树前后判定行逐字不变）＋ **布阵网格与随时暂停与结算 UI** ＋ **配比对照测试**（300 场）＋ **两条种族规则落到数据**（人族射程 ×1.1、兽人攻击 ×1.1 —— 只换对面那一族，同一份摆法胜率从 70% 掉到 15%，逻辑层零种族分支）。

两条设计结论并排放着：**摆位与配比各自都有因果力**（换摆位差 3.10 兵；换配比胜率差 45~100 个百分点），但**两个自由度各有一个近乎正解**（摆位＝弓手夹中间 95%；配比＝近战重锤对三组阵容全 100% 胜）⇒ 灰盒阶段据此收口，结论记作「配比有因果力，但存在一档通吃 ⇒ 买兵不用看对面」。另记一条事实：现在这套数值下**默认对阵我方会输**。

- 逻辑层：`Scripts/Logic/` 纯 C#；表现层：`BattleUnitViews.cs` 只做镜像、零兵种与种族分支，`BattleGridView.cs` 铺 15 格，`UI/BattleHud.cs` 兵源面板 ＋ 暂停读数 ＋ 结算面板；
- 单位 AI：`AI/`（Beehave 树宿主 ＋ 桥 ＋ 三条 C# 叶子），参数档在 `Scenes/Brains/*.tscn`（**射程两处真值由两道校验钉住**：离线逐字比 ＋ 运行时 `参数冲突` push_error）；
- 调试通道：**已接 DebugBridge**，要一整局带 `BATTLE_ARRAY_AUTO_START=1`。

**一局时长按短局定稿**：实测 20~31 秒打完，契约里只说时间 —— 上限 120 秒是兜底、到点判我方赢。

**下一步**：没有排好的下一包了 —— 要么用户确认「买兵要不要先看对面」那条，要么带着这块地基进**活人感测试**阶段。

## 验证通道与结论落笔处（约束句 → AGENTS.md「契约索引」；此处只留本原型的命令与产物去向）

- 纯 C# 逻辑行为 → `dotnet test src/Prototypes/BattleArray/Tests`（固定种子）；表现层绑定 → 真机实测 —— → 「测试与实测分工」
- 造型：每个 `.glb` 落地即出体检单 `dotnet run --project src/Tools -- review BattleArray .`，报告进 `model-review.md` —— →《模型与动画准则》「审阅工位」
- 技能：`dotnet run --project src/Tools -- skill BattleArray .` 出一页三栏（报告进 `skill-review.md`）
- 验证闭环 → 「收尾落盘」与「游戏开发的各阶段」；结论落哪一份：机制灰盒各包 → `灰盒阶段结论.md`；技能层各轮 → `技能层验证记录.md`；相机与画面各轮 → `表现层记录.md`；等确认事项 → `待确认区.md`
