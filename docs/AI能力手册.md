# AI 能力手册

> 本文只回答一件事：AI 能自主做到哪些验证动作。通道怎么开、命令原文、实测数字与按症状查的故障表在 `docs/验证操作手册.md`。本文不设立规则（「约束唯一出处」），只列能力与它们的入口。

## 两条通道

| 通道 | 入口 | 能做到什么 |
|---|---|---|
| 离线 | `dotnet test` / `src/Tools`，不开编辑器 | 纯逻辑断言、录一局批量重放、分歧定位到第几步、造型体检单、离线出整局画面 |
| DebugBridge（默认） | 游戏进程内 TCP 通道，`DEBUG_BRIDGE_PORT` 或 `--debug-bridge-port=` 指定端口 | 起一局、读全量状态快照、变速·暂停·单步、注入写路径、**合成输入**、读日志、视口截图 |

早先还有第三条 `godot-ai` MCP，已连同插件删除，四处在用能力全部被 DebugBridge 顶上（见 `docs/adr/0010-移除-godot-ai-mcp-改用调试桥输入合成.md`）。

## 输入合成（`InputInjector`）

真机输入链——玩家按键到逻辑层那一段——可被自动化。四条动词 `input_action` / `input_click` / `input_hover` / `input_read` 在公共层，参数与命令原文在《验证操作手册》「四条动词」。要点四条：

- **按下与抬起是两个动作**。只发按下不发抬起，第二次同 action 的按下不产生跳变。
- **`input_read` 不报 action 的按下态**，消费完即清，桥上读到的永远是 0。注入有没有生效要问世界自己（`snapshot_debug` 或 `eval`）。
- **输入事件入 Journal，它触发的写本来就在录**。词表在 `GugaFramework/Replay/SyntheticVerbs.cs` 一份，入录口是原型侧递进 `InputInjector.Vocabulary(this, RecordSyntheticInput)` 的委托。**重放端一律跳过这两条**（`SyntheticVerbs.Skip`）——重放端是纯 C#，无引擎无光标。⇒ 这一层只增可读性、不增断言能力。
- **`hover_pick` 的实现在原型侧**，不进公共那四条：那四条零游戏知识，而「拾取谁」是玩法语义。

## 输入链端到端断言

真机输入链整条链接起来断言的能力已经有了，判据八条全部取自世界自己的读数。无头模式即可跑完，实测建筑 7→8、金库 198→98、新座 `market2` 进快照。命令序列在《验证操作手册》「端到端断言」。

## 已验证能力

- **运行**：命令行起一局（无头或窗口）、headless 自启桥、离线出整局画面。
- **时间可控**：任意倍率、暂停、单步、推进到第 N 步；变速与暂停不改演化结果。
- **读真值**：全量状态快照、场景树、节点属性、UI 元素、日志（看 `dropped_count`）。
- **写与输入**：反射调任意 public 方法、进程内求值 C# 表达式、合成 InputMap action 与鼠标键与光标位置。
- **取证**：固定种子毫秒级断言、录一局重放比对、离线二分定位第一个分叉命令。
- **查证**：`GodotSharp.xml` 本地 grep 不联网；`--doctool` 导出 GDScript 侧类参考；`godot-docs` 稀疏检出 `.rst`。
- **编辑器侧**：`addons/godot_ai` 删除后本条不适用。场景由 `src/Tools` 生成、造型由 `Gen.cs` 产出。

## 边界 — 仍需用户的部分

- 「好不好玩」的主观判断与手感调参反馈。
- 美术 / 音频资产（原型阶段用灰盒与代码生成几何体替代）。
- **3D 拾取悬停只能在窗口模式验**。读出口是各原型的 `hover_pick` 动词；接入情况按各原型文档夹的现状为准。
- 合成 action 的按下态在桥上读不到，所以「注入是否生效」一律以世界自己的读数为准。
