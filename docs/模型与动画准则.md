# 模型与动画准则（跨原型标准）

> 触发原因见 `docs/prototypes/<原型>/`；约束句已上收为 AGENTS.md「造型与动画」一组；本文只留机制、参数与实测数字。

## 1. 什么才算模型

> 判据 → 「真模型」（不用引擎图元拼的造型）、「模型四件套」（合格模型装齐四样）。骨架在 Godot 侧是 `Skeleton3D`，在 glTF 里是 `skins` + joints 节点链。

### 四样各是什么

| 样 | 合格的样子 |
|---|---|
| 真实顶点数据 | 写进文件里，不是节点缩放现场拼的 |
| 骨架 | Godot 侧 `Skeleton3D`；glTF 里是 `skins` + joints 节点链 |
| 蒙皮 | 每顶点带骨索引与权重；刚性蒙皮合法 |
| 动作 clip | `AnimationPlayer` 能直接播的命名动作 |

四样少一样就不合格。静态资产（导成不带骨架的 `.glb`）按「允许 / 不允许」那一节处理。

### 怎么一眼识破"非模型的存在"

| 症状 | 说明 |
|---|---|
| `Models/` 空、`ext_resource` 计数为 0、部件全是 `BoxMesh`/`SphereMesh` | 那是节点树，不是模型 |
| 有 `Marker3D`/`Node3D` 层级但没有 `Skeleton3D` | 没有骨架，不可能有真动画 |

### 造型判词（用户原话）

> 我不需要非常完美，所以我不需要 Blender。但是我需要完整的正常步骤，所以我必须要有真正的模型和真正的动画。如果 godot 本身就能做，粗糙是无所谓的。

## 2. 允许 / 不允许

允许：造型粗糙；建模用脚本产出而产物是导出的模型文件；Godot 自己导出 `.glb`；刚性蒙皮；静态资产导成不带骨架的 `.glb`。

## 3. 标准管线（新原型照抄）

```
造型：原型 Tools/ 里的关节树源场景（j_ 前缀 = 关节契约）   ← 相当于美术的 .blend，不进游戏
  ↓  src/GugaFramework/Tools/glb/export_glb.gd（引擎内编译）
产物：src/Prototypes/<原型>/Models/<Name>.glb              ← 骨架 + 蒙皮 + 动作
  ↓  Godot 自动导入
游戏：GD.Load("res://.../Models/<Name>.glb") + GugaFramework/Animation/ModelAnimator
      原型只喂三个状态：走多快 / 出手了 / 死了
```

### 三条分工线

源 vs 产物 → 「标准管线」；造型 vs 玩法 → 「造型进模型」；动作 vs 状态 → 「动作在模型」。

## 5.1 重建口径：换一台机器怎么把模型再产出来

> 约束句 → 「资产可重跑」。

| 源头（提交进版本库） | 作用 |
|---|---|
| `Tools/Gen.cs` + `Uids.cs` | 造型与 uid 表 |
| `Tools/ExportModels.gd` | 导出登记表：源目录 / 产物目录 / 模型名 → 要烘的 clip |
| `src/GugaFramework/Tools/glb/export_glb.gd` + `clips_humanoid.gd` | 编译器与动作库 |
| Godot **4.7.2-stable mono** | `.glb` 的字节由导出器决定，换补丁版本不保证逐字节等 |

可再生产物：`Tools/Rigs/**/*.tscn`（`gen` 出）、`Models/*.glb`（导出器出）、`Models/*.glb.import`（引擎导入出）。实测：删净源场景与两份产物、只留那四件源头重跑，`.glb` **逐字节相同**（那一次的 md5 读数在 `docs/prototypes/<原型>/model-review.md`）。`.glb.import` 是唯一的例外——它提交进版本库：同一次重跑里它的 `[remap] uid` 换了一个（引擎首次导入随机发身份，→ 「伴随文件入库」），`.gitignore` 按目录挡 vendored 包（→ 「排除精确点名」）。

## 6. 审阅工位：为什么这一段值得固定（已实现）

**立意**：建模难固定，但**建模之后的审阅环节高度同质**——看的就是剪影、体量、动作节奏、锚点、占地。

## 7. 一张体检单，三栏

### 栏 1 · 十视图 ——「造型与剪影站不站得住」

前 / 右 / 后 / 左 + 四个 45° 斜角 + 正俯视 + 等距 45°，共 **10 张**，姿势档位 = 绑定姿势。方位表写死在 `review_capture.gd` 的 `VIEWS` 常量——公共层改一次 = 全原型旧图不可比。

| 细则 | 口径 |
|---|---|
| 绑定姿势的坑 | `AnimationPlayer.stop()` 不把骨骼放回绑定姿势 ⇒ 先 `play`/`seek` 过再取的是上一条 clip 的末姿势 |
| 机距 | 由模型自身世界 AABB 算出。Troll 高数米、BountyFlag 一米不到，共用定距相机会一个顶天一个占仨像素 |
| 机位调度 | 一台相机转多次，不用并行视口（并行视口共享环境资源，出图顺序与就绪时机都会变成变量） |

### 栏 2 · 动画胶卷 ——「动作的节奏对不对」

每条 clip 一条横向格带。采样时刻的约束句 → 「动画胶卷」栏。

| 细则 | 口径 |
|---|---|
| 格距 | 0.2 秒 = 逻辑 2 步，进公共层。胶卷第 N 格与逻辑行为流第 k 步直接互查 |
| 绝对秒 | 归一化相位会把尺子藏起来——0.62 秒的 run 与 3.2 秒的 idle 各取 8 格，摆一起会误判成一样快 |
| 每格独立定格 | `seek(秒, exact=true)` 逐格独立；`advance()` 累加会把上一格的误差传给下一格 |
| 格数封顶与升档 | 封顶 8，装不下才升档。阶梯 `0.2 / 0.4 / 0.8 / 1.6`，与 `src/Tools/Review.cs` 的 `StepLadder` 一致；格距印在每格下方 |
| 循环 / 非循环取样 | 循环取半开区间 [0, 长度)；非循环补一个结束端点（收势 / 倒地那一帧本身要看） |
| 机位 | 每组模型可声明方位与仰角（`ReviewContract.FilmAngles`）；缺省方位 135°、仰角 45°；四足巨兽用侧向 90° / 仰角 10°。产物名不变 `film/<clip>.png`，报告列出每组机位 |

### 栏 3 · 比例尺同框 ——「体量关系成不成」

按占地档分组：原型可声明若干组（`ReviewContract.ScaleGroups`，每组含组名、模型表、网格步长），组内一行、整组同一像素比例、脚下铺该组声明的方格网；分组口径是组内最宽 / 最窄占地比不超过约 10 倍。未声明组的原型仍走单行。一台侧向机位 + 一台俯视机位；声明组时产物 `scale_<组>_side.png` / `scale_<组>_top.png`，未声明组仍是 `scale_side.png` / `scale_top.png`。十视图各自取景到满幅，看不出弓手相对宫殿是不是太小；组间尺寸比不了图，读体检单数字。决策与取舍 → ADR 0019「体检单比例尺同框按占地档分组」。

工位机制（实测）：比例尺图空白或缺图时，报告汇总判「工位 FAIL」，退出码非零（单色检查排除底部字幕区）；跑前清掉输出根里不在送审清单的旧模型目录，保留 `.gdignore`、`facts.txt` 与本次送审目录；送审目录里没有 `.glb` 时在起引擎前报错退出；引擎超时未退时杀掉进程树并报错。

## 8. 三条固定项：光环境 / 叠层标记 / 就绪等待

| 固定项 | 口径 |
|---|---|
| 光环境 | 审阅台单独一档「中性棚」，不复用 `PreviewStage.cs` 那套地面色/环境色；中性灰背景、固定方向光角度、关 glow/SSAO、固定 tonemap。理由是可比：换天光就换造型 |
| 叠层标记 | ① 前脸箭头（产物前脸朝 −Z）② 头顶血条（清单第 ⑦ 条）③ 占地 AABB 地面投影线框，单出一张 `overlay.png`、不混进十视图 |
| 就绪等待 | 轮询 + 秒级超时上限 |

叠层 ② 的口径：**`Anchor` 不是空间位置而是数据容器**（`.x` = 血条宽度、`.y` = 名牌高度，单位米）。

## 9. 产物与留痕

```
.cache/Review/<原型>/facts.txt                ← 引擎写的数字，报告的唯一数据源
.cache/Review/<原型>/<模型>/contact.png       ← 一页总览（十视图 + 每条胶卷 + 叠层）
.cache/Review/<原型>/<模型>/views/*.png       ← 01_front … 10_iso
.cache/Review/<原型>/<模型>/film/<clip>.png   ← 每条 clip 一条胶卷
.cache/Review/<原型>/<模型>/overlay.png
.cache/Review/<原型>/scale_side.png / scale_top.png   ← 栏 3，原型级；声明 ScaleGroups 时按组出 scale_<组>_side.png / scale_<组>_top.png
docs/prototypes/<原型 kebab>/model-review.md            ← 体检单，提交进版本库
```

**图不提交进版本库，`model-review.md` 提交进版本库。** 像素可比性同机已证、跨机未证；能跨机比的是数字（顶点数、占地 AABB、每 clip 最大骨偏移、骨数）。

## 12. 这一段本身怎么算验收 + 落地结果

一条命令跑完，三栏产物齐、报告有 PASS/FAIL：17 个模型 246 张图 + 一份报告 **16 秒**；同种子重跑报告逐字全等；Troll（3.47 米）、BountyFlag（5.04 米、占地 2.72×1.81）、Ranger（1.87 米）都满幅不裁切。「换机器、换窗口尺寸，采样时刻表不变」只验了一半：时刻表由按秒定义的常量算出，与帧率无关。

### 四条待确认与确认结果

四条都已确认：① 图不提交、报告提交（9 节）；② 十视图用**绑定姿势**；③ 顶视取**正俯视 + 等距 45°**，落定 10 张（以上两条在 7 节 栏 1）；④ 格距**定死 0.2 秒（= 逻辑 2 步）**，升档走阶梯（7 节 栏 2）。

## 14. 实现时撞出来的引擎事实（全部实测）

1. **glTF 压根没有「循环」这个字段**——不是导出丢了，是无处可写（`Ranger.glb` 的 JSON 块里 `loop` 出现 **0 次**）。⇒ 采样时刻表由原型契约 `LoopClips` 声明循环；`ModelAnimator.PlayBase()` 把该 clip 的 `loop_mode` 设成 `Linear`（`LOOP_NONE` 下 walk 在 t=2.00 与起点差 **0.0000 米**）。
2. **`AnimationPlayer` 默认按真实帧自走**，`seek()` 之后那一帧的 delta 每次都不同。⇒ 定格前切 `player.callback_mode_process = AnimationMixer.ANIMATION_CALLBACK_MODE_PROCESS_MANUAL`（枚举常量名**不是** `ANIMATION_PROCESS_MANUAL`）。
3. **`AnimationPlayer.stop()` 只停止推进**，不把骨骼放回绑定姿势；clip 的 `"length"` 只是声明，实际时长由末键的时刻兜住。
4. **`Image.blit_rect` 要求源与目标同格式**，不同格式拼出来的是空图；拼盘画布要用 `cells[0].get_format()`。
5. **`DisplayServer.window_set_size` / `window_set_position` 在 Windows 上照预期工作**，不夹回屏内。
6. **按场景跑的退出码陷阱**：`quit()` 在 `extends Node3D` 的场景脚本里不存在（那是 `SceneTree` 的方法），脚本解析失败、进程仍退 0。

## 15. 造型线六步 —— 第五步「导入」是新加的（从零重跑实测）

六步的次序是定死的（→「造型线六步」），命令原文见 `src/GugaFramework/Tools/README.md`。

1. `gen <原型> .` —— 出源场景 `.tscn`；
2. `check <原型> .` —— 离线几何校验器，读 `.tscn`，不需要引擎；
3. `export_glb.gd --proto=<原型>` —— 导出 `.glb`；
4. `<godot> --headless --path . --import` —— 触发导入，生成 `.glb.import`；
5. `inspect_model.gd --models-dir=… --all --max-footprint=N` —— 模型校验器；
6. `review <原型> .` —— 体检单（窗口模式）。

**坑（代价是一次假 FAIL）**：`--script` 跑的无头进程不执行导入流水线，`.glb` 刚导出而 `.glb.import` 还不存在时第 5 步 `GD.Load` 直接 `FAIL <Name>.glb 加载失败`——这不是造型不合格，是资源没进过导入；解法是补一次第 4 步。

## 16. 模型体检单 — 资产层的三个观测口（落地）

**它把哪一步变便宜**：`.glb` 落地之后「造型对不对」从「开编辑器 + 跑起来 + 抓图」变成「一条命令出文件，agent 直接读图判定」；实测 17 个模型 **16 秒**、246 张 PNG，两次干净重跑 md5 逐字节全等。

## 17. 看图这一环到底抓到过什么（校验器全绿 ≠ 造型成立）

`review` 的 PASS 只判四件事（占地/野节点/缺 clip/骨骼有没有动），**不判「像不像、认不认得出是谁」**。实测逮到的九条全是数字全绿的：盾挂在垂下的手上落在大腿前｜人族弓手配色与兽人绿皮撞色（八件同框才看得出）⇒ **单件十视图看不出撞色与体量关系**。

## 18. 骑手这类「一个模型挂两副骨架」怎么过造型线（实测）

- **骨名撞了会静默串轨**：导出器用「骨名 → 序号」的字典给动作轨道寻骨，两边都叫 `root` 时不报错、后写的覆盖前面的。⇒ 坐骑骨带前缀（本项目用 `m_`，见 `src/Tools/QuadrupedRig.cs`）。
- **一座动作库套不上两副骨架**：直接套人形 walk ⇒ 骑手在马上蹬腿；砍掉人形腿轨道 ⇒ 坐骑站着滑行。做法是坐骑轨道自己写 ＋ 骑手轨道从人形库挑着搬（`lib = "mount"` 选库）。
- **骑乘姿态的位置在 rest、不在轨道**：`Humanoid.Rig(thighYaw/kneeYaw/legSpread/armYawL/armYawR)` 给绑定姿势摆跨坐；四条全默认 0。

## 19. 出图与装配这条通道抓到的引擎事实（实测，自《AI能力手册》归位）

### 出图抓到的四类表现层错（修法都已在码，形状留着好认）

1. **HUD 三行字互相压住**：根因是用绝对坐标给会变长的文本预留高度；那一栏交给 `VBoxContainer` 排版。
2. **换局漏挂观测件 = 静默什么都没有**：cue 件还指着上一局已释放的世界，而测试与日志全绿。
3. **合并计数恒 0 ⇒ 演的是虚数**：派发台取走待播槽即忘，每步把同一个身相当新账重报。

### `.godot` 脚本缓存过期 → vendored 的 `.gd` 全部 Parse error

新增 `.cs` 落地后没重导入就出片，`beehave/nodes/*.gd` 一起解析失败 ⇒ 行为树桥每次决策喷一条 `Nonexistent function 'tick_for_bridge'`，世界**静默走纯 C# 退路**，而 **`SCRIPT ERROR` 计数是 0**。三条口径：新增 `.cs` 后先一发 `--headless --import`；出片前先 `grep -c Exception`；「`SCRIPT ERROR` 0」不足以证明树在管事——要看 `brain` 那发的 `treeDecisions`。
