# 提交信息写法

> 判据在 `AGENTS.md`「通用开发规约」的「git 操作」那一节。本文件只记 50/72 规则的细节与示例。

## 50/72 规则

50/72 规则是一个被广泛采纳的提交信息排版惯例，目的是确保提交信息在终端、邮件、Git 工具等环境下都清晰可读。

核心规则：

| 部分 | 规则 | 说明 |
| :--- | :--- | :--- |
| 标题行（Subject） | 限制在 50 个字符以内 | 简洁概括改动，使用祈使语气，末尾通常不加句号 |
| 正文（Body） | 每行限制在 72 个字符左右 | 手动换行，提升长正文的阅读体验 |
| 空行分隔 | 标题行和正文之间必须有一个空行 | 许多 Git 工具依赖这个空行区分“主题”与“正文” |

标题行（Subject）格式：`<类型>(<作用域>): <描述>`

- 类型（Type）：必填，指明修改性质。
- 作用域（Scope）：可选，用圆括号包裹，指明修改范围或模块，如 `auth`、`payment`。
- 描述（Description）：必填，简短总结做了什么。
- `!`（感叹号）：可选，放在类型或作用域之后、冒号之前，表示破坏性变更。

常用提交类型：

| 类型 | 含义 | 对应 SemVer |
| :--- | :--- | :--- |
| `feat` | 新增功能 | MINOR |
| `fix` | 修复 Bug | PATCH |
| `docs` | 仅文档变更 | - |
| `style` | 代码格式调整（空格、分号等，不影响逻辑） | - |
| `refactor` | 代码重构（既非新功能，也非修复 Bug） | - |
| `perf` | 性能优化 | - |
| `test` | 增加或修改测试 | - |
| `chore` | 构建过程或辅助工具的变动 | - |

## 示例

```text
feat(auth)!: 添加用户登录校验

提交前校验邮箱格式，避免无效请求进入后端。
移除旧版 legacy_email 字段支持，统一使用 email 字段。

BREAKING CHANGE: 登录接口在邮箱格式非法时由返回 200 改为返回 400；
```

`feat(auth)!`：feat 是类型；auth 是作用域，表示修改范围是认证模块；! 表示破坏性变更。

## 说明

- 标题行 50 字符那个上限超过以后，在某些终端和工具中可能被截断。
- 72 字符这个宽度来自传统邮件和终端的显示习惯。
- 空行分隔没有时，Git 工具可能无法正确区分标题和正文。
