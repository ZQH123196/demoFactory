# 局结束时冻结时间轴

一局分出胜负的那一刻起，逻辑时间轴停住：**冻结**，不是暂停。

**冻结与暂停是两件事**：暂停是玩家按一下还能继续，冻结是这一局已经结束。
两者对推进的效果一样（一步都不走），真值分开放。

## Considered Options

- **局结束时只停推进循环、不冻时间轴**：三处原型本来就都有一层「本局结束了吗」的判断
  （继续推也没意义）。但那层判断管的是「这一帧还推不推」，时间本身还在走：
  调试读数里的「第几秒」在局结束后继续爬，而那一秒已经不属于任何一局。
- **局结束时把逻辑时钟直接设成暂停**：一个字段就够，不需要第二个真值。代价是玩家按暂停
  就能把已经结束的一局继续跑下去——结局被按掉。
- **真值一个字段，闸开在推进的那一处**：本轮选这个。
  `GameLogicBase.TimeFrozen` 是唯一的真值，冻结只在局结束时置上，没有反向口。
  闸开在推进公共件那一条路上（`WorldAssembly.FrozenProbe`，`GameLogicBase` 构造时
  把 `() => TimeFrozen` 递进去），三条推进的路都从那里过。

## Consequences

- **闸开在推进公共件而不是基类的推进口**，因为有的世界会重写 `Advance` 并直接调装配那一份。
  闸若开在基类那一处，那条路会绕过去：实测冻结之后 `Advance(10)` 仍回 `true`、步号照爬。
  把闸开在公共件上，绕不过去。收口这一步是用变异测试钉住的——拿掉闸，被冻住的那侧用例即红。
- **没有解冻口**：解冻不是「这一局还没结束」，是换了一局。换局走换世界，那条路上本来就是一个新对象。
- **冻结不设反向口，但暂停的接口原样留着**：玩家仍可暂停一局进行中的世界，那与结局无关。
- 局开始与局结束两个事件是这一层的接线口，冻结挂在局结束那一端订阅
  （→ 机制见 `docs/GugaFramework/前端.md`，推进那一侧的闸见 `docs/GugaFramework/世界装配.md`）。
- 三个宿主各有同族用例钉这一格；逐原型的读数记在 `docs/prototypes/<原型>/框架迁移记录.md`。
