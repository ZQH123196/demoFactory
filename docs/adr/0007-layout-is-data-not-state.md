# 区域蓝图是数据不是状态：捕获只读、放置参数自包含

布局（Layout）= 名字 + 成员列表（蓝图 id、相对偏移、自身方向）；网格侧偏移是整数格，自由侧是
量化坐标。**捕获（Capture）是只读查询**：给一个矩形区域，返回序列化的布局文本，call 类、不入录、
不改世界。**放置（PlaceLayout）的动词 args 自带完整布局文本** + 锚点 + 整体方向——Journal 一条
即可逐字重放，重放端零额外状态。布局文本的旋转 / 镜像是模块静态纯函数（数据进数据出，离线可测）。

## Considered Options

- **模块内注册表**（id → 布局）：捕获变成写动词、注册表进检查点快照、重放端必须同序重跑捕获——
  多一块要守的状态，多一类分叉源。
- **原型侧注册表**：N 个原型各存一份，动词 args 引用原型状态，重放不再自包含；
  布局文本格式随原型漂移。

## Consequences

- 重放与检查点快照零新增状态。
- 布局文本可手工编辑、可被外部工具处理、可跨原型存档（纯数据）。
- 代价：Journal args 变长——大布局一条长文本；重放端逐字比对要盖住它（L3 口径下天然盖住）。
- 整布局 Move 留待未来（拆单件 Move 或拆 + 重放）。
- 空区域捕获不算错（回 0 成员文本）；放置 0 成员布局是脚本作者错误，当场抛
  （两类失败的分界见 spec.md 2 节 D7）。
