# 技能层需要不止一个真世界来压测，理由不是省代码

一个新世界接上一条公共能力时，第一问不该是「省下多少代码」。
一个世界就有一份自己的实现：移动、索敌、血量结算三件若不在公共层里，实现那个宿主接口一行也省不下来。

真正的理由是：**一条公共层只跑在一个真世界上，就没法证明它没被那一个绑住。**
只被一方用着的公共层证明不了自己没跟那一方长在一起。这条学费本仓交过一次——
取证器里写死了一个原型的名字，第二个世界只好另抄一份重放器。
「接新原型不必改公共层」这条验收，在一个真世界里永远验不到。

## Considered Options

- **完全不接**：当期最省，但这一层继续只有一个真世界用它，「接新原型不动公共层」在技能层永远验不到。
- **当期就把第一个世界的战斗世界上收进 `src/GugaFramework/Combat/`**：那是 `AGENTS.md` 0 节产出②该做的事，
  但要动第二个世界的代码，与当期要验的那句命题无关，排到判绿之后。

## Consequences

- 配置里事件容量那一格要显式给，缺省值会构造即抛——公共层不替调用方选这一格（见 ADR 0001）。
- 新世界自己写的那部分按日后可上收的形状写：纯 C#、零 Godot 依赖、参数走契约（「逻辑层纯 C#」）。
- 上收要不要连第二个世界一起改：公共层在真实原型里不断变厚（`AGENTS.md` 0.3 节），上收即改公共层与第二个世界。
  「接新原型不许改公共层」那条（原文是旧条 4.15，已按用户裁决废止），这条出入随之消解。
- 新世界需要的动作 clip 不在公共层白名单里时，按「公共层在真实原型里不断变厚」走白名单上收，
  不在本世界私造一套动作。

## 接口那一半可能根本没有落点

实施时核了三处，本文「实现那个宿主接口」那一档在公共层里可能没有落点：

1. `AbilityStepper` 把 `IAbilityHost _host` 存下来（`AbilityStepper.cs:83,98`），
   只在 `Branch()` / `Restore()` 里转发（`:1384`），**从不调用**。
2. 整个 `src/GugaFramework/Abilities/` 里没有任何一处 `host.` / `_host.` 的方法调用。
3. 层唯一的扩展点 `CalcFn(CalcInput)`（`AbilityCalc.cs:73`）而入参 `CalcInput` 是个只装
   字典的 `readonly struct`（`:13`），**函数体够不着 host**。

仓里现存的 `IAbilityHost` 实现全在 `Tests/` 下。**所以「实现那个接口」可能解开不了任何绑定**：
它是构造函数强制要的一档（不实现编译不过），但填进去的那几个方法没人调。
层真正被一个世界绑住的往往是**内容那一半**——兵种表与公式，而不是接口。
新世界照契约实现那几个方法（不接编译不过），但当回事的是内容那一半：表与公式自己写，不抄第一个世界。

本文「理由不是省代码」那条立论成立在内容那一半上，不在接口那一半上。
