# 建造是一个模块 + 两条放置规则，不是两套建造系统

网格建造（Grid/Tile-based）与自由建造（Free Placement）共用一个建造模块（`src/GugaFramework/Construction/`）：
建筑册、占用、建造过程、损毁、事件出口、动词表、快照段全是一份；seam 切在**放置规则**上——
只答「这个候选点能不能放、实际落在哪」。两个 adapter（网格放置、自由放置），宿主构造时择一注入，
不做运行时切换。连带两条口径：**裁决原因在框架内封闭**（OutOfBounds / Occupied / TooClose /
NotBuildable / UnknownBlueprint / UnknownId / InvalidState），经济类原因不进模块——模块不认识钱；
**工期 0 无特判**——「等同即时建」指外部不可区分（Placed 与 Completed 在同一次 Commit 调用里连发），
不是代码里有 `if (工期==0)` 分支。设计定稿全文在 `.scratch/construction/spec.md`（用户确认）。

## Considered Options

- **两套并行建造系统**：共享骨架（册、事件、快照、重放接线、损毁链）写两遍，每修一个 bug 修两处——
  删除测试不过。各宿主各自的放置实现里共有的正是这份骨架（自由落建、格子摆位、建造位三种形态），
  差异只有合法性判定那一个点。
- **网格当自由的特判**（吸附到格点）：丢掉 D4 整数变换、格占用表与网格 gizmo 的参数源，
  「受影响格名单」给不出来。
- **自由当网格的特判**（格长趋零）：量化与枚举退化，同样给不出格名单；浮点格不是格。

## Consequences

- 混合放置模式（一个世界同时两条规则）留待未来；真到那天是规则组合器的事，seam 不翻。
- 盒形占地（OBB + 分离轴判定）留待未来：Footprint 家族加 Box 变体 + 裁决加一个分支，接口不翻。
- Reason 封闭为有限枚举铺路——可逐字序列化进 inject 的 `out reason`，「那两侧要原因，得先让世界回话」的前提在建造模块这侧成立。
- 六角格是这个 seam 的试金石：新写一个 adapter（axial 吸附、六向方向整数、格名单照给），
  模块核心、动词表、事件形状、快照段一个字不改。
