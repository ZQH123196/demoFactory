# 玩家命令与注入走同一条 sink

玩家在界面上做的每一个玩法命令，与调试桥的 `inject` 动词，**走同一个写入口**。
两处时间旋钮（暂停、单步、变速）除外，见 `0015`。

## Considered Options

- **玩家命令与 `inject` 各走各的**（现状的两种形态之一）：玩家点左键走 `Write`，
  调试注入走 `Recorder.Inject`，两条最终汇到同一处——这条路已经有两个消费者证明可行
  （无限领主与排兵布阵）。不成立。
- **玩家的每个动作都下沉成逻辑层的一等状态**（意图队列，AI 意图同形）：
  更彻底，行为树那条已经修成那个形状。代价是要重划表现层与世界的边界——
  现在玩家的位置就是表现层触发 `Write`，把意图下沉意味着 `Main.cs` 里一大片搬进逻辑世界。
  收益在只有一个消费者时看不出来。等有第二个消费者（触屏、手柄）时再说。
- **玩家命令一律走 `Write`，与 `inject` 同一条 sink**：本轮选这个。

## Consequences

- 巨兽竞技场要改：玩家命令从直调 `_world` 改成走它的 `ArenaSetup` 同一个 sink。
- 三个原型的 `Write` 名字可能不同（无限领主 `Main.cs:120`、排兵布阵
  `MainReplayBridge.cs:211`），但**同一条 sink** 是口径，不是同一个方法名。
- 输入缓冲留在表现层、不进 Journal（见 `docs/GugaFramework/输入层.md`）——
  本 ADR 只管命令的落点，不管输入本身的采集。

## 支撑这条 sink 的论据

- 巨兽竞技场**没有任何玩家玩法命令**。玩家侧只碰四个时间旋钮，现已收编进
  `PollTimeKnobs()`（`BeastArena/Main.cs:284-302`，每帧读一次「刚按下」，由 `_Process` 调用），
  其余命令全部走调试桥 `inject`，而 inject 本来就过同一个 sink。
- 那四个时间旋钮**不进 Journal**（见 `0015`），本 ADR 开篇也已明写「两处时间旋钮除外」。

**所以「重放端发不出也跳不掉」不是缺陷，是 `0015` 的直接后果。**
本 ADR **不补任何时间旋钮动词**——补了就是顶自己的牛。

**论据**：巨兽竞技场玩家那侧**复制了一份调试桥已有的逻辑**。
复制只发生在**单步**那一处：玩家侧（`Main.cs:294-298`）写
`_world.Advance(1)` 加 `_deck.Sync(_world, AnimGameSpeed)`；调试桥的 `step` 动词
（`Main.cs:437` → `StepDebug()`，`Main.cs:314-319`）写的是逐字同形的两行。
同一件事两处代码，那才是要收的那条。

**这一条已收编**：玩家侧那一档改为调桥上同一个 `StepDebug()`，
两条触发（玩家按键、调试桥 `step` 动词）汇进一个方法，两份代码变一份。
判据在 `src/GugaFramework/Tests/InputLayerTests.cs`
「巨兽的单步_玩家按键调的是桥上那个方法_不自己再抄一份」——
它断的是 `PollTimeKnobs` 的方法体里不再出现 `_world.Advance(` 与 `_deck.Sync(`。

另两处查过，不是复制，本 ADR 不主张收：

- **变速不复制** —— 玩家侧（`Main.cs:300-301`）调的就是桥上 `speed` 动词
  （`Main.cs:436`）同一个 `SetSpeed`，本来就是一条路。
- **暂停桥上没有对应动词** —— 桥上词表（`Main.cs:435-450`）里没有 `pause`，
  玩家侧（`Main.cs:288-292`）那两行没有第二处副本，那是「只有一处」，不是「两处」。

玩家侧读键走逐帧读而不是逐事件读（见 `docs/GugaFramework/输入层.md`）。
