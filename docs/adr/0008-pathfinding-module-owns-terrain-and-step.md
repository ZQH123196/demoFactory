# 寻路层持有地形与走位，单一入口是两个写入口

寻路层是 GugaFramework 的公共 module，持有寻路网格与一份 agent 投影（id → 位置/半径/朝向），
并且是**唯一决定「单位下一步站哪」的东西**。它只有两个写入口——改地形、落位移；其余全是只读查询与事件。
seam 定在「怎么求一条路」（点到点 / 流场两条 adapter），判据照建造层那句：生命周期内完备，seam 外零泄漏。
「这一步允不允许动」的**移动激活检查**排在寻路层上游，归技能层，于是调用顺序（先问激活检查，再算站哪）成了契约。

## Considered Options

- **只做查询库**（`Find(grid, from, to) → 折线`，单位与推位归宿主）：查询统一了、位移没统一，
  每个世界仍会各写一份跟随与分离，第三个世界时就是三套。名不副实。
- **直接做群体模拟器**（再加 N 个单位同时走、死锁裁决）：现有世界的实测并发峰值在 30~50 这个量级
  （有的世界有硬上限，有的不设常数上限），流场与避障解决的是还没到的问题。
- **模块只管地形不管 agent**：那「谁持有坐标」这条边界就没有守卫，
  各宿主仍能在网格之外自己算下一站，单一入口立刻漏。

## Consequences

- 现有六种阻挡机制必须先分类再收编，因为它们**不是同一种东西**：地形阻挡（设施位占用、建造格占用）
  进静态网格；减速陷阱进**动态代价层**（乘性，不是阻挡）；相向阻挡（身体半径推开、战斗员拦停）归**避让**，
  **不进网格**——网格是采样场，成对相对查询是解析量，翻译过去是错位；竞技场边界钳位收成网格边界。
- 建造的最小距离半径（宿主世界里的放置半径常量）归建造模块，**不迁进寻路层**。
- 各世界自己写的跟随与分离（下一站算给、退让）随之退休（→ 守卫测试那份豁免账：`NavSourceGuard.Exemptions`，
  各期的名单在 `docs/GugaFramework/寻路层.md`「豁免名单」那几节）。
- 技能层已有的 `MoveBlocked`（`AbilityStepper` 发出的那个事件）是激活检查不是寻路读数；两层各答一个问题，不合并。
- 「寻路只有寻路层一个入口」这条契约已登记进「契约索引」，名字是「寻路单入口」。
  判据只写在「契约索引」那一处，这里不复述。
