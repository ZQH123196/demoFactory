# 技能层的出口是带字段的事件形状，事件类型就是名单

技能层（`src/GugaFramework/Abilities`）对外的唯一输出面原本是一条四元组事件
`(Tick, Kind, Subject, Detail)`，其中 `Detail` 是给人看的自由文本：谁打的、半径几米、
第几步落地、为什么落空都要靠调用方解析字符串才拿得到，于是同一份知识被抄成 4 处解析函数、
3 份读数口与 26 处文本断言。我们把它改成**一个 kind 一个 sealed record 形状**（46 个），
**形状的类型名就是事件名单**——不再有 `Kind` 枚举与形状清单这两份要对齐的账；
形状里**不留可选位**，凡是旧文本「有的带尾巴、有的不带」的档位（`til=` / `target=-` /
`queued=1` / ` move=` / `x1 instant`）各自成一类。理由在设计文档里早就写了：
A4「真值只有一处，输出只有事件」与 423 行「参数随事件带」——这次是补实现，不是改契约。

## Considered Options

- **字典式 payload**（`Kind` + `IReadOnlyDictionary`）：调用方必须背「哪个 kind 用哪几个键」，
  等于把文本形态换个包装留在接口上，否。
- **共享形状 + 可选字段**（把形状数压到 14~19）：可选位就是「先知道名字才知道读哪个字段」，
  与「不留可选位」冲突；压数字这个目标本身不值得，否。
- **保留 `enum Kind` 37 名 + 一 kind 一形状**：两份名单必须靠一条结构测试互相同步——
  那是在为一个本可以不存在的漂移装护栏，否。
- **把二维坐标请进逻辑层**，让层自己枚举单位算扇形命中：顶设计文档 N-13/N-14
  「判定在层、跨边界由宿主发动词、层不持活对象」，且多一列坐标要问进不进快照——
  进了就动 `[技能层]` 段结构（A53/N-19）。改成层开补记口 `RecordShape`：名字与形状仍归公共层，
  标量与活对象枚举归宿主，否掉了这条改法。
- **宿主继续往 `_sets.Events` 里塞自己的事件**（旧 `slam_shape` 的写法）：逻辑流的形状由被牵引的
  一侧决定就漂了，所以事件流是**封闭的**——只有公共层能发。

## Consequences

- 加一类事件要动公共层，这是刻意的：一份表 + 各消费者只做映射，与 `AbilityVerbs` 走通的那条同形。
- `pending` / `modifier` / `activate` / `reject` / `queue_drain` / `slam_shape` / `apply_effect`
  这七族各有两条形状，所以「按事件名数几条」要改成按形状数（`Count<T>()`）。
- 事件流改成有界环形并报 `dropped`，读数口只一份（`Tail` / `TailText` / `Where<T>` / `Count<T>`）；
  容量由 `AbilityLayerConfig.EventCapacity` 递进来，公共层不替宿主选这一格，缺了当场抛。
- 数字格式化收成一处 `AbilityNumbers`，事件行与快照同源。
- 事件行只供人读：真值在字段与检查点快照里，逐字基线不锁事件行文案（一次性 46 条逐字对照已跑完并删除，
  证据留在 git 历史 `f4a2167`）。
