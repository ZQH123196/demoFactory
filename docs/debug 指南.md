# debug 指南 — 让调试这一步变便宜的方法与陷阱

> 本文只记方法、机制与操作步骤；约束句在 AGENTS.md「契约索引」。
>
> **立意**：自动化的元目的是「让 agent 更好地调试」。没有基线，「提高」永远是感觉；
> 没有成文方法，同一个坑一个月后还会再踩一遍。

## 记法

每一条都写明**它让 agent 调试的哪一步变便宜**——省掉的是哪次考古、那几十次工具调用。
答不上来的当场销掉，不记。

条目的形状是「症状 → 病根 → 判据或现法 → 指针」。
只属于某一轮会话的读数不进本文；那类内容归 git 历史与各原型的 `design.md`。

## 调试能力基线实验（drill）

**为什么存在**：自动化的效果不测量就永远是感觉。drill = 给被测 agent 一个已知答案的 bug，
掐表测完整个调试过程。

**埋 bug 与冷启动**：独立分支 + 单独提交、事后 revert 干净，bug 选**不变量破坏类**；
被测 subagent 只拿 AGENTS.md 与两份手册，盲区名单不可读，不给 git log / diff / blame，
只诊断不改代码。

**交付契约**：自报五项——①根因（文件:行 + 机制）②修复建议 ③过程 ④卡点自报（**drill 的主产物**）⑤置信度。
计时双口径，只信外层现实时间；自报口径实测虚高约 8 倍。

**通道压力协议（Drill B）**：温柔序列 20 发 → 连发压测（50 发或连续 3 败即止）→ 重启恢复成本全程计时；
脚本末尾无条件恢复现场，中止路径同样如此（→ 「压测必恢复」）。

### 已测基线

| 项 | 读数 |
|---|---|
| Drill A：定位一个深号经济 bug | **~24 分钟 / 约 20 次工具调用**，全程离线，eval 失败 0 次 |
| Drill A 复测（有基线对照后） | 现实时间 **~2.6 分钟**（−89%）/ test 2 发 / 置信 88% |
| Drill B：20 发温柔序列失败次数 | **0**（单发约 160 ms） |
| Drill B：50 发长会话连发失败 | **第 24 发起连续 `NOT_READY`**（失败路径约 320 ms/发） |
| Drill B：重启恢复成本 | stop 0.2s + run 2.0s + 就绪轮询 1.2s ≈ **3.4s**，恢复后探针一发过 |

**两条基线结论**：

- 深号逻辑 bug **100% 可离线解决**，证据链（断言消息 → 代码 → 文档口径 → 数字复算）全程不碰 eval。
  三条卡点：①`StartSnapshot` 无首处差异 Hint，取证器的需求由此而来；②`dotnet test` 管道输出不可用，改 `--logger trx`；③缺一次性分析通道。
- eval 单发很快、温柔用法很好；死法在**长会话累积节流**（约 24 发临界），而且死得静默——上一发还好好的。

## 判绿线掉了怎么定位

**现象**：移动收归寻路层之后，判绿线从 **167/200 掉到 141/200**，Wilson 95% CI 不重叠。

### 五条管用的做法

1. **先立扰动对照臂，再谈「是不是噪声」。** 旧路 + 出生坐标扰 10 厘米 ⇒ 95.5% 的局结果变了而统计量纹丝不动。
2. **每条假设做成「能证伪的扰动臂」，不是「修复版」。**
3. **每臂带阳性对照**，否则臂上那些 `0/600` 分不清「真无效」与「夹具没编进去」。
4. **先立同口径再比较**；探针要与测试同口径，读数能被测试本身复现才算数。
5. **口径不合的那一轮读数当场作废重跑**，不并进结论。

### 一个照着做就查出来的战例

根因是**迁移本身漏了一格**：`BattleWorld.Step` 的 `switch (decision.Intent)` 漏了 `Hold`，
于是每步发一条「走回过时驻守点」的令。补上那一行后 600 局里 599 局与旧基线逐字相同。

**留下的结论**：迁到「命令由层持有」之后，**「不发令」不再等于「不动」**——
旧形状里的「没有动作」在新形状里要显式表达。

## 症状离病根的两段距离

### 一、夹具骗人：症状在玩法，病根在脚手架

**症状**：大考跑不出胜负，现场看起来是「怪不动」。

**病根**：`GrandExamTests` 的营建候选点表写在战场界外，而营建口不校边界 ⇒ 战士公会被建在界外
⇒ 19 名英雄生成在界外 ⇒ 怪永远照发同一个界外令。

**怎么定位到的**：先量「同屏有多少单位在报同一个读数」——`地形无路` **153 条**是主线索，
顺着「谁在报这条」「它追的目标在哪」两问往下走才落到夹具。

**读数**：`地形无路` 153 → 0，建会位置 (-50,-50) → (-5,-25)。修法全在宿主侧与夹具，寻路层一行未动。

### 二、两个读数合起来才看得出病：一个说「在动」，另一个说「没动」

**症状**：第一名游侠站着一动不动，`starve` 从 19 涨到 280，第 301 步被行会开除、阵亡。

**误导项**：无头跑一局日志里 `游荡` 逐步都在写，只读行为流会判「树是好的」；
两次读数合起来才看得出病——行为流说 `游荡`，同一时刻 `DebugSnapshot` 里 `intent` 是 `树:未决策`。

**病根**：`HeroBrainTask.Dispatch` 的 switch 漏了 `Wander` 那一支 ⇒ 意图从没写回
⇒ 世界因接管在册跳过自己的决策链 ⇒ 每步发「原地不动」。

**留下来的做法**：用一条读源码点名的用例要求每个 `BrainIntent` 都有一支 `case`；
`None` 写明成 no-op，未知分支 `throw`。

### 三、断言的前提会被时间轴悄悄改掉

测朝向时种子建筑已不在树里，因为村庄被地精拆光。断言要钉住的东西得先确认它还在。

## 通用陷阱清单

| 症状 | 病根与现法 | 指针 |
|---|---|---|
| 编译全过，`dotnet test` 一启动 `testhost` 就 `Win32Exception (5)`，**0 条测试真跑** | 工作区根带继承的 `Mandatory Label\Low`，Low 进程对 Medium 父进程只有只读权。改 `icacls <根> /setintegritylevel '(OI)(CI)M' /T /C`（括号那串在 PowerShell 下必须带引号）。判据是**位置不是代码**：同一 exe 在工作区是 Low、在 `%TEMP%` 是 Medium | 修完 11289 文件、0 失败、7.6 秒 |

| 根目录 `dotnet build` 与五条测试线全绿，但 `src/Tools` 那个 csproj 报「命名空间不存在 `Camera` / `Godot`」 | 根 build 编的是主 Godot 工程，它要这两个场景壳；测试工程排除了视图层自然红不了；`dotnet format` 只查格式不解析类型。**「五条线全绿」不等于「全仓能编」**，该排除的是凡是把 `GugaFramework/**/*.cs` 通配链进来的工程，本仓六处。两条 build 都 0 错误才算过 | `docs/验证操作手册.md` |
| 比对两条写路径（注入 vs 真鼠标）逐字不一致，两边其实都对 | 建局要发一条命令、暂停要发另一条，一次往返 1.3 秒 ≈ 十几步，**tick 根本没钉住**。现法：建局与暂停放进同一发 eval（`Main.StartNewRun(seed); Main.PauseToggle()`），推进那一发写成「起 → 推 n 步 → 再停」；逐格比对要**每步都存一份快照**。落空的一发读数与画面分开验——读数对、画面不对这类假绿只靠出图看得见 | 「桥只转发」 |
| `.godot` 脚本缓存过期：vendored `.gd` 全部 Parse error，而 `SCRIPT ERROR` 计数是 0 | 世界静默走纯 C# 退路。判据只看 `SCRIPT ERROR` 计数这条不够——缓存过期是另一种形状 | `docs/模型与动画准则.md` |
| VFX 四份效果「读得回属性却不生效」 | `color_ramp` 在 4.7 里类型是 `Texture2D`，直接塞 `Gradient` 被静默丢弃，要套 `GradientTexture1D`；`vertex_color_use_as_albedo` 默认 `false`，不写它粒子全白；加色混合下把 alpha 淡到 0 不会变暗，末端要同时把 RGB 淡到黑。技能试验场无光源，一律加色 + unshaded | `docs/adr/0011-vfx-effect-asset-is-a-scene-file.md` |
| 快进下粒子提前散尽，`finished` 仍按实时抛 | 槽位归还不跟倍率 ⇒ 快进时等效池容量被压紧约 20 倍。给槽位加一条**按倍率缩的持有时长上限**，超时自还；倍率 0 那格不缩。`Emitting` 不能当「还在演」量，`one_shot` 头一帧就射完 | `src/GugaFramework/Vfx/VfxPlayer.cs` |
| 改 clip 时长不生效 | `"length"` 只是声明，实际长度由末键时刻兜住，要连键帧一起改 | `docs/模型与动画准则.md` |
| 「通道没坏」却读不出真值 | 集合返回值走 `ToString()` 兜底 ⇒ 读回类型名。通道活着与读得出真值是两件事 | `InfinityLord/Tests/BridgeArgsTests.cs` |
| 回调「只加不减」，节点复用足够多次后才显形，那时读数已读不出来 | 借出时 `node.Finished += …`、归还时不 `-=` ⇒ 一个节点借 N 次，信号上积 N 个闭包。凡是这个形状都要成对接挂，并用「连演 N 次不积」的离线用例钉住 | `src/GugaFramework/Tests/VfxPlayerTranscript.cs` |
| 迁移测试框架后「编译能过、测试也能跑，但判据悄悄变了」 | `ShouldContain(sub, Case, msg)` 是子串、集合才用谓词形态，无脑统一会把「含有」改成「整串全等」；`Assert.Skip` 不能放构造函数（会记成失败） | 迁移当时的 712 通过 / 0 失败 / 3 跳过 |

## 两条跨层判据

**新原型落地时，公共层判据当场红两条**——逻辑层全绿、真机也通，跑框架层测试却红。两条都与原型逻辑无关，
是公共层守卫在拦：

- ①原型为了快进可用，在世界类里手写了一条推进循环并用 `new` 遮住基类那份。修法不在原型侧绕：
  把 `GameLogicBase.AdvanceTo` 从转发装配改成自持循环、以虚 `Advance` 为一步。
- ②灰盒 UI 直接把中文赋给 `.Text`。守卫只判「紧贴字面量且前面是 `.Text =`」那一种形状，`+` 拼接的读数行只报第一段。
  模板键必须写成 `{0}` 形态——**插值串 `LocKeys` 扫不出来**，上了 `Loc` 也不进表。

**「先验身份」那条原文的路径限制写窄了**，公共层试验场场景本来就在 `res://src/GugaFramework/` 下。
第二句已改成「当前场景属于本仓库」，`project_name == "DemoFactory"` 那一半不动（用户确认）。
